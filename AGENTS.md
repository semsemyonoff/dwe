# Repository Guidelines

## Project Structure & Module Organization

This is a Go CLI project named `devbox`. Devbox is a developer tool for local development environments running on Docker. Typical flow: a developer installs Devbox locally, enters a project with Devbox configuration, runs `devbox`, and the CLI detects the current directory as a Devbox project. From there it automates deploy/setup steps, orchestrates Docker services, and runs project commands.

`AGENTS.md` is the canonical file; `CLAUDE.md` is a symlink to it. Edit `AGENTS.md` — overwriting `CLAUDE.md` will break the symlink.

The executable entrypoint lives in `cmd/devbox`; most code is under `internal/`. Tests sit next to code as `*_test.go`; fixtures live in package-local `testdata/`. Package layout:

- `cmd/devbox/main.go` — entry point (uses `fang.Execute` for styled help/errors).
- `internal/version/` — `Version` / `Commit` / `Date` / `BuiltBy` vars + `Info()`; injected via `-ldflags -X`.
- `internal/config/` — `DevboxConfig` and all YAML loaders (`LoadConfig`, `LoadServicesConfig`, `LoadToolsConfig`, `LoadDeployConfig`, `LoadDockerConfig`, `LoadLifecycleConfig`, `LoadInfoConfig`, `LoadStylesConfig`); merged-config types (services, tools, runtime ports/hosts, render policy, parallel groups, actions, file gates, `DeployStep.SubStepOverrides` / `SubStepOverride`, `StatusColumn` for custom per-row columns); tools mirror services symmetrically — definitions in `devbox/tools.yml` (loaded standalone, strict-decoded), 3-layer overlay carries only `tools.<name>.enabled` (cross-layer `validateToolsOverlay` rejects stray definition fields with per-layer source attribution); `injectToolsIntoRaw` mirrors `injectServicesIntoRaw` so `tools.<name>.*` dot-paths keep resolving for exports / commands / docker templates. `ComposeFiles()` / `ComposeFilesAll()` return active vs all overlay sets (`--all` uses the latter). **Always** access binaries via `config.DevboxBin`/`DockerBin`/`ShellBin` (nil-safe), never `cfg.Binaries.*`. User-visible schema details: `docs/reference/config/`.
- `internal/docker/` — `Compose` for building/executing `docker compose` with policy args; `NewCompose` / `NewComposeAll`; always read the binary via `Compose.BinName()` (nil/empty-safe). Health helpers: `WaitContainersHealthy`, `HealthStatus`, `ContainerIDsFor`.
- `internal/render/` — `Writer` with ANSI output methods (Success / Error / Warning / Info / Definition / TableHeader / ASCII art); plain passthrough for logs; `Writer.Confirm` is the non-TTY Y/n fallback.
- `internal/ui/` — Lipgloss styled output: `RenderSummary`, `RenderInfo`, `RenderServiceTable(rows, extraCols)` / `RenderToolTable(rows, extraCols)` (dynamic per-row `Extras map[string]string` filled in by `stack.RenderCustomCells`; missing key → `—`), `RenderTopology`, `RenderDiagnosticsTable` (paired with `FormatDiagnostics`), `RenderDeployStatus`, `RenderGitWorkspace`, `ApplyStyles`. huh-backed primitives: `RunSelector`, `RunMultiSelect`, `RunConfirm`, `RunParamForm` / `BuildParamForm` (with UI-layer `ParamField` DTO so ui stays free of `usercommands` / `tpl` / `config` imports), `ConfirmRun` (caller pre-renders title; renders a sorted `key = value` summary above the prompt); `Theme()`, `IsInteractiveFn`. String-typed palette accessors `Color*()` (e.g. `ColorFocusBorder`, `ColorDescription`, `ColorTreeCount`, `ColorTreeArrow`, `ColorFilterMatch`, `ColorPaginationActive`, `ColorPaginationInactive`, `ColorKey`, `ColorSuccess`) are the only sanctioned bridge between v1 lipgloss here and v2 lipgloss in `cmdbrowser/`. **`SetHuhHooks` / `ClearHuhHooks`** — package-level hooks fired around every `ui.Run*` call so a `LiveLine` footer can pause/resume cleanly; any new prompt-like UI must go through `ui.Run*`, never bypass. **`RunWithPromptHooks(fn)`** — production helper that snapshots the hooks, runs `before`, defers `after`, and invokes `fn`; used by full-screen UI (cmdbrowser) that cannot go through `Run*`. `SnapshotHuhHooks` remains test-only.
- `internal/ui/cmdbrowser/` — two-panel interactive command browser (bubbletea v2) used by `devbox commands` when no exact ID is given (no-ID with `--inspect` is a hard error, not a browser launch). Palette is wired through `cmdbrowser/palette.go`, which constructs `charm.land/lipgloss/v2` styles from `ui.Color*()` strings and applies them to `list` / `viewport` / `help` (`applyListStyles` / `applyItemStyles` / `applyHelpStyles` / `applyViewportStyles`). Height math reserves one row for the help footer via `bodyHeight(h) = max(h-4, 3)` / `listHeight(h) = bodyHeight(h)-1` so the footer never clips. Public surface: `Run(title, items, opts) (Result, error)`, `Item` (carries precomputed `Inspect` string — package is decoupled from `usercommands.CommandDef`), `Options`, `DefaultOptions()`, `Result { Idx, Action, SkipConfirm }`, `Action` / `Mode` enums (each with `*Unknown` at iota 0). Builds its tree internally by splitting `Item.ID` on `.` — no dependency on `usercommands.GroupNode`. Fallback ladder: non-TTY → `ui.ErrCancelled` (defensive; call sites short-circuit first); `width<60` or `height<15` → delegate to `ui.RunSelector`; `width ∈ [60,79]` single-panel; `[80,99]` two-panel sans badges/counts; `≥100` full two-panel. Test seams `isTerminalFn` / `terminalSizeFn` / `runSelectorFn` are package-local function vars. Production code always wraps the bubbletea program in `ui.RunWithPromptHooks` so a surrounding `LiveLine` pauses cleanly.
- `internal/git/` — git update probe: `Probe`, `PullFFOnly`, `Decide` (safety matrix: dirty / no-upstream / fetch-failed → warn; behind + auto → pull; behind + prompt + TTY → prompt; behind + check → warn). `Runner` interface for tests.
- `internal/tpl/` — Go template engine: `Render`, `EvalCondition`, `EvalCommandCondition` (render-first). `FuncMap()` returns a per-call shallow clone of a sprout-backed map (`std`, `strings`, `numeric`, `slices`, `maps`, `regexp`, `conversion`, `time`, `filesystem`, `semver`) plus domain helper `appURL`. Hermetic (no env, FS, network, crypto). `commandFuncMap` adds `resolve` / `resolveMap` / `resolveFile` (command scope only).
- `internal/builtin/` — engine builtins usable as step bodies or `check:` actions: `service_dirs_ensure`, `service_configs_copy`, `service_configs_check`, `message`, `confirm`, `docker_remove_project_volumes`, `docker_wait_healthy`, `remove_paths`. `Builtin` interface threads `ctx` for cancellation.
- `internal/liveui/` — shared live-output infrastructure: `LiveLine` + `LiveBlock` (sticky footer + multi-row block via `bubbles/v2/spinner` + private ticker) and output helpers (`LineTee`, `ANSIOnlyStripper`, `LogSanitizer`, `JoinWriters`). Consumed by `internal/pipeline/plain.go` and by workflow parallel groups in `internal/usercommands/runtime/runner_workflow.go`. **Nine non-negotiable invariants** for the live view are documented in `liveline.go` — read them before touching anything here.
- `internal/pipeline/` — pipeline executor and `PlainReporter`: `Reporter` interface (concurrent-safe; implementations must tolerate sub-step events from N goroutines); `SuspendForExec` / `ResumeAfterExec` wrap every sequential step body so the child writes directly to the host terminal. Action dispatch: `ExecAction` (pure dispatch — no `when:`, no reporter, no check). `RunWithOptions` owns `when:` eval, reporter calls, `check:` orchestration, and `continue_on_error`. Plan-time helpers: `ResolvePhaseSteps`, `PrintPlanTable`, `FormatCondition` / `FormatAction` / `FormatFilesGate`. Plan-time sentinels: `ErrNestedParallel`, `ErrUnnamedSubStep`, `ErrInteractiveInParallel`, `ErrEmptyParallelSteps`, `ErrDuplicateStepName`, `ErrSubStepOverridesInvalid`. State: `Recorder` / `FileRecorder` (mutex-protected). Log files: `OpenPipelineLog` / `OpenSubStepLog`. **Executor step ordering**: `phase-when → step-when → files_gate probe → (journal-skip only when FilesGate == nil) → execute` (gated steps always re-probe). User-facing parallel / `files_gate:` semantics: `docs/reference/config/deploy.md`. `Run` and `ExecStep` are deprecated thin wrappers.
- `internal/deploy/` — deploy plan resolution: `ResolvePlan`, `ResolveServicePlan`, `FindStep`, `TrackedServices`, `LoadTrackedServices` (canonical tracked-service set from the resolved plan; nil registry tolerated — gate validation skipped). Subpackage `journal/` owns the state-file types and I/O (`ProjectState`, `ServiceState`, `PhaseState`, `StepState`, `Status`, `Load` / `Save` / `Remove` / `RemoveService`, hashing: `ActionHash` / `StepHash` / `ServiceConfigHash` / `ProjectConfigHash`, `Decide` for skip logic, `Recompute` for aggregates). State file: `.devbox/deploy/state.yml` (gitignored). User-facing journal semantics: `docs/reference/config/state.md`.
- `internal/lifecycle/` — lifecycle pipeline execution: `RunPhases`, `RunRun` (git update + phases + show-info), `RunRestart` (stop + run), `RunStop`; `RunContext.ShowInfo` is injected to avoid importing cobra renderers. Deploy gate is unconditional — no bypass flag (compose errors immediately on undeployed services).
- `internal/lock/` — project-level file lock with stale-PID detection (Unix-only build tag): `Acquire(path)` uses `flock(LOCK_EX|LOCK_NB)`; on `EWOULDBLOCK` reads the holder PID and calls `Kill(pid, 0)` to reclaim stale locks. Lock file: `.devbox/deploy/deploy.lock`. Behavior detail: `docs/reference/config/state.md` § Lock file.
- `internal/reset/` — reset plan resolution (`ResolvePlan`, `FindStep`); mirrors deploy.
- `internal/stack/` — Docker Compose topology + health, plus status section collectors / renderers: `AggregateHealth`, `FetchComposeTopology`, `ParseTopologyFromFiles`; `RenderHealth` / `RenderServices` / `RenderTools` / `RenderDeployStatus` / `RenderTopology` are pure string-returning section renderers composed by the `status` group; `RenderServices` / `RenderTools` return `(string, []error)` so the command layer aggregates one stderr warning per section; `BuildCustomColumns(cfg, kind)` + `RenderCustomCells(defs, data)` power the per-service / per-tool `status:` block (hermetic `tpl.Render` only — never `RenderCommand`); `CollectGitWorkspace(ctx, cfg)` runs `git status -b --porcelain=v2` per service under `errgroup.WithContext` + `SetLimit(8)` with `exec.CommandContext` for cancellation, pre-checks `<dir>/.git` to avoid walking to a parent repo, and reports per-row errors on `GitWorkspaceRow.Err` (goroutines always return nil so siblings aren't cancelled on first error).
- `internal/envfile/` — `.env` generation: `BuildContent(cfg)`, `Regenerate(configPath)`. No cobra / UI deps.
- `internal/localconfig/` — local YAML toggle helpers: `LoadLocalYAML`, `WriteLocalYAML`, `SetLocalEntryEnabled`, `ValidateServiceToggle`.
- `internal/pathsafe/` — filesystem safety: `CheckNoSymlinks`, `ContainedRel` (rejects `..` / `.` escaping), `EnsureRealUnder` (callers must `filepath.EvalSymlinks` before passing). Used by template renderers to prevent escape attacks.
- `internal/usercommands/` — declarative command system facade (re-exports subpackages):
  - `model/` — pure types: `CommandDef`, `CommandFile`, `ParamDef`, `ContextDef`, `FileSpec`, `WorkflowStep` (with optional `Name` for pipeline-side `sub_step_overrides` targeting; `StepName()` returns `Name` when set else `Command`) + `WorkflowParallel`, enums. `CommandType` payload field is `Cmd` (legacy `Run` / `type: command` are strict-decode errors).
  - `loader/` — YAML discovery and parsing: `DiscoverCommandFiles`, `LoadCommandFile` (parse + validate; runtime callers), `ParseCommandFile` (parse only; validators only — never use at runtime, it skips semantic validation), `ComputeGroup`, `ComputeCommandID`.
  - `registry/` — `Registry`, `LoadRegistry`, `GroupNode`, cross-ref validation; diagnostic API (`BuildRegistryFromParsed`, `ValidationIssue`, `Diagnostics`); `WalkWorkflowSteps` recursive walker (path: `step[i]` at root, `step[i].parallel.steps[j]` inside groups).
  - `resolve/` — `Params`, `ParamDefaults` (raw-string prefill for the parameter form: merges `provided ∪ DefaultFrom ∪ Default`; empty-as-missing parity with `Params`; no coercion, no required-check, no pattern check — those stay in `Params` at run time), `Context`, `BuildEnv`.
  - `runtime/` — runners and execution: `RunContext`, `Runner` (ctx passed explicitly, never stored), `NewRunner`, `RunCommand`, `ConfirmCommand`, host / devbox / service-exec / service-run / script / workflow runners. Script env contract: `DEVBOX_BIN`, `DEVBOX_FILES_JSON`, `DEVBOX_NONINTERACTIVE`. **Shell env contract** (`hostContractEnv` in `runner_host.go`): `DEVBOX_BIN` + `COMPOSE_PROJECT_NAME` + `COMPOSE_FILE` (colon-joined, absolutised against `ProjectRoot`) — appended after `env:` so contract wins on duplicate keys. **Service-runner template fields**: `resolveServiceFields` renders `service`, `workdir`, `workdir_from` (and their `runner:` overrides) through `tpl.RenderCommand` before resolution — same contract as `argv`/`cmd`/`compose_args`. This unblocks `service: app-${param.service}` + `workdir_from: services.${param.service}.work_dir_internal` generic commands. `BuildRunContext` + `ComputeFilePathsProbe` are reused by the executor's files_gate evaluation. **`RunContext.UnderParallel`** is set on every sub-step of a parallel group (pipeline or workflow); guards reject nested parallel (`ErrWorkflowNestedParallel`) and transitive interactive confirmations (`ErrConfirmInsideParallel`). **`RunContext.WorkflowSubStepOverrides`** carries pipeline-side per-sub-step `files_gate` directives forwarded from `DeployStep.SubStepOverrides` via `ActionContext.SubStepOverrides`; the workflow runner applies the gate before each matching sub-step in both sequential and parallel paths via `evalSubStepOverrideGate`. Overrides are intentionally not propagated to inner workflows. The workflow's per-block `liveui.NewLiveLine` does NOT call `ui.SetHuhHooks` — interactive prompts are forbidden inside parallel, and overwriting hooks set by a surrounding `PlainReporter` would corrupt its pause/resume dance. Parallel block rendering: the per-sub-step `lineTee` callback refreshes the live row on **every** frame (final and non-final) so `\r`-progress bars are visible, but only commits newline-terminated frames to the per-sub-step buffer and log; the post-Wait emit suppresses per-sub-step status lines in TTY mode (already shown in the frozen block rows) and prints a single `writeParallelSummary` footer (`✓ [<elapsed>] parallel: <workflow-id>`), while non-TTY mode keeps the per-sub-step status lines plus a plain-text footer. Failure-output dumps print in BOTH modes.
- `internal/templates/` — template pack helpers shared between render commands and validators (`manifest/`, `packroot/`, `ide/`, `ai/`, `git/`). Manifest schema, `<pack>.local/` overrides, and collision policies (IDE / git: deepest extends wins; AI: shallowest) are documented in `docs/reference/render/index.md`. Each kind exposes `SelectServices`, `ResolveTemplatePack` (implicit-missing returns `found=false, err=nil`; explicit-missing or invalid-name errors), `LoadManifest`, `ValidateManifest`, `ExtendsRoot`. Manifest is **mandatory** — packs without `manifest.yml` return `ErrManifestMissing`. **`TemplateData.Service` vs `Resolved`**: `Service` is the canonical config identity (extends-chain root, used to key raw-config lookups); `Resolved` is the rendering identity (collision winner); `ServiceCfg` is the merged block of `Resolved` (so e.g. `.ServiceCfg.Container` reflects the extender's overlay).
- `internal/validate/` — static project validation framework: `Validator` interface, `Diagnostic` (severity / domain / target / file / line / message / hint), `Context` (carries `CommandRegistry any` — nil-tolerant: validators self-skip gate checks), `Registry` (scope-dispatch), `Summary`, `ExitCode` (severity-gated). Subpackages: `config/` (per-file YAML validators + `deploy_files_gate` aggregator + `parallel_groups` walker matching the pipeline sentinels via `errors.Is`), `templates/` (per-kind manifest + override validators; explicit `enabled: false` opt-out is silent — only policy and actionable skips emit info), `commands/` (uses `loader.ParseCommandFile` for categorised diagnostics).
- `internal/condition/` — deploy step `when:` evaluator. Two APIs coexist: legacy string-based (`Classify`, `IsRuntime(string)`, `EvalRuntime`, `Kind*` constants) for workflow string `when:`, and typed (`Condition` struct, `EvalRuntimeTyped`) for pipeline `when:`. Template conditions evaluate at plan time in `pipeline/resolve`, not here. Uses hardcoded `sh -c` (POSIX-portable, intentionally not `ShellBin`). **Known wart**: `type: builtin` in `when:` resolves the *predicate* registry here; `type: builtin` in a step body or `check:` resolves the *engine builtin* registry in `internal/builtin` — same keyword, two registries, disambiguated by YAML position. User-facing semantics: `docs/reference/config/conditions.md`.
- `internal/filesgate/` — deploy step file-existence gate (parser-types): `FilesGate`, `State` (`readable` / `missing`), `RequireSpec`, `StepRef` (minimal step-shaped value so validators avoid importing `config.DeployStep`). Subpackage `spec/` does plan-time validation (`Validate`, `ResolveRequireIDs` against command `files:` block). Root package stays import-light. User-facing semantics: `docs/reference/config/deploy.md` § `files_gate:`.
- `internal/command/` — cobra commands with Fang integration and command groups (root summary, lifecycle, `status` group, mutating-only `services` / `tools`, deploy / reset, docker / compose, docs, validate); thin adapters delegating to domain packages. **`status` group** (`status.go`): default `RunE` renders health + services + tools + deploy + topology + git in order; each section also addressable via subcommand (`status services` / `status tools` / `status deploy [svc]` / `status topology` / `status git`); default-only `--no-services` / `--no-tools` / `--no-deploy` / `--no-topology` / `--no-git` flags suppress sections; a typed `Section` enum + ordered list is the single source of truth for both the default orchestrator order and the `--no-*` flag set. The group does **not** use `PersistentPreRunE` (would replace the root project-resolution hook) — instead, `loadStatusContext(flags)` is called once from each subcommand's `RunE` and loads cfg/journal/tracked/topology on demand. `status deploy <svc>` uses `cobra.MaximumNArgs(1)` and `ValidArgsFunction` routed through `completionConfigPath`. All stdout via `cmd.OutOrStdout()`; warnings via `cmd.ErrOrStderr()`. **Mutating-only `services` / `tools`**: bare `devbox services` / `devbox tools` open the multi-select toggle (TTY only) with mandatory items pre-checked/disabled; non-TTY → `ErrInteractiveRequired` sentinel (hint points at `devbox status services` / `devbox status tools`); all-mandatory short-circuit before opening the form; `enable <mandatory>` warns and exits 0; `disable <mandatory>` errors and exits non-zero; completion via `completeDisabledOptional` / `completeEnabledOptional` / `completeToolDisabled` / `completeToolEnabled` filters. `devbox commands [id]` (alias `cmd`) is the single command surface: no positional id → cmdbrowser selector; exact id → direct run; `-i/--inspect <id>` prints the resolved definition (mutually exclusive with `--set` / `--yes`); `--set k=v` (repeatable, `StringArrayVar`) prefills the param form. Orchestrator `runCommandByID(ctx, stdin/stdout/stderr, cfg, reg, projectRoot, id, runOpts)` owns the run pipeline: `reg.Get` → private guard → `resolve.ParamDefaults` (raw-string prefill, distinct from `resolve.Params` which still runs at `BuildRunContext`) → `ui.RunParamForm` → `BuildRunContext` → attach I/O channels → render confirmation title against `rctx.Render` → `ui.ConfirmRun` with `stringifyParams(rctx.Params)` summary → set `rctx.SkipConfirm` to prevent re-prompt → `usercommands.RunCommand`. Test seams: package-level vars `runParamForm` / `confirmRun` / `runUserCommand` / `notifyContext` (`signal.NotifyContext`) — subtests overriding any of these MUST NOT call `t.Parallel()`. The TUI `y` toggle is folded into `runOpts.Yes` at the call site as `yesFlag || skipFromTUI`. **Validate schema-bypass pattern**: `isValidateCommand(cmd)` in `PersistentPreRunE` switches from `project.Resolve` (schema-validating) to `project.Locate` (locate only) so schema errors surface as diagnostics rather than aborting before `RunE`. Apply this pattern to any future diagnostic-mode command. **Exit-code interface**: errors implementing `ExitCode() int` are translated to custom process exit codes in `cmd/devbox/main.go` via `errors.As`; the fang error handler suppresses the "Error:" line for them. `validationFailedError` in `validate.go` is the canonical example. `docs generate --scope cli` works without a project; `--scope all` / `--scope commands` requires a project.
- `internal/command/statusview/` — view-model types owned by the command layer and passed to `internal/ui` renderers (ui must never load YAML or compute hashes): `DeployStatusView`, `DeployStatusRow`, `DeploySummary`, `ConfigDelta` enum (`ok` / `changed` / `missing`), `GitWorkspaceRow`.
- `internal/project/` — project discovery: `Locate(flag)` (upward walk from cwd; explicit mode when flag non-empty), `ValidateSchema(path)` (schema_version must be `"2"`), `Resolve(flag)` (Locate + ValidateSchema); `ErrNotFound` sentinel; constants `ConfigFilename`, `SchemaField`, `SupportedSchema`.

## Configuration Documentation

Keep behavior and docs aligned. Devbox configuration documentation lives in `docs/reference/`:

- `docs/reference/config/` — project config files (`devbox.md`, `services.md`, `tools.md`, `docker.md`, `info.md`, `styles.md`), pipelines (`deploy.md`, `lifecycle.md`, `conditions.md`, `state.md`), and user commands (`commands.md`).

Update these when changing schemas, commands, service toggles, deploys, or hooks.

## Build, Test, and Development Commands

- `make build` runs `go mod tidy`, builds `./cmd/devbox`, and writes `bin/devbox`.
- `make test` runs the full test suite with `go test ./...`.
- `make test-v` runs tests with verbose output.
- `make lint` installs `golangci-lint` if missing, then runs checks.
- `make tidy` updates `go.mod` and `go.sum`.
- `make clean` removes the built binary from `bin/`.

Use `go test ./internal/command` or `go test ./internal/usercommands/... -run TestName` for focused work.

## Coding Style & Naming Conventions

Follow `.editorconfig`: Go files use tabs with width 4; YAML, JSON, and shell files use two spaces. Run `gofmt` and `goimports`; `golangci-lint` enforces `errcheck`, `govet`, `staticcheck`, `revive`, `gocritic`, and `modernize`.

## Testing Guidelines

Prefer table-driven tests for command parsing, config resolution, Docker orchestration, and runner behavior. Keep fixtures in `testdata/` and avoid developer-specific Docker state unless the package isolates it. Every behavior change should update nearby `*_test.go` coverage. Run `make test` before opening a PR.

## Commit & Pull Request Guidelines

Recent history uses conventional-style commits such as `feat(commands): ...`, `fix(commands): ...`, `docs(config): ...`, and `refactor(commands)!: ...`. Keep the scope tied to the package or user-facing area, and use `!` only for breaking changes. Pull requests should include a summary, verification commands, linked issues when applicable, and screenshots or terminal output when changing CLI presentation.

## Key Patterns

- **Completion helpers**: Cobra's hidden `__complete` path bypasses `PersistentPreRunE`, so `ValidArgsFunction` callbacks cannot rely on the project being resolved. All such callbacks must call `completionConfigPath(flags, cmd)` (in `internal/command/completion.go`) before any config-dependent work. On any error (`ErrNotFound`, schema, bad `-c` path) return empty completions and `cobra.ShellCompDirectiveNoFileComp` silently.
- **Binary accessors**: Never read `cfg.Binaries.*` fields directly. Always use nil-safe accessors: `config.DevboxBin(cfg)`, `config.DockerBin(cfg)`, `config.ShellBin(cfg)`. Deploy/condition step `when:` predicates intentionally use hardcoded `sh` (not `ShellBin`) for portability.
- **YAML loader strictness**: Deploy / reset / lifecycle loaders (`LoadDeployConfig`, `LoadResetConfig`, `LoadLifecycleConfig`), the command-file parser (`model.ParseCommandFile`), and template manifest loaders (via shared `manifest.Load()`) use `yaml.Decoder.KnownFields(true)` — unknown fields are hard errors. Other loaders (info, styles, docker, localconfig, topology) use lenient `yaml.Unmarshal`. When adding loaders, match the surface: strict for user-edited pipeline / command / manifest YAML; lenient for internal or non-step config. For command files, `loader.LoadCommandFile` (parse + validate) is the runtime entry point; `loader.ParseCommandFile` is for validators that want categorised diagnostics — never use it at runtime.
- **Validation framework**: `internal/validate` defines `Validator`, `Diagnostic`, and `Registry` for static project validation. Validators run independently per-file to surface all issues regardless of main-config load success. Registry dispatches by scope (domain + optional ID); diagnostics are sorted deterministically and rendered via `RenderDiagnosticsTable`. Exit code is severity-gated: errors → 1, warnings with `--strict` → 1, otherwise 0. Per-domain validators live in `internal/validate/{config,templates,commands}` and register via `All()` functions (no `init()` side effects).
- **Live view & state pointers**: The pipeline live view (`internal/liveui` + `internal/pipeline/plain.go`) uses `bubbles/v2` models directly via `Model.View()` — never `tea.NewProgram`, `term.MakeRaw`, or terminal capability queries. Nine non-negotiable invariants enforced by `LiveLine` / `LiveBlock` are documented in `internal/liveui/liveline.go`; read them before touching the live view. Deploy lock and state-journal invariants (atomic write-temp + rename, stale-PID reclaim, config-hash invalidation before skip decisions) are documented in `docs/reference/config/state.md`.
- **Grouped commands: no child `PersistentPreRunE`**. Cobra does NOT chain `PersistentPreRunE` — a child's hook *replaces* the parent's entirely, silently dropping the root's project resolution and schema validation. For grouped subtrees (e.g. `status services` / `status tools` / `status deploy`) that need shared setup beyond what root provides, use a per-`RunE` loader helper instead. The `status` group uses `loadStatusContext(flags)` (`internal/command/status.go`) as the canonical example: called once from each subcommand's `RunE` to load cfg/journal/tracked/topology on demand. Same constraint applies to any new command group added on top of the root.
- **Section renderer signature contract**: `internal/stack/` section renderers return strings (and per-row errors where applicable) rather than writing to `*render.Writer`. The `internal/command` layer is the single writer of stdout/stderr (`cmd.OutOrStdout()` / `cmd.ErrOrStderr()`), so `internal/ui/` stays format-agnostic and `internal/stack/` stays output-agnostic. When adding a new status section: collector in `stack/` returns data, `ui.Render*` returns a string, command layer composes and writes. Do not pass `io.Writer` into `stack` or `ui` render functions.

## Agent-Specific Instructions

Do not overwrite unrelated local changes. Keep command examples current with the `Makefile`. When changing CLI behavior, update tests and config docs.

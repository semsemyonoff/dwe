# Repository Guidelines

## Project Structure & Module Organization

This is a Go CLI project named `devbox`. Devbox is a developer tool for local development environments running on Docker. Typical flow: a developer installs Devbox locally, enters a project with Devbox configuration, runs `devbox`, and the CLI detects the current directory as a Devbox project. From there it automates deploy/setup steps, orchestrates Docker services, and runs project commands.

`AGENTS.md` is the canonical file; `CLAUDE.md` is a symlink to it. Edit `AGENTS.md` — overwriting `CLAUDE.md` will break the symlink.

The executable entrypoint lives in `cmd/devbox`; most code is under `internal/`. Tests sit next to code as `*_test.go`; fixtures live in package-local `testdata/`. Package layout:

- `cmd/devbox/main.go` — entry point (uses `fang.Execute` for styled help/errors)
- `internal/version/` — `Version`, `Commit`, `Date`, `BuiltBy` vars; `Info()` formatter; injected via `-ldflags -X` at build time
- `internal/config/` — `DevboxConfig` struct, layered `LoadConfig()`, `LoadDeployConfig()`, `LoadDockerConfig()`, `LoadLifecycleConfig()`, `ResolvePath()`, `ExportRule`, `ComposeConfig`, `DockerConfig`, `DeployConfig`, `LifecycleConfig`, `InfoConfig`, `LoadInfoConfig()`, `StylesConfig`, `LoadStylesConfig()`; `InfoSection` carries `HideOnEmpty bool` (`yaml:"hide_on_empty"`, default `false`); `InfoItem` now carries `Title string`, `Items []InfoItem` (subgroup children), `HideOnEmpty *bool` (subgroup default `true`), and `Decorative *bool` (all types; accessors `IsDecorative() bool` resolves nil to type default, `SubgroupHideOnEmpty() bool` returns `*HideOnEmpty` or `true` when nil) for every item. Valid item types: `info|warning|definition|separator|subgroup` (`subheader` removed — unknown types rejected at load time). Loader validates types and rejects empty-`items` subgroups; `BinariesConfig` (devbox/docker/shell binary overrides, read from top-level `devbox.yml` only — not layered); nil-safe accessors `DevboxBin`, `DockerBin`, `ShellBin` (always go through these, never `cfg.Binaries.*` directly); `Action` (typed step-body and `check:` struct: `Type` one of `shell|devbox|command|builtin`, `Cmd`, `With`; custom `UnmarshalYAML` rejects scalar shorthand); **strict YAML decode**: `LoadDeployConfig`, `LoadResetConfig`, `LoadLifecycleConfig` use `yaml.Decoder.KnownFields(true)` — unknown fields in deploy/reset/lifecycle YAML are hard errors; other loaders (info, styles, docker, localconfig, topology) remain lenient; `ToolsConfig` is `map[string]ToolConfig`, `RuntimePorts` and `RuntimeHosts` are `map[string]int` / `map[string]string` with identifier-safe keys (`^[A-Za-z_][A-Za-z0-9_]*$`), tool host/port live in the tool entry itself (not in Runtime), `ComposeConfig` has only `Base` field (tool overlays moved to `tools.<name>.compose`); `LoadConfig` rejects identifier-unsafe keys in `Tools`, `Runtime.Ports`, `Runtime.Hosts`, rejects legacy `compose.overlays` blocks with a migration error, and rejects any declared tool entry (enabled or disabled) missing `container`, `host`, or non-positive `port`; `(*DevboxConfig).ComposeFiles()` returns active compose file list (base + enabled tool overlays + enabled service overlays, sorted); `(*DevboxConfig).ComposeFilesAll()` returns all compose files regardless of enabled state — used by `--all` commands; `DockerArgs` has `Pull []string` and `Build []string` fields (yaml: `pull`, `build`) in addition to the other per-subcommand keys; `ServiceRenderConfig` (nested block; contains `IDE`, `AI`, `Git` fields; yaml: `render` on `ServiceConfig`), with `ServiceIDEConfig` (`Enabled *bool` tristate pointer, `Template string`; yaml: `ide`), `ServiceAIConfig` (`Enabled *bool`, `Template string`; yaml: `ai`), and `ServiceGitHooksConfig` (`Enabled *bool`, `Template string`; yaml: `git`); accessors `IDERenderEnabled()` / `GitRenderEnabled()` (return true when `Enabled` nil **and service type is `app`**, false otherwise) and `AIRenderEnabled() bool` (returns true when `Enabled` nil), `IDERenderEnabledExplicit()`, `AIRenderEnabledExplicit()`, and `GitRenderEnabledExplicit() (bool, bool)` (return enabled + whether explicitly set); render fields inherited via `extends` (same topological pass in `resolveExtendsInheritance`); `render.ide.*`, `render.ai.*`, and `render.git.*` fields are NOT injected into `raw["services"]` and cannot be used in dot-path expressions
- `internal/docker/` — `Compose` struct for building and executing `docker compose` commands with policy args; `Compose.Bin` is private-by-convention — always use `Compose.BinName()` (nil/empty-safe), never read the field directly; `NewCompose(cfg, dockerCfg)` populates `Bin` via `config.DockerBin(cfg)`; `NewComposeAll(cfg, dockerCfg)` uses `ComposeFilesAll()` instead of `ComposeFiles()` — use when `--all` is in effect; `WaitContainersHealthy(ids, get, attempts, interval, w)` polls container health with retry logic, `HealthStatus(bin, id)` returns container status, `Compose.HealthStatus(id)` wrapper method, `Compose.ContainerIDsFor(services)` filters containers by service names
- `internal/render/` — `Writer` with ANSI output methods (Success, Error, Warning, Info, Definition, TableHeader, ASCII art); plain passthrough for logs/deploy output; `Writer.Confirm` is the documented non-TTY fallback for Y/n prompts (piped stdin, CI)
- `internal/ui/` — Lipgloss styled output: `RenderSummary(cfg, summary *statusview.DeploySummary)` for compact root summary (nil summary omits the deploy-state line), `RenderInfo(cfg, infoCfg)` for full info dashboard; delegates to `renderBlock` for recursive section/subgroup rendering — a section/subgroup with `hide_on_empty: true` is skipped when no surviving item is non-decorative; decorative items (`separator` by default; any type with `decorative: true`) do not count toward visibility; footer suppressed when no section produced output, `RenderServiceTable()` and `RenderToolTable()` for Lipgloss tables, `RenderTopology()` for dependency tree; `RenderDiagnosticsTable(rows)` renders the `devbox validate` output table (STATUS / DOMAIN / TARGET / FILE / MESSAGE / HINT columns with severity-colored glyphs) — use `FormatDiagnostics(diags, quiet)` to convert `[]validate.Diagnostic` to renderable rows; `RenderDeployStatus(rows []statusview.DeployStatusRow)` renders the per-service deploy status table (SERVICE / STATUS / CONFIG / PREV HASH / CURR HASH / LAST FAILED); `ApplyStyles(stylesCfg)` to hot-apply palette from `styles.yml` (also rebuilds the huh theme); terminal width detection; huh-backed interactive primitives: `RunSelector(title, items)` (single-pick), `RunMultiSelect(title, items)` (multi-toggle), `RunConfirm(title, affirmative, negative)` (confirmation); `Theme()` accessor for the project-palette `huh.Theme`; `IsInteractiveFn(stdin)` TTY-detection helper used by all interactive callers
- `internal/git/` — git update probe: `Probe(workDir, fetch)` returns `Status` (IsRepo, Dirty, Behind, Ahead, FetchOK, FetchErr); `PullFFOnly(workDir)` returns `moved bool`; `Decide(status, mode, isInteractive)` encodes the safety matrix (dirty/no-upstream/fetch-failed → warn; behind + auto → pull; behind + prompt + TTY → prompt-pull; behind + check → warn). Runner interface for unit-test stubbing.
- `internal/tpl/` — Go template engine with `Render()`, `EvalCondition()`, `EvalCommandCondition()` (render-first condition evaluator for workflow `when` expressions, resolves `${...}` before classifying/dispatching); `FuncMap()` returns a per-call shallow clone of a cached sprout-backed map: domain helper `appURL` + sprout registries `std`, `strings`, `numeric`, `slices`, `maps`, `regexp`, `conversion`, `time`, `filesystem`, `semver`; hermetic (no env, no FS reads, no network, no crypto/random); `commandFuncMap` extends the clone with `resolve`/`resolveMap`/`resolveFile` (command-scope only); template funcs available in `${...}` expressions in command definitions
- `internal/builtin/` — builtin step registry: `Builtin` interface (`Validate`, `Describe`, `Run`), `ExecContext` carrier; registered builtins: `service_dirs_ensure` (creates service hub dirs with skip/error/recreate modes), `service_configs_copy` (template config file deployment), `service_configs_check` (verify config files exist), `message` (outputs text at info/success/warning/error level with Go template support), `confirm` (Y/n prompt), `docker_remove_project_volumes` (cleanup), `docker_wait_healthy` (wait for container health), `remove_paths` (delete project files)
- `internal/pipeline/` — deploy/reset reporter abstraction: `Reporter` interface (StartPipeline, EnterPhase, SkipPhase, StartStep, SkipStep, FinishStep, FailStep, FinishPipeline, SuspendForExec, ResumeAfterExec); `PlainReporter` — the sole reporter; outputs icons (✓ ✗ ◎ ·), suppresses untracked phase output, prints elapsed time in `FinishPipeline`; **action dispatch**: `ActionContext` carries `WorkDir`, `Cfg`, `Reg`, `LogWriter`, `SkipConfirm`; `ExecAction(a config.Action, actx ActionContext) error` dispatches `shell`/`devbox`/`command`/`builtin` — pure dispatch, no reporter, no `when:`, no check orchestration; `RunWithOptions(RunOptions)` generic executor owns `when:` evaluation, reporter calls, `check:` orchestration, and `continue_on_error`; `Run(steps, reporter, ...)` is a deprecated wrapper — use `RunWithOptions`; `ResolvePhaseSteps(cfg, reg, ...)` (tolerates `reg == nil` — gate validation skipped; runtime callers must pass non-nil), `ResolvedStep`, `PrintPlanTable`, `FormatCondition`, `FormatAction`, `FormatFilesGate`; `OpenPipelineLog(workDir, name, enabled)` — opens `.devbox/logs/<name>.log`, returns tee writer that strips ANSI before writing to file; `ExecStep` is a deprecated thin wrapper — new code should call `ExecAction` directly; **state tracking**: `Recorder` interface (`OnPipelineStart`, `OnStepStart`, `OnStepFinish`, `OnStepFail`, `OnStepSkip`, `OnPipelineFinish`) with `NopRecorder` no-op; `FileRecorder` writes per-step results to `state.yml` routing project-scope steps to `state.Project.Phases` and service-scope steps to `state.Services[name].Phases`; `SkipDecider func(addr string, rs ResolvedStep, stepHash string) journal.Decision` — caller-supplied closure for state-based step skipping; `RunOptions` carries `Registry *usercommands.Registry` (required at runtime for `files_gate` probe); **executor step ordering**: `phase-when → step-when → files_gate probe → (journal-skip only when FilesGate == nil) → execute`; gated steps bypass the journal skip-decider and always re-probe; both passed via `RunOptions`
- `internal/deploy/` — deploy plan resolution: `ResolvePlan(cfg, reg)`, `ResolveServicePlan(cfg, reg, ...)`, `FindStep`; assembles `DeployConfig` phases into executable steps (`reg` nil-tolerated — gate validation skipped when nil); includes `internal/deploy/journal/` subpackage for state tracking:
  - `journal/` — deploy state file types and I/O: `ProjectState`, `ServiceState`, `PhaseState`, `StepState`, `Status`, `LastRun` types; `Load()` and `Save()` for atomic read/write; `Remove()` and `RemoveService()` for cleanup; `ActionHash()`, `ServiceConfigHash()`, `ProjectConfigHash()` for hashing; `Decide()` for skip-decision logic; `Recompute()` for status aggregation. New helper (Task 7): `StepHash(step)` computes display/audit hash including both action and files_gate (nil gate → identical to `ActionHash`); recorded in journal for config-delta detection in `devbox deploy state show` and per-service status tables, but not used for skip decisions (gated steps bypass journal-skip via executor). State file: `.devbox/deploy/state.yml` (gitignored).
  - `deploy.TrackedServices(cfg, reg)` and `deploy.LoadTrackedServices(configPath, reg)` helpers (in parent `deploy/` package, not `journal/`) to derive the canonical tracked-service set from the resolved deploy plan
- `internal/lifecycle/` — lifecycle pipeline execution: `RunPhases(cfg, lifecycleCfg, ...)` executes a set of deploy phases via `pipeline.Run`; `RunRun(ctx RunContext)` — full run lifecycle (git update, run phases, show-info); `RunRestart(ctx RunContext)` — stop then run; `RunStop(ctx StopContext)` — stop pipeline; `RunContext` carries `ConfigPath`, `NoUpdate`, `UpdateMode`, `Yes`, `ShowInfo func() error` (injected to avoid importing cobra renderers); the deploy gate is unconditional — there is no bypass flag because running against an undeployed service immediately errors out in compose
- `internal/lock/` — project-level file-locking with stale-PID detection (Unix-only): `Acquire(path)` acquires `LOCK_EX|LOCK_NB` via `syscall.Flock`; on `EWOULDBLOCK`, reads PID from lockfile and calls `syscall.Kill(pid, 0)` to detect stale locks (build tag `//go:build !windows`). Lock file: `.devbox/deploy/deploy.lock`.
- `internal/reset/` — reset plan resolution: `ResolvePlan`, `FindStep`; mirrors deploy for the reset pipeline
- `internal/stack/` — Docker Compose topology + health: `AggregateHealth`, `FetchComposeTopology`, `ParseTopologyFromFiles`; augments compose state with devbox service config
- `internal/envfile/` — `.env` file generation: `BuildContent(cfg)`, `Regenerate(configPath)`; no cobra or UI dependencies
- `internal/localconfig/` — local YAML toggle helpers: `LoadLocalYAML`, `WriteLocalYAML`, `SetLocalEntryEnabled`, `ValidateServiceToggle`; no envfile dependency
- `internal/pathsafe/` — filesystem safety helpers: `CheckNoSymlinks(absRoot, absDir, label)` validates no symlink components in a path; `ContainedRel(absRoot, absChild)` returns cleaned relative path and rejects escaping (`..`, `.`); `EnsureRealUnder(realDir, roots...)` enforces symlink-resolved directory boundaries (all callers must resolve paths via `filepath.EvalSymlinks` before passing). Used by IDE and agents template renderers to prevent escape attacks.
- `internal/usercommands/` — declarative command system facade (re-exports all public symbols from subpackages):
  - `usercommands/model/` — pure types: `CommandDef`, `CommandFile`, `ParamDef`, `ContextDef`, `FileSpec`, `WorkflowStep`, all enums (`CommandType`, `ParamType`, `ExecMode`, `UserMode`, `FileAccess`, `FileSort`, `FileOnError`); `CommandType` constants: `shell` (host shell, replaces legacy `command`), `devbox`, `service_exec`, `service_run`, `script`, `workflow`; `CommandDef.Cmd` is the payload field (replaces legacy `Run`); legacy `type: command` or `run:` in command files produce strict-decode errors
  - `usercommands/loader/` — YAML discovery and parsing: `DiscoverCommandFiles`, `LoadCommandFile`, `ComputeGroup`, `ComputeCommandID`
  - `usercommands/registry/` — command registry: `Registry`, `LoadRegistry`, `GroupNode` tree, cross-ref validation; diagnostic-friendly API: `BuildRegistryFromParsed`, `ValidationIssue`, `Diagnostics()`
  - `usercommands/resolve/` — param/context/env resolution: `Params`, `Context`, `BuildEnv`
  - `usercommands/runtime/` — runners and execution: `RunContext`, `Runner` interface, `NewRunner`, `RunCommand`, `ConfirmCommand`, `HostRunner`, `DevboxRunner`, `ServiceExecRunner`, `ServiceRunRunner`, `ScriptRunner`, `WorkflowRunner`, file path computation. Script contract env: `DEVBOX_BIN`, `DEVBOX_FILES_JSON`, `DEVBOX_NONINTERACTIVE`. New helpers (Task 3–4): `BuildRunContext(cfg, reg, def, with, workDir)` extracts param/context/docker resolution from caller-side setup for reuse in both command execution and files_gate probing; `ComputeFilePathsProbe(ctx, only)` probes a filtered set of command files for existence (no side effects; treats missing files as `Resolved: false` for both read and read_write access) — used by executor's files_gate evaluation. Both re-exported in facade `internal/usercommands/` for caller convenience.
- `internal/templates/` — template pack selection and validation helpers (shared between render commands and validators):
  - `templates/manifest/` — shared manifest schema for all renderers: `File` (the primary type, NOT `Manifest` — avoid stutter at call sites), `RenderEntry{From, To}`, `SymlinkEntry{Link, To}`; `Load(path)` strict-decode (`KnownFields(true)`); `ErrManifestMissing` sentinel (multi-`%w` wrap so both `errors.Is(err, manifest.ErrManifestMissing)` and `errors.Is(err, os.ErrNotExist)` hold on missing-file); `ValidateShape(m, destRoot, label)` pure schema check (no FS access); `ValidateSources(m, resolve, label)` resolver-aware source-existence check; `ValidateSourcesWith(m, resolve, sink, label)` adds an aggregation hook collecting `fromOverride=true` rels for validator info diagnostics; `ValidatePackName(name)` enforces `^[A-Za-z0-9][A-Za-z0-9_-]*$` (used by all three `ResolveTemplatePack` implementations to reject explicit `*.template` and silently skip identifier-unsafe implicit service-name candidates)
  - `templates/packroot/` — universal per-file local override resolver: `Resolve(projectRoot, kind, packName, rel) (path string, fromOverride bool, err error)` checks `<projectRoot>/devbox/templates/<kind>/<packName>.local/<rel>` (sibling shadow pack, gitignored by `*.local/` pattern — parallel to `devbox/local.yml` / `devbox/docker.local.yml`) first, then canonical `<packName>/<rel>`. Both candidates run through `pathsafe.CheckNoSymlinks` + `pathsafe.ContainedRel`. Hard-errors (no silent fallback) when either candidate exists but is not a regular file (directory, symlink, device).
  - `templates/ide/` — IDE template pack helpers: `SelectServices` (filter by enabled/render policy, resolve collisions by deepest extends), `SkippedService`, `ResolveTemplatePack` (returns `(packDir, packName string, found bool, err error)` — implicit missing returns `found=false, err=nil`), `LoadManifest`, `ValidateManifest(m, projectRoot, packName, destRoot)`, `ValidateTemplateKey`, `ExtendsDepth`. **Manifest is now mandatory** — packs without `manifest.yml` produce `ErrManifestMissing` with a migration hint (hard-cut migration from the legacy directory-walk). `TemplateData` carries `Cfg *config.DevboxConfig` for templates to reach merged config via `.Cfg.Raw`.
  - `templates/ai/` — AI template pack helpers: `SelectServices` (filter by enabled/render policy, resolve collisions by shallowest extends), `SkippedService`, `ResolveTemplatePack` (returns `(packDir, packName string, found bool, err error)` — implicit missing returns `found=false, err=nil`), `LoadManifest`, `Manifest` (type alias for `manifest.File`), `ValidateManifest(m, projectRoot, packName, destRoot)`, `RenderTemplateFile`, `EnsureRelativeSymlink`. All per-file reads go through `packroot.Resolve` so `<pack>.local/` overrides apply. `TemplateData` carries `Cfg *config.DevboxConfig` for templates to reach merged config via `.Cfg.Raw`.
  - `templates/git/` — git hooks template pack helpers: `SkippedService`, `ResolveTemplatePack(svc, projectRoot, name) (packDir, packName string, found bool, err error)` (implicit missing returns `found=false, err=nil`; explicit-pack-first ordering: resolve explicit pack before `.git` check so typos surface regardless of `.git` state, then implicit-on-match or skip), `SelectServices`, `PrepareHub(absRoot, name, svc) (absHub, err)` (preflight `pathsafe.ContainedRel` + `CheckNoSymlinks` on `svc.Dir` before any `MkdirAll`), `ResolveGitHooksDir(absHub) (absHooks, DirStatus, err)` (`DirOK | DirMissing | DirWorktree` — `.git` as a file is treated as a worktree/submodule pointer and the service is skipped with a warning; full worktree support deferred), `LoadManifest`, `ValidateManifest(m, projectRoot, packName, destRoot)` (shape + git-specific basename-only `to` + empty `symlinks` + resolver-aware sources), `RenderHooks(Context)` writes hooks with `os.WriteFile` + explicit `os.Chmod(0o755)` (handles re-render permission normalization), Lstat-rejects destination symlinks, runs `pathsafe.EnsureRealUnder(realHooksDir, realRoot, realGitDir)` containment after `MkdirAll`, uses a per-entry helper to avoid defer-in-loop. `TemplateData` carries `Cfg *config.DevboxConfig` for templates to reach merged config via `.Cfg.Raw`.
- `internal/validate/` — static project validation framework: `Validator` interface, `Diagnostic` type (severity, domain, target, file, line, message, hint), `Context` (project state; carries `CommandRegistry any` — `*usercommands.Registry` or nil; nil-tolerant: validators self-skip gate checks when nil), `Registry` (dispatch by scope), `Summary` (aggregate counts), `ExitCode` (severity-gated exit); subpackages:
  - `validate/config/` — validators for `devbox.yml`, `services.yml`, `docker.yml`, `info.yml`, `styles.yml`, `lifecycle.yml`, `deploy.yml`, `reset.yml`, `service-deploy` configs with per-file loaders and cross-ref validation; `deploy_files_gate` validator aggregates `files_gate:` misconfiguration diagnostics across deploy, lifecycle, and reset pipelines (self-skips with info diagnostic when registry is unavailable)
  - `validate/templates/` — validators for IDE, AI, and git template packs using `internal/templates/{ide,ai,git}` helpers. Each validator calls the kind-level `ValidateManifest` (never bypassing into `manifest.ValidateShape`/`ValidateSources` directly so per-kind extras like git basename-only `to` still run). Validators install a sink into `ValidateSourcesWith` to aggregate `fromOverride=true` rels and emit ONE info-severity diagnostic per kind+pack listing up to 5 overridden basenames (`...`-truncated). The git validator does NOT gate on `ResolveGitHooksDir` — it always validates the pack and emits an optional advisory info diagnostic when `src/.git` is missing or is a worktree pointer. **Explicit opt-out is silent**: skip reasons `service-disabled` and `<kind>-disabled` (i.e. `render.<kind>.enabled: false` set explicitly) produce no diagnostic — only the policy-default skip (`<kind>-policy`, non-`app` type without explicit opt-in) and actionable skips (`empty-dir`, `lost-collision`) emit info diagnostics. The "template pack not found" warning's `Hint` is multi-line (`\n`-split — Lipgloss table cells honor newlines) and suggests both creating `devbox/templates/<kind>/<name>` (or `default`) and setting `services.<name>.render.<kind>.enabled: false` in `services.yml` as the alternative.
  - `validate/commands/` — validator for command file syntax and cross-reference validation
- `internal/condition/` — deploy step `when:` expression evaluator. Two APIs coexist: (1) **legacy string-based** (`Classify`, `IsRuntime(string)`, `EvalRuntime`, `Kind*` constants) — used only by workflow string `when:` expressions; (2) **typed** `Condition` struct (`Type`: `builtin|shell|template`; `Cmd` or `Expr`), `EvalRuntimeTyped(*Condition, projectRoot)`. Template conditions are evaluated at plan time by callers (`pipeline/resolve`), not inside `condition`. Intentionally uses hardcoded `sh -c` for shell conditions — POSIX-portable regardless of `config.ShellBin`. **Known wart**: `type: builtin` in a `when:` condition resolves the *predicate* registry here; `type: builtin` in a step body or `check:` resolves the *engine builtin* registry in `internal/builtin` — same keyword, two registries, disambiguated by YAML position.
- `internal/filesgate/` — deploy step file-existence gate: parser-types package with `FilesGate` struct (short/long form YAML), `State` enum (`readable` / `missing`), `RequireSpec` (expand-able `required` / `all` / explicit list). Includes subpackage `internal/filesgate/spec/` for plan-time validation (`Validate`) and require-spec expansion (`ResolveRequireIDs` against command `files:` block); imports `config`, `registry`, `model`. Root `filesgate/` package (what `config.DeployStep` imports) stays import-light. No cycle with `internal/config` because validator lives in subpackage. Paired with `internal/pipeline/executor` for runtime probe evaluation and with `internal/deploy/journal` for `StepHash` computation (display/audit hash including gate).
- `internal/command/` — cobra commands with Fang integration and command groups (root summary, lifecycle, services/tools, deploy/reset, docker/compose, docs, validate); thin adapters delegating to domain packages. `docs generate --scope cli` works without a project (outputs to cwd); `--scope all`/`--scope commands` requires a project. `devbox validate` command tree (config, templates, commands) with severity-gated exit codes and `--strict`/`--quiet` flags; validates project YAML and reports diagnostics in a table. `devbox deploy` and `devbox reset` manage orchestrator pipelines; `devbox deploy state {show,clear,repair}` subcommands manage the idempotency state journal (raw YAML dump, atomic delete, recompute aggregates). `devbox docker pull/build` are image-management subcommands using resolver helpers. `devbox render ide`, `devbox render ai`, and `devbox render git` delegate to `internal/templates/{ide,ai,git}` packages. Note: `devbox wait`, `devbox up`, `devbox down`, `devbox logs`, `devbox ps`, `devbox docker wait`, and `devbox reset config check` commands were removed — use `devbox docker {up,down,logs,ps}`, `devbox run`, `docker_wait_healthy` builtin, and `devbox validate config reset` respectively. **Validate schema-bypass pattern**: `isValidateCommand(cmd)` in `PersistentPreRunE` switches from `project.Resolve` (schema-validating) to `project.Locate` (locate only) so that schema errors surface as diagnostics rather than aborting before `RunE`. Apply this pattern to any future "diagnostic-mode" command that should run even against malformed projects. **Exit-code interface**: errors implementing `ExitCode() int` are translated to custom process exit codes in `cmd/devbox/main.go` via `errors.As`; the fang error handler suppresses the "Error: ..." line for such errors. `validationFailedError` in `internal/command/validate.go` is the canonical example — use this pattern for any command that needs a non-1 exit code.
- `internal/command/statusview/` — view-model types owned by the command layer and passed to `internal/ui` renderers (ui must never load YAML or compute hashes): `DeployStatusView` (per-service rows slice), `DeployStatusRow` (`Service`, `Status`, `ConfigDelta`, `PrevHashShort`, `CurrHashShort`, `LastFailedPhase`, `LastFailedStep`), `DeploySummary` (`Deployed int`, `Total int`, `ProjectStatus`), `ConfigDelta` enum (`ok|changed|missing`)
- `internal/project/` — project discovery: `Locate(flag)` (upward walk from cwd; explicit mode when flag non-empty), `ValidateSchema(path)` (schema_version must be "2"), `Resolve(flag)` (compose Locate + ValidateSchema); `ErrNotFound` sentinel; constants `ConfigFilename`, `SchemaField`, `SupportedSchema`

## Configuration Documentation

Keep behavior and docs aligned. Devbox configuration documentation lives in `docs/reference/config`. It describes project config files, Docker/service orchestration, deploy flows, lifecycle hooks, and user commands. Update it when changing schemas, commands, service toggles, deploys, or hooks.

## Build, Test, and Development Commands

- `make build` runs `go mod tidy`, builds `./cmd/devbox`, and writes `bin/devbox`.
- `make test` runs the full test suite with `go test ./...`.
- `make test-v` runs tests with verbose output.
- `make lint` installs `golangci-lint` if missing, then runs checks.
- `make tidy` updates `go.mod` and `go.sum`.
- `make clean` removes the built binary from `bin/`.

Use `go test ./internal/command` or `go test ./internal/usercommands/... -run TestName` for focused work.

## Coding Style & Naming Conventions

Follow `.editorconfig`: Go files use tabs with width 4; YAML, JSON, and shell files use two spaces. Run `gofmt` and `goimports`; `golangci-lint` enforces `errcheck`, `govet`, `staticcheck`, `revive`, `gocritic`, and `modernize`.

## Testing Guidelines

Prefer table-driven tests for command parsing, config resolution, Docker orchestration, and runner behavior. Keep fixtures in `testdata/` and avoid developer-specific Docker state unless the package isolates it. Every behavior change should update nearby `*_test.go` coverage. Run `make test` before opening a PR.

## Commit & Pull Request Guidelines

Recent history uses conventional-style commits such as `feat(commands): ...`, `fix(commands): ...`, `docs(config): ...`, and `refactor(commands)!: ...`. Keep the scope tied to the package or user-facing area, and use `!` only for breaking changes. Pull requests should include a summary, verification commands, linked issues when applicable, and screenshots or terminal output when changing CLI presentation.

## Key Patterns

- **Completion helpers**: Cobra's hidden `__complete` path bypasses `PersistentPreRunE`, so `ValidArgsFunction` callbacks cannot rely on the project being resolved. All such callbacks must call `completionConfigPath(flags, cmd)` (defined in `internal/command/completion.go`) before any config-dependent work. On any error (`ErrNotFound`, schema, bad `-c` path) return empty completions and `cobra.ShellCompDirectiveNoFileComp` silently.
- **Binary accessors**: Never read `cfg.Binaries.*` fields directly. Always use nil-safe accessors: `config.DevboxBin(cfg)`, `config.DockerBin(cfg)`, `config.ShellBin(cfg)`. Deploy/condition step `when:` predicates intentionally use hardcoded `sh` (not `ShellBin`) for portability.
- **YAML loader strictness**: Deploy/reset/lifecycle loaders (`LoadDeployConfig`, `LoadResetConfig`, `LoadLifecycleConfig`) and the command-file parser (`model.ParseCommandFile`) use `yaml.Decoder.KnownFields(true)` — unknown fields produce hard errors. Template manifest loaders (`LoadManifest` in `internal/templates/{ai,ide,git}/`) also use strict decode via the shared `manifest.Load()` in `internal/templates/manifest/`. All other loaders (info, styles, docker, localconfig, topology) use lenient `yaml.Unmarshal`. When adding new loaders, match the strictness of the surface: strict for user-edited pipeline/command/manifest YAML; lenient for internal or non-step config.
- **Validation framework**: `internal/validate` package defines `Validator` interface, `Diagnostic` type, and `Registry` for static project validation. Validators run independently per-file to surface all issues regardless of main config load success. Registry dispatches by scope (domain + optional ID). Diagnostics are sorted deterministically and rendered via `RenderDiagnosticsTable`. Exit code is severity-gated: errors → 1, warnings with `--strict` → 1, otherwise → 0. Per-domain validators live in `internal/validate/{config,templates,commands}`; validators are registered via `All()` functions to avoid `init()` side effects.
- **Lock and state invariants**: The file lock at `.devbox/deploy/deploy.lock` prevents concurrent deploys via `syscall.Flock(LOCK_EX|LOCK_NB)`. On lock-held, the holder PID is read from the lockfile and tested with `syscall.Kill(pid, 0)` — if `ESRCH` (no such process), the lock is stale and is transparently reclaimed after truncate. The state journal at `.devbox/deploy/state.yml` uses atomic write-temp + `os.Rename` to survive crashes. Hashes are computed from parsed Go structs (not raw YAML bytes) so formatting changes do not invalidate the journal. Config-hash invalidation happens before skip decisions: a service's changed `config_hash` treats all its prior steps as absent, preventing false skips when config drifts.

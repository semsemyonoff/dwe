# Repository Guidelines

## Project Structure & Module Organization

This is a Go CLI project named `devbox`. Devbox is a developer tool for local development environments running on Docker. Typical flow: a developer installs Devbox locally, enters a project with Devbox configuration, runs `devbox`, and the CLI detects the current directory as a Devbox project. From there it automates deploy/setup steps, orchestrates Docker services, and runs project commands.

`AGENTS.md` is the canonical file; `CLAUDE.md` is a symlink to it. Edit `AGENTS.md` — overwriting `CLAUDE.md` will break the symlink.

The executable entrypoint lives in `cmd/devbox`; most code is under `internal/`. Tests sit next to code as `*_test.go`; fixtures live in package-local `testdata/`. Package layout:

- `cmd/devbox/main.go` — entry point (uses `fang.Execute` for styled help/errors)
- `internal/version/` — `Version`, `Commit`, `Date`, `BuiltBy` vars; `Info()` formatter; injected via `-ldflags -X` at build time
- `internal/config/` — `DevboxConfig` struct, layered `LoadConfig()`, `LoadDeployConfig()`, `LoadDockerConfig()`, `LoadLifecycleConfig()`, `ResolvePath()`, `ExportRule`, `ComposeConfig`, `DockerConfig`, `DeployConfig`, `LifecycleConfig`, `InfoConfig`, `LoadInfoConfig()`, `StylesConfig`, `LoadStylesConfig()`; `InfoSection` carries `HideOnEmpty bool` (`yaml:"hide_on_empty"`, default `false`); `InfoItem` now carries `Title string`, `Items []InfoItem` (subgroup children), `HideOnEmpty *bool` (subgroup default `true`), and `Decorative *bool` (all types; accessors `IsDecorative() bool` resolves nil to type default, `SubgroupHideOnEmpty() bool` returns `*HideOnEmpty` or `true` when nil) for every item. Valid item types: `info|warning|definition|separator|subgroup` (`subheader` removed — unknown types rejected at load time). Loader validates types and rejects empty-`items` subgroups; `BinariesConfig` (devbox/docker/shell binary overrides, read from top-level `devbox.yml` only — not layered); nil-safe accessors `DevboxBin`, `DockerBin`, `ShellBin` (always go through these, never `cfg.Binaries.*` directly); `Action` (typed step-body and `check:` struct: `Type` one of `shell|devbox|command|builtin`, `Cmd`, `With`; custom `UnmarshalYAML` rejects scalar shorthand); **strict YAML decode**: `LoadDeployConfig`, `LoadResetConfig`, `LoadLifecycleConfig` use `yaml.Decoder.KnownFields(true)` — unknown fields in deploy/reset/lifecycle YAML are hard errors; other loaders (info, styles, docker, localconfig, topology) remain lenient; `ToolsConfig` is `map[string]ToolConfig`, `RuntimePorts` and `RuntimeHosts` are `map[string]int` / `map[string]string` with identifier-safe keys (`^[A-Za-z_][A-Za-z0-9_]*$`), tool host/port live in the tool entry itself (not in Runtime), `ComposeConfig` has only `Base` field (tool overlays moved to `tools.<name>.compose`); `LoadConfig` rejects identifier-unsafe keys in `Tools`, `Runtime.Ports`, `Runtime.Hosts`, rejects legacy `compose.overlays` blocks with a migration error, and rejects any declared tool entry (enabled or disabled) missing `container`, `host`, or non-positive `port`; `(*DevboxConfig).ComposeFiles()` returns active compose file list (base + enabled tool overlays + enabled service overlays, sorted); `(*DevboxConfig).ComposeFilesAll()` returns all compose files regardless of enabled state — used by `--all` commands; `DockerArgs` has `Pull []string` and `Build []string` fields (yaml: `pull`, `build`) in addition to the other per-subcommand keys; `ServiceIDEConfig` (`Enabled *bool` tristate pointer, `Template string`; yaml: `ide` on `ServiceConfig`) and `ServiceAIConfig` (`Enabled *bool`, `Template string`; yaml: `ai` on `ServiceConfig`); accessors `IDERenderEnabled()` (returns true when `Enabled` nil **and service type is `app`**, false otherwise) and `AIRenderEnabled() bool` (returns true when `Enabled` nil), `IDERenderEnabledExplicit()` and `AIRenderEnabledExplicit() (bool, bool)` (return enabled + whether explicitly set); `ai` inherited via `extends` like `ide`; `ide.*` and `ai.*` fields are NOT injected into `raw["services"]` and cannot be used in dot-path expressions
- `internal/docker/` — `Compose` struct for building and executing `docker compose` commands with policy args; `Compose.Bin` is private-by-convention — always use `Compose.BinName()` (nil/empty-safe), never read the field directly; `NewCompose(cfg, dockerCfg)` populates `Bin` via `config.DockerBin(cfg)`; `NewComposeAll(cfg, dockerCfg)` uses `ComposeFilesAll()` instead of `ComposeFiles()` — use when `--all` is in effect; `WaitContainersHealthy(ids, get, attempts, interval, w)` polls container health with retry logic, `HealthStatus(bin, id)` returns container status, `Compose.HealthStatus(id)` wrapper method, `Compose.ContainerIDsFor(services)` filters containers by service names
- `internal/render/` — `Writer` with ANSI output methods (Success, Error, Warning, Info, Definition, TableHeader, ASCII art); plain passthrough for logs/deploy output; `Writer.Confirm` is the documented non-TTY fallback for Y/n prompts (piped stdin, CI)
- `internal/ui/` — Lipgloss styled output: `RenderSummary(cfg)` for compact root summary, `RenderInfo(cfg, infoCfg)` for full info dashboard; delegates to `renderBlock` for recursive section/subgroup rendering — a section/subgroup with `hide_on_empty: true` is skipped when no surviving item is non-decorative; decorative items (`separator` by default; any type with `decorative: true`) do not count toward visibility; footer suppressed when no section produced output, `RenderServiceTable()` and `RenderToolTable()` for Lipgloss tables, `RenderTopology()` for dependency tree; `ApplyStyles(stylesCfg)` to hot-apply palette from `styles.yml` (also rebuilds the huh theme); terminal width detection; huh-backed interactive primitives: `RunSelector(title, items)` (single-pick), `RunMultiSelect(title, items)` (multi-toggle), `RunConfirm(title, affirmative, negative)` (confirmation); `Theme()` accessor for the project-palette `huh.Theme`; `IsInteractiveFn(stdin)` TTY-detection helper used by all interactive callers
- `internal/git/` — git update probe: `Probe(workDir, fetch)` returns `Status` (IsRepo, Dirty, Behind, Ahead, FetchOK, FetchErr); `PullFFOnly(workDir)` returns `moved bool`; `Decide(status, mode, isInteractive)` encodes the safety matrix (dirty/no-upstream/fetch-failed → warn; behind + auto → pull; behind + prompt + TTY → prompt-pull; behind + check → warn). Runner interface for unit-test stubbing.
- `internal/tpl/` — Go template engine with `Render()`, `EvalCondition()`, `EvalCommandCondition()` (render-first condition evaluator for workflow `when` expressions, resolves `${...}` before classifying/dispatching); `FuncMap()` returns a per-call shallow clone of a cached sprout-backed map: domain helper `appURL` + sprout registries `std`, `strings`, `numeric`, `slices`, `maps`, `regexp`, `conversion`, `time`, `filesystem`, `semver`; hermetic (no env, no FS reads, no network, no crypto/random); `commandFuncMap` extends the clone with `resolve`/`resolveMap`/`resolveFile` (command-scope only); template funcs available in `${...}` expressions in command definitions
- `internal/builtin/` — builtin step registry: `Builtin` interface (`Validate`, `Describe`, `Run`), `ExecContext` carrier; registered builtins: `service_dirs_ensure` (creates service hub dirs with skip/error/recreate modes), `service_configs_copy` (template config file deployment), `service_configs_check` (verify config files exist), `message` (outputs text at info/success/warning/error level with Go template support), `confirm` (Y/n prompt), `docker_remove_project_volumes` (cleanup), `docker_wait_healthy` (wait for container health), `remove_paths` (delete project files)
- `internal/pipeline/` — deploy/reset reporter abstraction: `Reporter` interface (StartPipeline, EnterPhase, SkipPhase, StartStep, SkipStep, FinishStep, FailStep, FinishPipeline, SuspendForExec, ResumeAfterExec); `PlainReporter` — the sole reporter; outputs icons (✓ ✗ ◎ ·), suppresses untracked phase output, prints elapsed time in `FinishPipeline`; **action dispatch**: `ActionContext` carries `WorkDir`, `Cfg`, `Reg`, `LogWriter`, `SkipConfirm`; `ExecAction(a config.Action, actx ActionContext) error` dispatches `shell`/`devbox`/`command`/`builtin` — pure dispatch, no reporter, no `when:`, no check orchestration; `Run(steps, reporter, ...)` generic executor owns `when:` evaluation, reporter calls, `check:` orchestration, and `continue_on_error`; `ResolvePhaseSteps`, `ResolvedStep`, `PrintPlanTable`, `FormatCondition`, `FormatAction`; `OpenPipelineLog(workDir, name, enabled)` — opens `logs/<name>.log`, returns tee writer that strips ANSI before writing to file; `ExecStep` is a deprecated thin wrapper — new code should call `ExecAction` directly
- `internal/deploy/` — deploy plan resolution: `ResolvePlan`, `ResolveServicePlan`, `FindStep`; assembles `DeployConfig` phases into executable steps
- `internal/reset/` — reset plan resolution: `ResolvePlan`, `FindStep`; mirrors deploy for the reset pipeline
- `internal/lifecycle/` — lifecycle pipeline execution: `RunPhases(cfg, lifecycleCfg, ...)` executes a set of deploy phases via `pipeline.Run`; `RunRun(ctx RunContext)` — full run lifecycle (git update, run phases, show-info); `RunRestart(ctx RunContext)` — stop then run; `RunStop(ctx StopContext)` — stop pipeline; `RunContext` carries `ConfigPath`, `NoUpdate`, `UpdateMode`, `Yes`, `ShowInfo func() error` (injected to avoid importing cobra renderers)
- `internal/stack/` — Docker Compose topology + health: `AggregateHealth`, `FetchComposeTopology`, `ParseTopologyFromFiles`; augments compose state with devbox service config
- `internal/envfile/` — `.env` file generation: `BuildContent(cfg)`, `Regenerate(configPath)`; no cobra or UI dependencies
- `internal/localconfig/` — local YAML toggle helpers: `LoadLocalYAML`, `WriteLocalYAML`, `SetLocalEntryEnabled`, `ValidateServiceToggle`; no envfile dependency
- `internal/pathsafe/` — filesystem safety helpers: `CheckNoSymlinks(absRoot, absDir, label)` validates no symlink components in a path; `ContainedRel(absRoot, absChild)` returns cleaned relative path and rejects escaping (`..`, `.`); `EnsureRealUnder(realDir, roots...)` enforces symlink-resolved directory boundaries (all callers must resolve paths via `filepath.EvalSymlinks` before passing). Used by IDE and agents template renderers to prevent escape attacks.
- `internal/usercommands/` — declarative command system facade (re-exports all public symbols from subpackages):
  - `usercommands/model/` — pure types: `CommandDef`, `CommandFile`, `ParamDef`, `ContextDef`, `FileSpec`, `WorkflowStep`, all enums (`CommandType`, `ParamType`, `ExecMode`, `UserMode`, `FileAccess`, `FileSort`, `FileOnError`); `CommandType` constants: `shell` (host shell, replaces legacy `command`), `devbox`, `service_exec`, `service_run`, `script`, `workflow`; `CommandDef.Cmd` is the payload field (replaces legacy `Run`); legacy `type: command` or `run:` in command files produce strict-decode errors
  - `usercommands/loader/` — YAML discovery and parsing: `DiscoverCommandFiles`, `LoadCommandFile`, `ComputeGroup`, `ComputeCommandID`
  - `usercommands/registry/` — command registry: `Registry`, `LoadRegistry`, `GroupNode` tree, cross-ref validation; diagnostic-friendly API: `BuildRegistryFromParsed`, `ValidationIssue`, `Diagnostics()`
  - `usercommands/resolve/` — param/context/env resolution: `Params`, `Context`, `BuildEnv`
  - `usercommands/runtime/` — runners and execution: `RunContext`, `Runner` interface, `NewRunner`, `RunCommand`, `ConfirmCommand`, `HostRunner`, `DevboxRunner`, `ServiceExecRunner`, `ServiceRunRunner`, `ScriptRunner`, `WorkflowRunner`, file path computation. Script contract env: `DEVBOX_BIN`, `DEVBOX_FILES_JSON`, `DEVBOX_NONINTERACTIVE`
- `internal/templates/` — template pack selection and validation helpers (shared between render commands and validators):
  - `templates/ide/` — IDE template pack helpers: `SelectServices` (filter by enabled/render policy, resolve collisions by deepest extends), `SkippedService`, `ResolveTemplatePack`, `WalkPack`, `PackEntry`, `ValidateTemplateKey`, `ExtendsDepth`
  - `templates/ai/` — AI template pack helpers: `SelectServices` (filter by enabled/render policy, resolve collisions by shallowest extends), `SkippedService`, `ResolveTemplatePack`, `LoadManifest`, `Manifest`, `ValidateManifest`, `RenderTemplateFile`, `EnsureRelativeSymlink`
- `internal/validate/` — static project validation framework: `Validator` interface, `Diagnostic` type (severity, domain, target, file, line, message, hint), `Context` (project state), `Registry` (dispatch by scope), `Summary` (aggregate counts), `ExitCode` (severity-gated exit); subpackages:
  - `validate/config/` — validators for `devbox.yml`, `services.yml`, `docker.yml`, `info.yml`, `styles.yml`, `lifecycle.yml`, `deploy.yml`, `reset.yml`, `service-deploy` configs with per-file loaders and cross-ref validation
  - `validate/templates/` — validators for IDE and AI template packs using `internal/templates/{ide,ai}` helpers
  - `validate/commands/` — validator for command file syntax and cross-reference validation
- `internal/condition/` — deploy step `when:` expression evaluator. Two APIs coexist: (1) **legacy string-based** (`Classify`, `IsRuntime(string)`, `EvalRuntime`, `Kind*` constants) — used only by workflow string `when:` expressions; (2) **typed** `Condition` struct (`Type`: `builtin|shell|template`; `Cmd` or `Expr`), `EvalRuntimeTyped(*Condition, projectRoot)`. Template conditions are evaluated at plan time by callers (`pipeline/resolve`), not inside `condition`. Intentionally uses hardcoded `sh -c` for shell conditions — POSIX-portable regardless of `config.ShellBin`. **Known wart**: `type: builtin` in a `when:` condition resolves the *predicate* registry here; `type: builtin` in a step body or `check:` resolves the *engine builtin* registry in `internal/builtin` — same keyword, two registries, disambiguated by YAML position.
- `internal/command/` — cobra commands with Fang integration and command groups (root summary, lifecycle, services/tools, deploy/reset, docker/compose, docs, validate); thin adapters delegating to domain packages. `docs generate --scope cli` works without a project (outputs to cwd); `--scope all`/`--scope commands` requires a project. `devbox validate` command tree (config, templates, commands) with severity-gated exit codes and `--strict`/`--quiet` flags; validates project YAML and reports diagnostics in a table. `devbox deploy` and `devbox reset` manage orchestrator pipelines; `devbox docker pull/build` are image-management subcommands using resolver helpers. `devbox render ide` and `devbox render ai` delegate to `internal/templates/{ide,ai}` packages. Note: `devbox wait`, `devbox up`, `devbox down`, `devbox logs`, `devbox ps`, `devbox docker wait`, and `devbox reset config check` commands were removed — use `devbox docker {up,down,logs,ps}`, `devbox run`, `docker_wait_healthy` builtin, and `devbox validate config reset` respectively.
- `internal/project/` — project discovery: `Locate(flag)` (upward walk from cwd; explicit mode when flag non-empty), `ValidateSchema(path)` (schema_version must be "2"), `Resolve(flag)` (compose Locate + ValidateSchema); `ErrNotFound` sentinel; constants `ConfigFilename`, `SchemaField`, `SupportedSchema`

## Configuration Documentation

Keep behavior and docs aligned. Devbox configuration documentation lives in `docs/reference/config`. It describes project config files, Docker/service orchestration, deploy flows, lifecycle hooks, and user commands. Update it when changing schemas, commands, service toggles, deploys, or hooks.

## Build, Test, and Development Commands

- `make build` runs `go mod tidy`, builds `./cmd/devbox`, and writes `bin/devbox`.
- `make test` runs the full test suite with `go test ./...`.
- `make test-v` runs tests with verbose output.
- `make lint` installs `golangci-lint` if missing, then runs checks.
- `make tidy` updates `go.mod` and `go.sum`.
- `make clean` removes the built binary from `bin/`.

Use `go test ./internal/command` or `go test ./internal/usercommands/... -run TestName` for focused work.

## Coding Style & Naming Conventions

Follow `.editorconfig`: Go files use tabs with width 4; YAML, JSON, and shell files use two spaces. Run `gofmt` and `goimports`; `golangci-lint` enforces `errcheck`, `govet`, `staticcheck`, `revive`, `gocritic`, and `modernize`.

## Testing Guidelines

Prefer table-driven tests for command parsing, config resolution, Docker orchestration, and runner behavior. Keep fixtures in `testdata/` and avoid developer-specific Docker state unless the package isolates it. Every behavior change should update nearby `*_test.go` coverage. Run `make test` before opening a PR.

## Commit & Pull Request Guidelines

Recent history uses conventional-style commits such as `feat(commands): ...`, `fix(commands): ...`, `docs(config): ...`, and `refactor(commands)!: ...`. Keep the scope tied to the package or user-facing area, and use `!` only for breaking changes. Pull requests should include a summary, verification commands, linked issues when applicable, and screenshots or terminal output when changing CLI presentation.

## Key Patterns

- **Completion helpers**: Cobra's hidden `__complete` path bypasses `PersistentPreRunE`, so `ValidArgsFunction` callbacks cannot rely on the project being resolved. All such callbacks must call `completionConfigPath(flags, cmd)` (defined in `internal/command/completion.go`) before any config-dependent work. On any error (`ErrNotFound`, schema, bad `-c` path) return empty completions and `cobra.ShellCompDirectiveNoFileComp` silently.
- **Binary accessors**: Never read `cfg.Binaries.*` fields directly. Always use nil-safe accessors: `config.DevboxBin(cfg)`, `config.DockerBin(cfg)`, `config.ShellBin(cfg)`. Deploy/condition step `when:` predicates intentionally use hardcoded `sh` (not `ShellBin`) for portability.
- **YAML loader strictness**: Deploy/reset/lifecycle loaders (`LoadDeployConfig`, `LoadResetConfig`, `LoadLifecycleConfig`) and the command-file parser (`model.ParseCommandFile`) use `yaml.Decoder.KnownFields(true)` — unknown fields produce hard errors. Agents manifest loader (`loadAgentsManifest` in `internal/command/render_ai.go`) also uses strict decode. All other loaders (info, styles, docker, localconfig, topology) use lenient `yaml.Unmarshal`. When adding new loaders, match the strictness of the surface: strict for user-edited pipeline/command/manifest YAML; lenient for internal or non-step config.
- **Validation framework**: `internal/validate` package defines `Validator` interface, `Diagnostic` type, and `Registry` for static project validation. Validators run independently per-file to surface all issues regardless of main config load success. Registry dispatches by scope (domain + optional ID). Diagnostics are sorted deterministically and rendered via `RenderDiagnosticsTable`. Exit code is severity-gated: errors → 1, warnings with `--strict` → 1, otherwise → 0. Per-domain validators live in `internal/validate/{config,templates,commands}`; validators are registered via `All()` functions to avoid `init()` side effects.

## Agent-Specific Instructions

Do not overwrite unrelated local changes. Keep command examples current with the `Makefile`. When changing CLI behavior, update tests and config docs.

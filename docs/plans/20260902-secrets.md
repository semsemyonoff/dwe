# Encrypted secrets in workspace config and config packs

## Overview

Today the only place for a credential is plaintext `vars.*` in the gitignored
`workspace/local.yml` (`docs/reference/config/workspace.md` "Personal
credentials", `vars.md`, `setup.md`). That covers values each developer mints
for themselves, but not values the whole team shares and that must not sit in
the open in git: a test Telegram bot token, a Google service-account JSON. Those
end up pasted around by hand and drift between machines.

This change adds **encrypted-at-rest secrets committed to the repository**, in
two shapes:

1. **Scalar values** — a string in any config layer (`workspace.yml`,
   `workspace/defaults.yml`, `workspace/local.yml`) may be an `ENC[age:…]`
   marker. `LoadLayers` decrypts markers in memory, so `${vars.*}`,
   `exports.env`, `dwe vars`, the deployment hash and every other consumer of
   the merged config see plaintext and need no change. The decrypt pass is
   path-agnostic; the `secrets set` command writes only into the `vars:`
   sandbox, which is also the only place the overlay validator lets a
   free-form value live.
2. **Whole files** — a config-pack source whose `from:` ends in `.age` is a
   native age-encrypted file; `service_configs_render` decrypts it before the
   usual `${...}` render into the service hub dir.

One shared **X25519 age key per project**: the public recipient is committed
under a new top-level `secrets: {recipient: age1…}` in `workspace.yml`, the
private identity lives in `~/.config/dwe/keys/<recipient>.key` (or
`DWE_AGE_KEY` / `DWE_AGE_KEY_FILE` for CI). Anyone with the repo can **add** a
secret (encryption needs only the recipient); only identity holders can read
one.

Without a usable identity the project still **loads**: markers stay as-is,
`dwe vars` shows `<encrypted>`, read-only commands work, and a preflight
validator blocks lifecycle commands with a message naming the fix. A missing
key never renders a secret as `""` **and never writes a marker into an output
file**: `dwe render env` and `dwe render config` fail explicitly when a value
they are about to write is still a marker.

### Where plaintext goes (the honest scope)

Decrypted values exist, by design, in: process memory; the project-root `.env`
(gitignored, 0600, already the home of `exports.env`); the service hub dir
outputs of config packs (gitignored via `/services/`); the generated-value
store `.dwe/generated.yml` (0600, gitignored) when a `generated:` harvest
reads a rendered hub file that contains a decrypted value; the container,
which reads the hub dir; child-process output the user chose to run. They are
**kept out of**: git-tracked files (ide/ai/git pack outputs render against a sanitized
config, see decision 9); dwe's own diagnostic echoes (`-v` / `--debug` traces
and the `.dwe/logs` copies of them are redacted, decision 10); `dwe vars
inspect` per-layer output when the key is absent. A value passed to
`secrets set` on the command line lands in shell history like any argument;
the docs say so and point at `--stdin` and the prompt.

Non-goals (decided): no `${secret.*}` namespace, no masking in `dwe vars`
(already decided against — output is not an access boundary), no recipient
lists (the scalar `recipient` field can grow into one later), no `.age`
support in ide/ai/git packs (their outputs are tracked), no `secrets unset`,
no container-side read gate (decision 7), no redaction of child-process
output.

The whole plan ships as **one pull request**. Task order is chosen so that
every intermediate state is safe: bridge hardening lands before decryption,
the render guards and the preflight gate land before any command can write a
marker (`secrets set` is Task 12; nothing earlier mints one).

Related patterns found:

- `yaml.v3` decoding into `map[string]any` **silently drops custom tags**
  (`tok: !secret "abc"` → `"abc"`). Verified. A string marker survives every
  decoder in the tree; a YAML tag would not. This is why `ENC[age:…]`.
- `LoadLayers` + `validateLayerRoots` are the shared loader/validator for
  `LoadConfig` and `ResolveLayeredPath` "so the two cannot drift" —
  decryption and the `secrets:` layer restriction must live there.
- `vars set` takes the project lock pair and runs no preflight; `secrets`
  writers follow it.
- Overlay layers (`defaults.yml`, `local.yml`) may carry only
  `services.<name>.enabled` under `services:` (`validateServicesOverlay`), so
  the practical home of a marker is `vars.*`.
- `dwe render config` is already bridge-allowed (`bridgepolicy.go:92`) and
  runs host-side, so container-initiated renders decrypt with the host key.
- `compose.extra` is the precedent for a root key that is legal in exactly one
  layer and hard-errors elsewhere with a pointer to the right file.
- `age.X25519Identity` implements `fmt.Stringer` **with the secret key**; any
  wrapper must own `String()`.

Dependencies identified:

- `filippo.io/age` v1.3.2 (latest at planning time). First cryptography
  dependency. Justification: standard, audited format; files and markers stay
  readable with the `age` CLI; X25519 gives "encrypt with public key only" for
  free; a home-grown `x/crypto` envelope would be a private format with the same
  dependency weight. Only `internal/shared/secrets/` may import it.

## Solution Overview

```
workspace.yml                 secrets: {recipient: age1…}          (committed)
workspace/defaults.yml        vars.telegram.token: ENC[age:…]      (committed)
workspace/templates/config/bot/google-credentials.json.age         (committed)
~/.config/dwe/keys/age1….key  AGE-SECRET-KEY-1…                    (never in git)

LoadRawLayers ─ read 3 layers (ciphertext)          ← secrets CLI, rekey, status
      │
LoadLayersWithSecrets ─ recipient from workspace.yml ─ LoadIdentity ─ decryptLayers (copy, sorted walk)
      └─ []Layer (plaintext in memory) + SecretsState{Decrypted…, Unresolved…}
                    │
        LoadConfig / ResolveLayeredPath / vars list  (unchanged consumers)
          │      LoadConfigSanitized ─ same assembly over raw layers → ide/ai/git packs (tracked outputs)
          ├─ registers decrypted values with the trace redactor (dwe's own echoes)
   service_configs_render ─ from: *.age → DecryptBytes → ${...} render → hub dir (0600)
   render env            ─ exports.env → refuses to write a marker
```

Key design decisions:

1. **Decrypt in `LoadLayers`, not in `tpl`.** One point; every consumer of the
   merged config (`${vars.*}`, `exports.env` via `config.ResolvePath`, `vars
   inspect`, journal hash) stays unchanged. Decrypting lazily in the template
   resolver would leave `envfile.BuildContent`, `vars get`, JSON dumps and the
   hash as separate crypto-aware sites.
2. **String marker, strict regex.** `^ENC\[age:[A-Za-z0-9+/=]+\]$` — the
   whole scalar or nothing. A string that merely *contains* `ENC[` is data.
3. **Plaintext is always a string.** No `CoerceScalar` on decrypt or on
   `secrets set`; a secret `"123"` stays a string.
4. **Identity is loaded, never carried.** `SecretsState` holds the recipient,
   the identity *source* and the decrypted / unresolved path lists; renderers
   and CLI call `secrets.LoadIdentity` again (one file read).
5. **Degrade, then block on use.** Unresolved markers stay literal in `Raw`;
   the `secrets.unresolved` validator is cherry-picked into preflight (both
   `preflight.Run` and the deploy pre-wizard gate), so `dwe run` / `deploy` /
   `reset` stop with a named fix while `status`, `docs`, `validate`, `prompt`
   keep working. The two lock-free renderers (`render env`, `render config`)
   and `dwe run`'s pre-preflight `.env` render are not behind the gate, so
   they enforce the same policy themselves: a marker in a value about to be
   written is a hard error pointing at `dwe secrets status`.
6. **Hash sees plaintext.** age output is non-deterministic; hashing ciphertext
   would invalidate `already up-to-date` on every re-encrypt. Hashing plaintext
   means re-encrypting the same value is a no-op and changing it re-runs the
   step. Pinned by tests on both hash functions.
7. **Bridge: writes closed, reads accepted, identity env daemon-owned.**
   `secrets` is not in `bridgeAllowedTopLevel`, so no container can mint,
   rekey or export a key. `DWE_AGE_KEY` / `DWE_AGE_KEY_FILE` are stripped
   from the client env at the shim **and** re-supplied from the daemon's own
   environment (the `hostIdentityEnvNames` mechanism), so a container cannot
   choose which host file the host `dwe` parses as an identity, while a host
   that runs with an env-only identity keeps working over the bridge. **Reads
   are deliberately not gated**: `dwe vars get` from a bridged container
   already reaches the host `dwe`, which holds the identity, and returns
   plaintext — the same exposure the container already has through its
   rendered `.env`. Documented as an accepted consequence.
8. **`secrets:` lives in `workspace.yml` only**, enforced in
   `validateLayerRoots` so `LoadConfig` and `ResolveLayeredPath` reject the
   same files. The recipient the decrypt pass reads and the recipient
   `cfg.SecretsState.Recipient` reports are the same value by construction.
9. **Tracked outputs render against a sanitized config.** ide/ai/git packs
   receive a config assembled by `config.LoadConfigSanitized(path)`: the
   same assembly as `LoadConfig` but over the **raw** layers, with no decrypt
   pass at all. Every field a template can reach (`Raw`, `Vars`, `Project`,
   `Runtime`, `Services`, `ServiceCfg`) therefore carries the marker where the
   real config carries plaintext — no path bookkeeping, no ambiguity for
   sequences or dotted keys. A template that reads a secret emits ciphertext
   (already committed, harmless), never plaintext.
10. **dwe's own echoes are redacted.** `LoadConfig` registers every decrypted
    value (length ≥ 4 runes) with a process-global `trace` redactor — the
    loader is the single installer because 60 call sites load config and the
    root `PersistentPreRunE` does not. The redactor is union-merging under a
    mutex and lives for the process (a `dwe test` scenario copy contributes
    the same values), so concurrent pipelines and stacked printers see one
    consistent set; `trace.emit` applies it to every line, which covers `-v` /
    `--debug` command echoes and their `.dwe/logs` mirrors. Child output is
    not touched (non-goal), and values under 4 runes are not redacted — the
    docs say so.
11. **Rekey is a recoverable sequence, not a transaction.** Order: read-only
    pass that decrypts and validates *everything* into memory (a corrupt
    marker or undecryptable `.age` aborts here, before any write) → write the
    new keyfile as the **first mutation** (old one kept) → re-encrypt files one
    by one, each atomically → update `secrets.recipient` last. A crash leaves
    both keys on disk and a mixed tree; re-running `rekey` (or loading with
    `secrets status`) tries the configured identity first and then every
    other keyfile in `~/.config/dwe/keys/` for a marker that fails, so the
    sequence converges.

## Technical Details

### `internal/shared/secrets/` (leaf, imports `filippo.io/age` only)

```go
const MarkerPrefix = "ENC[age:"
func IsMarker(s string) bool                       // strict full-string regex
func ContainsMarker(s string) bool                 // any marker inside a rendered text (output guard)
func Encrypt(plain string, recipient string) (marker string, err error)
func Decrypt(marker string, id Identity) (plain string, err error)
func EncryptBytes(plain []byte, recipient string) ([]byte, error)   // native age file
func DecryptBytes(ciphertext []byte, id Identity) ([]byte, error)
func Keygen() (Identity, error)                    // X25519

type Identity struct { /* unexported *age.X25519Identity */ }
func (Identity) Recipient() string
func (Identity) String() string                    // "age identity for age1…" — NEVER the key
func (Identity) Export() string                    // "AGE-SECRET-KEY-1…", the only accessor
func ParseIdentity(text string) (Identity, error)
func ParseRecipient(text string) error             // "age1…" shape check

type Source string // "env", "env-file", "keyfile", ""
func LoadIdentity(recipient string) (Identity, Source, error)
func LoadAnyIdentity(exclude string) ([]Identity, error)  // every keyfile in the keys dir except `exclude` (rekey recovery)
func KeyfilePath(recipient string) (string, error) // ~/.config/dwe/keys/<recipient>.key
func WriteKeyfile(id Identity) (path string, err error)  // dir 0700 (chmod if it exists), O_CREATE|O_EXCL, 0600
var ErrNoIdentity, ErrWrongIdentity, ErrCorrupt error   // sentinel errors → Unresolved reasons

type Redactor struct{ … }
func NewRedactor(values []string) *Redactor        // drops values shorter than 4 runes, longest first
func (r *Redactor) Redact(line string) string      // replaces each value with "***"
```

`LoadIdentity` order: `DWE_AGE_KEY` (identity text) → `DWE_AGE_KEY_FILE`
(path) → keyfile. The first present source is used and **must** match the
recipient; a mismatch is `ErrWrongIdentity` (with the source named), not a
fall-through to the next source. Keyfile `ErrNotExist` → `ErrNoIdentity`; any
other read error is returned as-is (permissions problems are never hidden).
An empty recipient is `ErrNoIdentity` without touching the filesystem.

`WriteKeyfile` is a true no-clobber write (`O_CREATE|O_EXCL`), and the keys
directory is `chmod 0700` after `MkdirAll` so a pre-existing 0755 directory is
tightened. `%v` / `%s` / `%+v` on an `Identity` (or a struct embedding one)
must never print `AGE-SECRET-KEY-` — pinned by test.

Marker payload: `base64.StdEncoding` of a binary age file (one X25519
stanza). `base64 -d | age -d -i key.txt` opens it; documented as a feature.

### Config

```go
// workspace.go
type SecretsConfig struct { Recipient string `yaml:"recipient"` }
DweConfig.Secrets      *SecretsConfig `yaml:"secrets"`   // the declared block (name matches the key)
DweConfig.SecretsState SecretsState   `yaml:"-"`         // load-time result

type SecretRef struct { Layer, Path string }
type SecretsState struct {
    Recipient      string
    IdentitySource string            // secrets.Source, "" when none
    Decrypted      []SecretRef       // sorted by layer order then path
    Unresolved     []UnresolvedSecret
}
type UnresolvedSecret struct { SecretRef; Reason string } // no_identity | wrong_identity | corrupt

func ValidateLayerRoots(layers []Layer) error        // exported: the per-layer strict-root + secrets rules, for staged writes
func LoadConfigSanitized(workspacePath string) (*DweConfig, error)  // LoadConfig's assembly over LoadRawLayers, no decrypt, empty SecretsState
func LoadConfigSanitizedOrWrap(workspacePath string) (*DweConfig, error)  // the "loading config:" wrapper, same as LoadConfigOrWrap — CLI sites use this one
```

`LoadConfig` is refactored into `LoadRawLayers` / `LoadLayersWithSecrets` +
one private `assembleConfig(layers, state)`; `LoadConfigSanitized` is the same
`assembleConfig` over the raw layers. After assembly `LoadConfig` calls
`trace.RegisterRedaction(values)` with the decrypted plaintexts (decision
10); `LoadConfigSanitized` registers nothing.

`allowedRootKeys` gains `"secrets"`; `tpl.KnownVarHeads` gains `"secrets"` in
the same commit (subset test); `formalBlockStructs` gains
`"secrets": reflect.TypeFor[config.SecretsConfig]()` so a misspelled nested
key (`recipiant:`) warns like every other formalized block.
`${secrets.recipient}` therefore resolves from `Raw` like any root key —
harmless and not documented as a feature.

`validateLayerRoots` (shared, now exported as `ValidateLayerRoots`)
additionally rejects `secrets:` in any layer other than the first
(`workspace.yml`), a non-mapping `secrets:` value, and a malformed
`recipient`, each naming the file. `LoadConfig`, `ResolveLayeredPath` and the
`secrets set` staging check therefore reject the same inputs.

Layer API (all exported, `layers.go`):

- `LoadRawLayers(path) ([]Layer, error)` — today's `LoadLayers` body:
  ciphertext as written. Used by the `secrets` CLI (`status`, `get`, `rekey`,
  inventory) and by `decryptLayers` itself.
- `LoadLayersWithSecrets(path) ([]Layer, SecretsState, error)` — the
  primitive: `LoadRawLayers` → `validateLayerRoots` → recipient from the
  `workspace.yml` layer → `secrets.LoadIdentity` → `decryptLayers` on a
  **deep copy** (the raw slice is never mutated).
- `LoadLayers(path) ([]Layer, error)` — keeps its signature, returns the
  decrypted layers, discards the state. `ResolveLayeredPath` and the three
  `cli/vars` callers keep using it (same pass — no drift).

`decryptLayers(layers, recipient)`: if any layer contains a marker and the
recipient is empty, every marker is recorded `no_identity` with the identity
source `""`. Walk `map[string]any` (keys **sorted**) / `[]any` recursively;
replace marker strings in place (on the copy); record every replaced path in
`Decrypted`; `Unresolved` paths are dot-paths (`vars.telegram.token`, list
index as `.0`) plus the layer path.

`LoadConfigSanitized` is what the ide/ai/git render commands
(`cli/render/ide.go:166`, `ai.go:159`, `templates/git/git.go:367`) and the
three `validate/templates` dry-run builders load; `packcommon` itself is
untouched. The config-pack renderer keeps the real `cfg`.

`prompt.readProjectName` (and the prefix read next to it): a value that is a
marker is treated as unset — the hot path never loads the full config, and an
encrypted project name is nonsensical anyway; a one-line guard plus test.

### Output guards (`render env`, `render config`)

Neither renderer runs preflight, and `dwe run` renders `.env` *before* its
preflight, so each refuses to materialize a marker:

- `envfile.BuildContent`: every emitted value — the three system values
  (`PROJECT` comes from `cfg.Project.Name`, l.36) **and** each export rule —
  is checked with `secrets.IsMarker`; a hit is an error `exports.env[<name>]:
  value at <from> is an undecrypted secret — see 'dwe secrets status'`.
  `envfile.Write` additionally `os.Chmod`s the root `.env` to 0600 so a
  pre-existing permissive file is tightened. Reached by `dwe render env`, the
  compose auto-regen in `cli/docker`, the `.env` regeneration in `dwe
  services enable/disable` (`cli/service/service_toggle.go:392,509`), and
  `renderAndSourceDotEnv` in `lifecycle/run.go` (where it fires before
  preflight and is therefore the first thing a keyless `dwe run` reports —
  acceptable, it is explicit and names the fix). All four fail the same way
  on an unresolved marker; the docs list them.
- `renderTemplateFile`: after `tpl.RenderCommand`, if
  `secrets.ContainsMarker(out)` → error naming the entry's `to:` path. The
  render context is `cfg.Raw`, so this catches every `${...}` substitution of
  an unresolved marker without tracking which one.
- ide/ai/git render commands load `LoadConfigSanitized`; a tracked output
  can at most contain ciphertext. A regression test per renderer renders a
  template that reads `.Cfg.Raw.vars.<secret>` and `.Cfg.Vars` and asserts
  the output carries the marker, not the plaintext.

### Config packs

`RenderConfigs`: if any `m.Render[i].From` ends in `.age`, load the identity
once (`secrets.LoadIdentity(cfg.SecretsState.Recipient)`) and pass it down;
skip the lookup entirely otherwise, so a pack without encrypted sources never
touches `~/.config`. An empty recipient with an `.age` source is the same
error path as a missing identity (`ErrNoIdentity`), worded to point at
`secrets:`.

`renderTemplateFile`: after `os.ReadFile`, if `strings.HasSuffix(rel, ".age")`
→ `DecryptBytes` → continue with `tpl.RenderCommand` on the plaintext. Error
wording: `render template %s: encrypted source needs the project identity for
%s (%v) — see 'dwe secrets key import'`. **`to:` is never auto-stripped**:
authors write `from: creds.json.age`, `to: src/creds.json`. Outputs whose
source was `.age` are written 0600 **and explicitly `os.Chmod`ed** (a
pre-existing 0644 target is tightened; `os.WriteFile` alone would not);
other outputs keep 0644 — a scalar secret substituted into `.env` lands in
the gitignored hub dir at the pack's usual mode, and that is documented. The
container reads a 0600 file fine because it runs as the host UID/GID that
`exports.env` already publishes.

`ValidateManifest` and `check.go` are **not** changed; "`.age` source but no
`secrets.recipient`" is reported by the `secrets.recipient` validator at
`dwe validate` time and by `RenderConfigs` at render time.

### Trace redaction

`trace` gains `RegisterRedaction(values []string)` and, for tests,
`ResetRedaction()`. The redactor is a process-global set behind the existing
`mu`: registration is a **union** (never a replacement), so nested and
concurrent config loads — `dwe test --parallel` runs several pipelines with
stacked `SetPrinter` entries and per-context `WithLinePrinter` printers — all
see one consistent set, and no restore-ordering problem exists because
nothing is ever removed. `emit` applies it to every line before any printer
(context override, stack, or fallback). The only installer is
`config.LoadConfig` (decision 10). Values shorter than 4 runes are skipped
(redacting `"1"` would shred every line); longer values are replaced first so
a value that contains another is handled once. Redaction runs at **two**
points: `trace.Command` redacts each argument *before* `FormatCommand`
(`quoteArg` rewrites `'` to `'\''`, so a secret containing an apostrophe is
no longer a substring of the formatted line), and `emit` redacts the finished
line for every other echo. `FormatCommand` itself is untouched — quoting
stays byte-identical and its goldens do not move. The `.dwe/logs` mirrors of
parallel-step traces go through the same `emit`, so they are covered.

### `vars` integration

- The `Encrypted` flag is derived from the **origin** layer, not from "any
  layer": reuse `layerBadge`'s origin scan (the highest-precedence layer with a
  non-nil value) and ask whether `cfg.SecretsState.Unresolved` holds that
  `(layer, path)` pair. A `defaults.yml` marker overridden by a plaintext
  `local.yml` value renders plaintext; a `local.yml` marker over a plaintext
  default renders `<encrypted>`.
- `runVarsList` / `browser.go`: unresolved leaves render `<encrypted>`;
  `VarListItem` / JSON entry carry `Encrypted bool` (`"encrypted": true`,
  `omitempty`); `layerBadge` gains a ` (encrypted)` suffix for them.
- `vars inspect`: **every** per-layer field of `LayeredValue` (`Default`,
  `Local`, `Current`, text and JSON) that holds an unresolved marker is
  rendered as `<encrypted>`; `VarInspect` gains `Secret string` rendered as
  one extra line: `secret: decrypted via keyfile (~/.config/dwe/keys/age1….key)`
  or `secret: unresolved — no identity for age1…`. Test asserts the output
  contains no `ENC[age:` substring.
- `vars get`: a leaf prints `<encrypted>` (exit 0, JSON `"encrypted": true`);
  a **namespace** prints the subtree with every unresolved marker replaced by
  `<encrypted>` recursively, in both text and JSON.
- `vars set` keeps writing plaintext to `local.yml`; it gains one stderr
  warning (not in JSON mode) when the path it shadows holds a marker in a
  lower layer: `note: vars.x is an encrypted secret in defaults.yml; this
  plaintext override wins locally`. `varsusage` unchanged.

### CLI `dwe secrets`

Package `internal/cli/secrets/`, `NewCmd(groupID, flags)` wired next to
`vars` in `groupConfiguration`. All writers: `cmdctx.AcquireProjectLocksOrReport`,
no preflight. Read-only: `status`, `get`, `key export`, `decrypt`.

JSON contract (`--output json`): every command has a typed DTO through
`cmdctx.WriteData` and returns typed `cmdctx.Err`/`ErrWrap`; warnings are
gated behind `flags.Output != "json"`. Writers emit `{"path":…,"file":…}` /
`{"recipient":…,"keyfile":…}` on success. `key export` emits
`{"identity": "AGE-SECRET-KEY-…"}`. `encrypt` / `decrypt` are byte streams:
with `-o -` they **reject** `--output json` (typed error `secrets_raw_stream`)
and otherwise report `{"from":…,"to":…}`.

| Command | Behaviour |
|---|---|
| `secrets init` | `Keygen`; `WriteKeyfile`; write `secrets.recipient` into `workspace.yml` via the node writer. Refuses when `secrets.recipient` is already set (point to `rekey`) or when a keyfile for the new recipient exists. Prints the recipient and the keyfile path. |
| `secrets status` | Recipient, identity source (`env` / `env-file` / `keyfile <path>` / `none`), a table of every marker across the **raw** layers (`layer`, `path`, `state`: `decrypted` / `unresolved: <reason>`), and every `*.age` under `workspace/templates/config/**` with `decryptable` / `not decryptable` (each one is actually decrypted). Rows sorted by layer order then path. The text table is a `render.tableView` (shrink → wrap → records) and ships the `…At(width)` sibling. Exit 0 always — it is a report, not a gate. |
| `secrets set <path> [value]` | Value from arg, `--stdin` (whole stdin, one trailing newline trimmed), or a hidden `ui/ask` prompt when neither is given and stdin is a TTY. Path must start with `vars.` (the only free-form sandbox; `varsusage.VarsPrefix`); descending through an existing mapping is normal, descending through an existing non-mapping node is refused (the `ApplyOverlayToNode` rule) except when the leaf itself is a scalar being replaced. The staged document is `EncodeYAMLNode`d, decoded back to a map, swapped into the raw layer list and run through `config.ValidateLayerRoots` before it is persisted, so a `set` can never leave a layer unloadable. `Encrypt(value, recipient)`; write into `workspace/defaults.yml` (`--file workspace` targets `workspace.yml`; `--file local` is refused with a pointer to `vars set`). No coercion. Requires only the recipient. |
| `secrets get <path>` | `LoadRawLayers`, find the marker at `path` in the highest layer that holds one, decrypt, print. Error when the path holds no marker (use `vars get` for plaintext). |
| `secrets encrypt <file> [-o out]` / `secrets decrypt <file> [-o out]` | File helpers. Defaults `<file>.age` / strip `.age`; refuse to overwrite without `--force`; decrypt output mode 0600 (chmod after write); `-o -` writes to stdout. Inputs and outputs inside the project go through `pathsafe.ContainedRel` + `CheckNoSymlinks` + `Lstat`-is-regular; a symlink or device as input or output is refused. `encrypt` needs the recipient only. |
| `secrets key export` | Print `Identity.Export()` to stdout (the sharing path: password manager, onboarding). Warn on stderr when stdout is a TTY (text mode only). |
| `secrets key import [--file F]` | Read identity text from `--file` or stdin, `ParseIdentity`, verify `Recipient()` equals the configured one, `WriteKeyfile`. |
| `secrets rekey` | Decision 11. Needs an identity for every existing marker (configured first, then `LoadAnyIdentity` for stragglers). Read-only pass: decrypt every marker (raw layers via the node walker) and every `.age` file (same path discipline as `encrypt`) into memory — any failure aborts here with nothing written. Then `Keygen` → **write the new keyfile as the first mutation** (old kept) → re-encrypt → write each `.age` file atomically, then each layer file via the node writer → update `secrets.recipient` **last**. A failure mid-way is recoverable by re-running. |

Node writer (`internal/core/project/local/`): renamed to the neutral
`LoadYAMLNode(path, label)` / `WriteYAMLNode(path, doc, label, policy)` plus
`EncodeYAMLNode(doc) ([]byte, error)` (the in-memory half of the write, for
staging). `policy` is one of two explicit modes: `ForceMode(0600)` — what
`local.yml` gets today via `writeFileAtomic`, kept byte-for-byte for the
`LoadLocalYAMLNode` / `WriteLocalYAMLNode` wrappers — and
`PreserveOrDefault(0644)` for `workspace.yml` / `defaults.yml` (tracked
files; forcing 0600 would surprise git and editors). Writing into
a document that carries YAML anchors and a `<<:` merge key (common in
`workspace.yml`) must either succeed by appending the key beside the merge or
fail with a clear error — never silently drop the merge; `mappingHasMergeKey`
already exists for that branch and gets a test. A new
`ReplaceScalars(doc, fn func(string) (string, bool))` walks every scalar node
(mappings, sequences, anchored nodes — aliases are skipped because the anchor
is rewritten once) and replaces in place, preserving comments, style and
anchors; `rekey` uses it instead of reconstructing from maps. `secrets` must
not grow a second YAML writer.

`ui/ask` gains `FieldPassword` (huh `Input` with `EchoModePassword`) so the
hidden prompt goes through `widgets.RunHuhForm` like every other form;
`detectKinds` classifies it as an input kind so the submit-help line and
`RunOptions.Quit` behave exactly as for `FieldInput`.

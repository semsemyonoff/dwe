# `dwe shell -c "<command>"` one-shot mode + free global `-c` shorthand

## Overview

Add a one-shot execution mode to `dwe shell` via a new `-c, --command "<string>"` flag.
When set, the command is evaluated by the container's shell (`<resolved shell> -c "<command>"`)
and `dwe` exits with the child command's exit code. TTY is auto-detected (`-it` only when
both stdin and stdout are terminals, otherwise `-i` for clean piping). dwe's own
`exec → <container>` / `run → <service>` banners are suppressed so script stdout stays
untouched.

Behavior with the flag unset is identical to today: interactive shell session.

To expose `-c` on `shell`, the global root persistent flag `-c, --config` loses its
shorthand. `--config <path>` long form continues to work everywhere (tests, CI, debugging).

This is sugar over `docker exec -it <container> bash -c '...'` workflows that developers
currently type by hand.

## Solution Overview

**Architecture choice:** parallel one-shot dispatch path rather than overloading `runServicesCLI`. The interactive and one-shot paths share the resolved `shellOptions` (mode, shell, user, workdir, env) but diverge on:

- argv shape (`<shell>` vs `<shell> -c "<command>"`)
- TTY flags (`-it` vs auto-detected `-it`/`-i`)
- stdout banner (info line vs silence)
- exit-code handling (cobra error vs explicit `os.Exit` for nonzero child)

Keeping the two paths separate is clearer than a per-call-site conditional inside the existing helpers.

**Key design decisions:**

1. **Flag shape:** `-c, --command "<string>"` (single string). No argv positional, no `--`. Matches `bash -c` / `ssh host '<cmd>'` muscle memory.
2. **TTY auto-detect** — two flag shapes, one decision:
   - Detector: `interactive := widgets.IsInteractiveFn(os.Stdin) && widgets.IsInteractiveFn(os.Stdout)`.
   - `docker exec` path: `interactive ⇒ ["-i", "-t"]`, else `["-i"]`.
   - `docker compose run` path: TTY is the **default** for `compose run`; the `-T` flag *disables* it. Shape: `interactive ⇒ ["-i"]`, else `["-i", "-T"]`. Always include `--rm` (existing behavior).
3. **Banner suppression:** one-shot helpers do NOT call `render.Stdout().Info(...)`. dwe errors continue to flow via cobra to stderr.
4. **Exit code — use the existing project convention** (NOT a custom `os.Exit` indirection). `cmd/dwe/main.go:75-81` already extracts `interface{ ExitCode() int }` from errors and calls `os.Exit(code)`. Multiple existing precedents: `validate.validationFailedError:120`, `deploy.deployCancelledError:213`, `snapshot.snapshotInterruptedError:493`, `completion.completionExitError:25`. Additionally, `main.go`'s `errHandler` at lines 40-44 **suppresses** Fang's "Error:" banner for `ExitCode()`-bearing errors — exactly what we want so the user sees only the child's stdout/stderr.
   - Define `shellCommandExitError struct { code int; underlying error }` in `internal/cli/shell/exec.go` with `Error()` (returns `underlying.Error()`) and `ExitCode() int` (returns `code`).
   - One-shot helpers detect `*exec.ExitError` from `runInteractive`/`cmd.Run` and wrap it: `return &shellCommandExitError{code: exitErr.ExitCode(), underlying: exitErr}`.
   - Non-exit errors (docker daemon unreachable, container not found, etc.) return through the normal cobra error path unchanged.
   - No `os.Exit` inside `shell/`. No `exitFn` package variable. No `propagateExit` helper.
5. **Validation:** empty/whitespace-only `-c` value rejected with `-c/--command cannot be empty or whitespace-only`.
6. **Mode + service selection:** unchanged. Identical matrix and selector behavior as interactive shell.
7. **Defaults precedence:** reuse the service `cli` block (flag > config > built-in). `--shell sh -c "..."` works naturally because `--shell` resolves the binary that evaluates `-c`.
8. **Testable dispatch:** extract `dispatchShell(cfg, compose, serviceName, shellFlags, processEnv, dockerBin) error` from `RunE` so tests can exercise the branch (`flagCommand != ""` → one-shot, else → interactive) without going through cobra's exec plumbing.

**Integration:** the one-shot branch lives inside `RunE` after config load + service pick + flag resolution. The existing `runServicesCLI` call site is preserved for the interactive path. No changes to `internal/core/`, no changes to `service.yml` schema, no new locks, no preflight.

## Technical Details

**New struct field** (`internal/cli/shell/exec.go`):
```go
type shellCLIFlags struct {
    asRoot  bool
    mode    string
    shell   string
    user    string
    workDir string
    envVars []string
    command string // NEW — non-empty triggers one-shot mode

```

**New helpers** (`internal/cli/shell/exec.go`):

```go
// shellCommandExitError carries the child's exact exit code through cobra/fang.
// cmd/dwe/main.go:75-81 already extracts `interface{ ExitCode() int }` and calls
// os.Exit; the errHandler at main.go:40-44 also suppresses Fang's "Error:" banner
// for ExitCode-bearing errors so the user sees only the child's output.
type shellCommandExitError struct {
    code       int
    underlying error
}
func (e *shellCommandExitError) Error() string  { return e.underlying.Error() }
func (e *shellCommandExitError) ExitCode() int  { return e.code }
func (e *shellCommandExitError) Unwrap() error  { return e.underlying }

// ttyDetector is a package-level seam for tests; defaults to widgets.IsInteractiveFn.
// Tests inject a fake to drive the auto-detect branches without touching real stdio.
var ttyDetector = widgets.IsInteractiveFn

// stdioInteractive returns true when both host stdin and host stdout are terminals.
func stdioInteractive() bool {
    return ttyDetector(os.Stdin) && ttyDetector(os.Stdout)
}

// dockerExecTTYFlags returns ["-i", "-t"] when interactive, else ["-i"].
// Stdin is always wired so scripts can pipe input.
func dockerExecTTYFlags() []string

// composeRunTTYFlags returns ["-i"] when interactive (compose run allocates TTY
// by default), else ["-i", "-T"] (-T disables the default TTY allocation).
func composeRunTTYFlags() []string

// dockerExecOneShot runs `<dockerBin> exec <ttyFlags> [-u u] [-w workDir] [-e K=V...]
// <container> <shell> -c "<command>"` with no info banner. On *exec.ExitError from
// the child, wraps as *shellCommandExitError so main.go can preserve the exit code.
// Non-exit errors return unchanged.
func dockerExecOneShot(containerName, shell, u, workDir string, env map[string]string,
    command string, processEnv []string, dockerBin string) error

// composeRunOneShot runs `<dockerBin> compose [-p ...] [-f ...] ... run --rm <ttyFlags>
// [-u u] [-w workDir] [-e K=V...] <service> <shell> -c "<command>"` with no info banner.
// Same exit-code wrapping as dockerExecOneShot.
func composeRunOneShot(compose *docker.Compose, serviceName, shell, u, workDir string,
    env map[string]string, command string) error

// runOneShotCommand mirrors runServicesCLI's mode switch but invokes the one-shot
// helpers. getState/execOneShot/runOneShot are injected for testability.
type oneShotExecFunc func(containerName, shell, u, workDir string, env map[string]string, command string) error
type oneShotRunFunc func(compose *docker.Compose, serviceName, shell, u, workDir string, env map[string]string, command string) error

func runOneShotCommand(
    cfg *config.DweConfig,
    compose *docker.Compose,
    serviceName string,
    flags shellCLIFlags,
    getState func(string) (string, error),
    execOneShot oneShotExecFunc,
    runOneShot oneShotRunFunc,
) error

// dispatchShell is the testable seam called from RunE. When flags.command is non-empty
// it routes to runOneShotCommand; otherwise to runServicesCLI. Tests can call it
// directly with fakes for getState / exec / run paths, bypassing cobra entirely.
func dispatchShell(
    cfg *config.DweConfig,
    compose *docker.Compose,
    serviceName string,
    flags shellCLIFlags,
    processEnv []string,
    dockerBin string,
) error
```

`dispatchShell` itself contains the one-shot vs interactive branch and builds the injection closures, keeping `RunE` thin and tests easy to wire:
```go
func dispatchShell(cfg *config.DweConfig, compose *docker.Compose, serviceName string,
    flags shellCLIFlags, processEnv []string, dockerBin string) error {
    stateFn := func(name string) (string, error) {
        return containerStateStatus(name, processEnv, dockerBin)
    }
    if flags.command != "" {
        execOneFn := func(c, sh, u, w string, env map[string]string, cmd string) error {
            return dockerExecOneShot(c, sh, u, w, env, cmd, processEnv, dockerBin)
        }
        runOneFn := func(co *docker.Compose, s, sh, u, w string, env map[string]string, cmd string) error {
            return composeRunOneShot(co, s, sh, u, w, env, cmd)
        }
        return runOneShotCommand(cfg, compose, serviceName, flags, stateFn, execOneFn, runOneFn)
    }
    execFn := func(c, sh, u, w string, env map[string]string) error {
        return dockerExecCLI(c, sh, u, w, env, processEnv, dockerBin)
    }
    return runServicesCLI(cfg, compose, serviceName, flags, stateFn, execFn, composeRunCLI)
}
```
Errors returned by `runOneShotCommand` already carry `*shellCommandExitError` when applicable; `main.go` extracts the code and suppresses the styled banner.

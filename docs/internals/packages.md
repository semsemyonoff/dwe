# Internal Package Layout

Internal architecture reference for agents and contributors. This document captures per-package responsibilities, invariants, and cross-package contracts that are not derivable from the code alone (or that would be expensive to re-derive every time). User-facing schema / behavior docs live under [`docs/reference/`](../reference/) — this file is purely about *internal code structure*.

The executable entrypoint lives in `cmd/devbox`; most code is under `internal/`. Tests sit next to code as `*_test.go`; fixtures live in package-local `testdata/`.

## Foundation

- `cmd/devbox/main.go` — entry point (uses `fang.Execute` for styled help/errors). Four non-obvious startup behaviors: (1) **Prompt hot-path bypass** (`isPromptInvocation`): if `os.Args` is exactly `["…", "prompt"]` or `["…", "prompt", "--check"]`, `prompt.Run(os.Stdout, os.Args[2:])` is called and `os.Exit` fires immediately — before cobra, fang, pflag pre-parse, and `loadHelpColorScheme`. Any other `prompt` shape (e.g. `--help`, unknown flags, `--check=true`) falls through to cobra so help/errors render normally. (2) **Pre-Cobra pflag pre-parse** (`configPathFromArgs`): extracts `--config/-c` from `os.Args` using pflag with `UnknownFlags=true` *before* Cobra runs, so the project root can be located without triggering Cobra flag parsing. (3) **Early styles injection** (`loadHelpColorScheme`): calls `project.Locate` + `config.LoadStylesConfig` + `ui.ApplyStyles` before `fang.Execute`, then passes a `fang.WithColorSchemeFunc` so `--help` output uses the project's `accent`/`muted` tokens. Silent on all failures — Fang's default colors apply when styles cannot be loaded. `ApplyStyles` runs twice on a normal invocation (once here before Cobra, once from root `PersistentPreRunE`); the second call is a no-op when styles haven't changed. (4) **Custom error handler**: suppresses output for `ErrSilent` (command already printed its own error) and for `ExitCode`-bearing errors (diagnostics already printed via `fang.WithErrorHandler`); delegates all others to `fang.DefaultErrorHandler`. Exit-code errors also produce a non-zero `os.Exit(ec.ExitCode())` after `fang.Execute` returns.
- `internal/version/` — `Version` / `Commit` / `Date` / `BuiltBy` vars + `Info()`; injected via `-ldflags -X`.
- `internal/project/` — project discovery: `Locate(flag)` (upward walk from cwd; explicit mode when flag non-empty), `ValidateSchema(path)` (schema_version must be `"2"`), `Resolve(flag)` (Locate + ValidateSchema); `ErrNotFound` sentinel; constants `ConfigFilename`, `SchemaField`, `SupportedSchema`.
- `internal/prompt/` — shell-prompt segment renderer for starship / similar integrations. Public entry point: `Run(stdout io.Writer, args []string) int`; internal testable form: `runFromDir(stdout, args, cwd string, useColor bool) int` (explicit cwd so tests use `t.TempDir()` without touching process state). **Lipgloss is deliberately not imported**: lipgloss auto-downgrades to no-color when stdout is piped, which it always is when starship invokes `devbox prompt`. Local `findRoot(start)` stat-walks up to `devbox.yml` — intentionally duplicates `project.Locate` logic to avoid `filepath.EvalSymlinks` cost and the cwd-injection issue on the `Locate` path. Three stub structs (`devboxStub` / `stylesStub` / `stateStub`) decode only the fields the prompt needs via lenient `yaml.Unmarshal`. Color is emitted as TrueColor ANSI (`\x1b[38;2;R;G;Bm…\x1b[39m`) using `strings.Builder` + `strconv.AppendUint` — never `fmt.Sprintf` to keep the render path allocation-free. `NO_COLOR` env: suppressed when the variable exists at all (`os.LookupEnv`, value irrelevant). Any error (yaml parse, IO, missing project) → silent exit 1.

## Configuration

- `internal/config/` — `DevboxConfig` and all YAML loaders (`LoadConfig`, `LoadServices`, `LoadServiceFolder`, `LoadDeployConfig`, `LoadDockerConfig`, `LoadLifecycleConfig`, `LoadInfoConfig`, `LoadStylesConfig`); merged-config types (services, render policy, parallel groups, actions, file gates, `DeployStep.SubStepOverrides` / `SubStepOverride`, `StatusColumn` for custom per-row columns). **Unified services schema.** All service-shaped entities (apps, tools, infra) live under `devbox/services/`, one folder per service. `service.yml` is the per-folder declaration file; folder name = map key (no `name:` field inside the file). Services are discriminated by `type:` (`app` | `tool` | `infra`). `ServiceType` is a named string type with typed constants `ServiceTypeApp` / `ServiceTypeTool` / `ServiceTypeInfra`, predicate methods `IsApp()` / `IsTool()` / `IsInfra()` on both `ServiceType` and `ServiceConfig`, sentinels `ErrServiceTypeMissing` / `ErrServiceTypeUnknown` / `ErrServiceFieldNotAllowed` / `ErrServiceExtendsCrossType` / `ErrServicePortsShape` / `ErrServiceHostsShape` / `ErrServicePortOutOfRange` / `ErrDependsOnTool`, and an unexported `allowedFieldsFor(t)` field allowlist consumed by both loader (strict-decode) and validators (updated to include `on_enable`, `on_disable`, `notes` for all toggleable service types). Each `ServiceConfig` owns `Ports map[string]int` and `Hosts map[string]string` (always maps — no scalar shorthand); helpers `Port(name)` / `Host(name)` return zero values for missing keys. `ServiceConfig` also has `OnEnable *ServiceToggleHooks`, `OnDisable *ServiceToggleHooks`, `Notes *ServiceNotes` fields. `ServiceToggleHooks{Requires ToggleRequires, Before []string, After []string}`; `ToggleRequires` is a string enum with zero-value `RequiresUnspecified`, values `RequiresNone`/`RequiresRestart`/`RequiresDeploy`. The dot-path namespace is `services.<name>.ports.<port-name>` / `services.<name>.hosts.<host-name>` — `runtime.ports.*` / `runtime.hosts.*` and the standalone `tools.yml` / `ToolConfig` / `LoadToolsConfig` / `validateToolsOverlay` / `injectToolsIntoRaw` surfaces are **gone**. **`LoadConfig` sequencing**: load services via `LoadServices(baseDir)` → `validateServicesOverlay` per layer (rejects any key other than `enabled:` / `ports:` / `hosts:` under `services.<name>` with per-layer source attribution; same shape rules as per-folder `service.yml` — ports map → int in 1..65535, hosts map → string) → merge 3-layer raw YAML (devbox.yml → defaults.yml → local.yml) → resolve `Enabled` and **deep-merge** per-developer port/host overrides into `cfg.Services[name].Ports` / `.Hosts` by entry name (`applyOverlayPorts` / `applyOverlayHosts` — declared entries the overlay does not mention are preserved; new entries are added) → `injectServicesIntoRaw` (mirrors every resolved field including post-overlay `ports` / `hosts` so `${services.X.ports.Y}` resolves through `Raw`). `LoadServiceFolder(baseDir, name)` reads `devbox/services/<name>/service.yml` with strict decode (responsibilities 1-6 of the old single-file loader); `LoadServices(baseDir)` enumerates `devbox/services/*/`, calls `LoadServiceFolder` per folder, applies cross-service `extends:` toposort + inheritance merge, and collects all folder errors via `errors.Join`. Missing `devbox/services/` directory → empty map (no error). **Per-developer port/host overrides are a load-bearing devbox feature** — developers must be able to remap a clashing port or change a `*.local` hostname in `local.yml` without touching the shared service folders, and the resolved values must stay visible in `devbox status`. Do not narrow the overlay allowlist back to `enabled:` only, and do not remove the HOSTS / PORTS columns from `ui.RenderServicesTable`. `RuntimeConfig` is now `{ UseHTTPS, SPX }`. `extends:` resolution uses `slices.Clone` / `maps.Clone` defensive copies so child mutation never corrupts parent. Per-type accessors `(c *DevboxConfig).AppServices()` / `ToolServices()` / `InfraServices()` (each filters by type); `ComposeFiles()` / `ComposeFilesAll()` emit `base → tools (sorted) → infra (sorted) → apps (sorted)` — order is part of the public surface, locked. **Always** access binaries via `config.DevboxBin`/`DockerBin`/`ShellBin`/`GitBin` (nil-safe), never `cfg.Binaries.*`. **Deploy config loaders** were split by context: `LoadProjectDeployConfig(path)` (project-wide `devbox/deploy.yml` — rejects `after:` field with `ErrAfterFieldNotAllowed`); `LoadServiceDeployConfig(path)` (per-service deploy — permits `after:`); `LoadServiceDeployConfigs(baseDir, services)` (bulk loader for all services); `ParseDeployConfigForValidation(path)` (parse-only for validators, permits `after:` so validators can inspect and emit per-file diagnostics). `LoadResetConfig` (project-wide) rejects `after:`. New `LoadServiceResetConfig(baseDir, name)` and `LoadServiceResetConfigs(baseDir)` for per-service `reset.yml` (also reject `after:`). Additional loaders: `LoadSnapshotConfig(baseDir)` (strict-decode, `KnownFields(true)`; returns `(nil, nil)` cleanly when `devbox/snapshot.yml` is absent — caller decides whether absence is fatal per subcommand); `LoadValidateConfig(baseDir)` (strict-decode; single parse point — callers thread the result into `validate.Context` rather than re-parsing); `LoadUIConfig(cfg)` / `UIConfig` (loaded leniently from the `ui:` block in `devbox.yml`; pointer fields distinguish absent from explicit zero). User-visible schema details: `docs/reference/config/`.
- `internal/userconfig/` — user-level config loader (`Load(projectRoot)`): defaults → `~/.config/devbox/config` (identical path on every OS — no platform-native location, no XDG fallback) → `<projectRoot>/.devbox/config` → env (`DEVBOX_NOTIFY_*` and `DEVBOX_LANGUAGE`). Flat `key = value` parser (full-line `#` only, inline-`#` rejected, dotted keys rejected, unknown keys warn for forward-compat). `Config.NotifyEnabledFor(kind string) bool` is the master+per-op gate keyed on `"deploy"` / `"run"` / `"command"` (string-keyed so `notify` doesn't import `userconfig` cyclically). `Config.Language string` field holds the resolved locale (empty = unset, resolved at startup). User-visible details: `docs/reference/config/notifications.md` (notify) and `docs/reference/config/i18n.md` (language).
- `internal/i18n/` — localization system: embedded + project-layer translation file loading, locale resolution, and typed lookup. **Schema**: `Bundle{UI map[string]string, Commands map[string]CommandStrings, Groups map[string]GroupStrings}` (CommandStrings and GroupStrings carry description + params/title respectively). **File format**: YAML files under `internal/i18n/translations/` (built-in) and `<projectRoot>/devbox/i18n/` (project overlay, optional); strict `KnownFields(true)` decode. **Loader**: `Load(projectRoot)` reads embedded files + project overrides (project-wins deep merge per locale); returns a `*Store` with methods `T(locale, uiKey, fallback)` (generic lookup for `ui.*` namespace), plus typed helpers `CommandDescription` / `CommandConfirmationText` / `ParamDescription` / `GroupTitle` / `GroupDescription` (all with same locale → en → fallback chain). `LoadProjectBundles(projectRoot)` returns per-file parse metadata for the validator (source path, locale, parse error if any); missing directory → `(nil, nil)`, OS error → sentinel `ProjectFile{Locale: "", ParseErr}`, parse error → non-fatal (skipped, file appears in result slice). **Resolver**: `ResolveLocale(flagLang, configLang, sysLang)` precedence chain: flag → config → system `$LANG` parse → `"en"` default. **Scope v1**: user-command `description`/`confirmation_text`/`param.description`, command-group `title`/`description`, and doc-generator `ui.*` strings (section headers + property labels). Devbox's own Cobra strings stay English; `${snapshot.*}` variables stay English. **Coverage test**: `coverage_test.go` ensures every `ui.*` key in built-in `en.yml` exists in every other built-in locale. User-visible details: `docs/reference/config/i18n.md`.
- `internal/localconfig/` — local YAML toggle helpers: `LoadLocalYAML`, `WriteLocalYAML`, `SetLocalEntryEnabled`, `ValidateServiceToggle`.
- `internal/envfile/` — `.env` generation: `BuildContent(cfg)`, `Regenerate(configPath)`. No cobra / UI deps.

## Setup / Wizard

- `internal/setup/` — interactive setup wizard for fresh projects (`devbox/setup.yml` schema + executor). **Model**: `SetupConfig{Questions []Question}`, `Question{ID, Type, Title, Description string; Required bool; Writes string; Options []Option; Validate *ValidateSpec}`, `Option{Value, Label string}`, `ValidateSpec{Preset, Regex string}`. **Loader**: `LoadSetupYAML(path)` (strict-decode, missing file → `(nil, nil)`, parse errors wrapped); semantics-permissive (unknown `Type` / duplicate IDs / invalid `writes:` caught by validators, not loader). **Merge logic**: `BuildOverlay(questions, answers) map[string]any` (dot-path → nested map), `BuildPortOverlay(overrides) map[string]any` (port key → `services.<name>.ports.<port_name>`), `MergeIntoLocal(existing, overlay)` (deep-merge with conflict detection). **Validation**: `ValidateAndCoerce(q, raw) (any, error)` — processes `input`-type answers through preset validators (`port` → `int`; `hostname`, `path`, `non-empty` → `string`) or regex checks, returning typed values; other question types bypass coercion (huh already produces typed output). **Wizard executor**: `Run(ctx, WizardDeps)` orchestrates port-conflict prompts + setup questions (answers → overlay → merge → atomic write); huh-bound asker functions (`AskQuestions`, `AskPortOverrides`) are dependency-injected for testability. **Huh bindings**: `NewHuhAsker(out)` returns the production asker functions; `coerceInputAnswers`, `coercePortOverrides` are pure helpers extracted for unit testability. Sentinel error `ErrWizardCanceled` indicates user abort (returns without writing). **Type/semantic enforcement at wizard runtime** (belt-and-suspenders after huh/validators): type assertions per question type, required-answer checks (zero-value rejection), re-validation of `input` presets against answer map values, `BuildPortOverlay` range check (1..65535).

## Docker / Stack

- `internal/docker/` — `Compose` for building/executing `docker compose` with policy args; `NewCompose` / `NewComposeAll`; always read the binary via `Compose.BinName()` (nil/empty-safe). Health helpers: `WaitContainersHealthy`, `HealthStatus`, `ContainerIDsFor`. `StopContainer(ctx, dockerBin, name string, timeoutSec int) error` added for direct container stop (no compose); idempotent on "No such container". `DefaultStopTimeoutSec` exported constant shared with daemon_stop.go.
- `internal/stack/` — Docker Compose topology + health, plus status section collectors / renderers: `AggregateHealth`, `FetchComposeTopology`, `ParseTopologyFromFiles`; `RenderHealth` / `RenderApps` / `RenderTools` / `RenderInfra` / `RenderDeployStatus` / `RenderTopology` are pure string-returning section renderers composed by the `status` group — one per service `type:` (apps / tools / infra are three distinct sections, each filtered by `IsApp()` / `IsTool()` / `IsInfra()`). `RenderApps` / `RenderTools` / `RenderInfra` return `(string, []error)` so the command layer aggregates one stderr warning per section; `BuildCustomColumns(cfg, t ServiceType)` + `RenderCustomCells(defs, data)` power the per-service `status:` block (hermetic `tpl.Render` only — never `RenderCommand`); `CollectGitWorkspace(ctx, cfg, projectRoot)` runs `<config.GitBin(cfg)> status -b --porcelain=v2` per service under `errgroup.WithContext` + `SetLimit(8)` with `exec.CommandContext` for cancellation; probes `<svc.Dir>/src` (mirrors `internal/templates/git`, which writes hooks to `<svc.Dir>/src/.git/hooks/`) — services whose `<dir>/src` is missing or not a directory are silently omitted; pre-checks `<dir>/src/.git` to avoid walking to a parent repo (blank cells when absent, nil row.Err); dedups services that extend a parent and share its `dir` by keeping the extends-chain root (shallowest depth, alphabetic tiebreak); reports per-row errors on `GitWorkspaceRow.Err` (goroutines always return nil so siblings aren't cancelled on first error); `CollectDaemons(ctx, cfg, dockerCfg)` shells out `docker ps --format=json` filtered on `devbox.project` + `devbox.daemon.id` labels, parses NDJSON per line, returns `([]statusview.DaemonRow, []error)`; `RenderDaemons(rows)` returns `(string, []error)` (hidden when empty — same treatment as topology).
- `internal/daemon/` — cross-cutting daemon domain utilities: `ResolveContainerName(projectFullName, renderedTemplate)` (prepends `<projectFullName>-`, validates against `^[a-zA-Z0-9_][a-zA-Z0-9_.-]*$` — the authoritative runtime gate on container names), `StandardLabels(projectFullName, daemonID, params)` (emits `--label key=value` argv pairs for the three standard labels), `FilterArgsByLabels(projectFullName, daemonID)` (`--filter label=…` argv for `docker ps`); sentinel errors `ErrContainerNameInvalid` / `ErrDaemonAlreadyRunning` / `ErrDaemonNotRunning`; label-key constants `LabelProject` / `LabelDaemonID` / `LabelDaemonParams`. Consumed by `internal/builtin`, `internal/stack`, `internal/validate/commands`, and `internal/command`.
- `internal/lock/` — project-level file lock with stale-PID detection (Unix-only build tag): `Acquire(path)` uses `flock(LOCK_EX|LOCK_NB)`; on `EWOULDBLOCK` reads the holder PID and calls `Kill(pid, 0)` to reclaim stale locks. Lock files: `.devbox/deploy/deploy.lock` and `.devbox/snapshots/snapshot.lock`. Lock files are intentionally left on disk after `Release` with the last writer's PID; **never** delete a conflict lock file (inode-race invariant, `lock.go:120-125`). `project.go` exposes `AcquireProjectLocks(baseDir) (release func(), err error)` — the **single seam** for project-mutating commands: acquires `deploy.lock` first, `snapshot.lock` second (alphabetical), releases in reverse; on second-lock failure the first is released before returning the error; error message is `"<deploy|snapshot> operation in progress: pid N"` (wraps `lock.HeldError`). Every snapshot mutating subcommand (`create` / `restore` / `rollback` / `remove` / `pack` / `unpack`) and every deploy lifecycle command (`deploy run` / `run` / `stop` / `restart` / `reset`) calls this helper — never `lock.Acquire` directly on the deploy or snapshot lock path. Lifecycle commands acquire the project locks **after** `preflightRun` succeeds (the existing invariant from `deploy.go` is preserved: preflight may invoke user `type: command` checks and must not hold operation locks). Behavior detail: `docs/reference/config/state.md` § Lock file and `docs/reference/config/snapshot.md` § Lock interaction.

## Pipeline / Deploy / Lifecycle

- `internal/pipeline/` — pipeline executor and `PlainReporter`: `Reporter` interface (concurrent-safe; implementations must tolerate sub-step events from N goroutines); `SuspendForExec` / `ResumeAfterExec` wrap every sequential step body so the child writes directly to the host terminal. Action dispatch: `ExecAction` (pure dispatch — no `when:`, no reporter, no check). `RunWithOptions` owns `when:` eval, reporter calls, `check:` orchestration, and `continue_on_error`. Plan-time helpers: `ResolvePhaseSteps`, `PrintPlanTable`, `FormatCondition` / `FormatAction` / `FormatFilesGate`. Plan-time sentinels: `ErrNestedParallel`, `ErrUnnamedSubStep`, `ErrInteractiveInParallel`, `ErrEmptyParallelSteps`, `ErrDuplicateStepName`, `ErrSubStepOverridesInvalid`. State: `Recorder` / `FileRecorder` (mutex-protected). Log files: `OpenPipelineLog` / `OpenSubStepLog`. **Executor step ordering**: `phase-when → step-when → files_gate probe → (journal-skip only when FilesGate == nil) → execute` (gated steps always re-probe). User-facing parallel / `files_gate:` semantics: `docs/reference/config/deploy.md`. `Run` and `ExecStep` are deprecated thin wrappers.
- `internal/deploy/` — deploy plan resolution: `ResolvePlan`, `ResolveServicePlan`, `ResolveServicesPlan`, `ResolveServicesPlanSubset(cfg, reg, deploys, names)` (subset deploy: validates every name has deploy.yml, topo-sorts by `after:`, strips duplicate ImplicitEnvStep, prepends one env step), `FindStep` (updated to read `devbox/services/<name>/deploy.yml`), `TrackedServices`, `LoadTrackedServices` (canonical tracked-service set from the resolved plan; nil registry tolerated — gate validation skipped). `TopoSortByAfter(deploys, services)` performs deploy-time ordering by the `after:` field (distinct from runtime `depends_on:` sort); returns names in dependency-first order with alphabetical tie-break; sentinel errors `ErrDeployCycle`, `ErrDeploySelfReference`, `ErrDeployUnknownAfterRef`. Subpackage `journal/` owns the state-file types and I/O (`ProjectState`, `ServiceState`, `PhaseState`, `StepState`, `Status`, `Load` / `Save` / `Remove` / `RemoveService`, hashing: `ActionHash` / `StepHash` / `ServiceConfigHash` / `ProjectConfigHash`, `Decide` for skip logic, `Recompute` for aggregates). `ProjectState` carries `Pending *PendingApply` (yaml omitempty). `PendingApply{Operations []PendingOp, ConfigHash string, CreatedAt time.Time}`; `PendingOp{Kind PendingKind, Services []string}`. `PendingKind` string enum: `PendingKindUnspecified` (zero), `PendingRestart`, `PendingDeploy`. Helper methods: `(*PendingApply).Find(kind)`, `(*PendingOp).ServiceNames()` (defensive copy). Package-level atomic helpers: `AddPendingOp`, `AddPendingOps` (atomic batch), `ClearPending`, `ClearPendingForKind`, `ClearPendingForServices`, `ClearPendingOps` (atomic batch clear), `ReplaceServiceWithPending` (atomic combine of RemoveService + AddPendingOp). State file: `.devbox/deploy/state.yml` (gitignored). User-facing journal semantics: `docs/reference/config/state.md`.
- `internal/lifecycle/` — lifecycle pipeline execution: `RunPhases`, `RunRun` (git update + phases + show-info), `RunRestart` (stop + run), `RunStop`; `RunContext.ShowInfo` is injected to avoid importing cobra renderers; `RunContext.SkipNotify` is set by `RunRestart` on its inner `RunRun` call so a restart fires at most one desktop notification (restart is not a user-invoked run — spec says zero notifications). `EnsureStopConfig(cfg)` synthesises a stop pipeline with the `_auto_reap_daemons` phase prepended (a nil or stop-less config produces a reap-only pipeline); consumed by `RunStop` to make `lifecycle.yml` optional for stop. Deploy gate is unconditional — no bypass flag (compose errors immediately on undeployed services).
- `internal/reset/` — reset plan resolution (`ResolvePlan`, `FindStep`); mirrors deploy.
- `internal/condition/` — deploy step `when:` evaluator. Two APIs coexist: legacy string-based (`Classify`, `IsRuntime(string)`, `EvalRuntime`, `Kind*` constants) for workflow string `when:`, and typed (`Condition` struct, `EvalRuntimeTyped`) for pipeline `when:`. Template conditions evaluate at plan time in `pipeline/resolve`, not here. Uses hardcoded `sh -c` (POSIX-portable, intentionally not `ShellBin`). **Known wart**: `type: builtin` in `when:` resolves the *predicate* registry here; `type: builtin` in a step body or `check:` resolves the *engine builtin* registry in `internal/builtin` — same keyword, two registries, disambiguated by YAML position. User-facing semantics: `docs/reference/config/conditions.md`.
- `internal/filesgate/` — deploy step file-existence gate (parser-types): `FilesGate`, `State` (`readable` / `missing`), `RequireSpec`, `StepRef` (minimal step-shaped value so validators avoid importing `config.DeployStep`). Subpackage `spec/` does plan-time validation (`Validate`, `ResolveRequireIDs` against command `files:` block). Root package stays import-light. User-facing semantics: `docs/reference/config/deploy.md` § `files_gate:`.

## Builtins / Templates / Git

- `internal/builtin/` — engine builtins usable as step bodies or `check:` actions: `service_dirs_ensure`, `service_configs_copy`, `service_configs_check`, `message`, `confirm`, `docker_remove_project_volumes`, `docker_wait_healthy`, `remove_paths`, plus the daemon-runtime builtins `docker_daemon_start` / `docker_daemon_logs` / `docker_daemon_stop` (registry expansion of `type: daemon` targets these — see `internal/usercommands/`) and `daemons_reap` (auto-injected into `devbox stop` via `lifecycle.EnsureStopConfig` as the synthetic `_auto_reap_daemons` phase). `Builtin` interface threads `ctx` for cancellation; `ExecContext.DockerConfig` (loaded once per top-level invocation, normalised `os.ErrNotExist` → `&DockerConfig{}`) is the single source of docker policy — builtins never call `config.LoadDockerConfig` themselves. `IsInteractive(name)` is the centralised predicate (`confirm`, `docker_daemon_logs`) consumed by both pipeline plan-time (`pipeline/resolve.go` `checkInteractive`) and workflow runtime (`runner_builtin.go` parallel guard).
- `internal/tpl/` — Go template engine: `Render`, `EvalCondition`, `EvalCommandCondition` (render-first). `FuncMap()` returns a per-call shallow clone of a sprout-backed map (`std`, `strings`, `numeric`, `slices`, `maps`, `regexp`, `conversion`, `time`, `filesystem`, `semver`) plus domain helper `appURL`. Hermetic (no env, FS, network, crypto). `commandFuncMap` adds `resolve` / `resolveMap` / `resolveFile` (command scope only).
- `internal/templates/` — template pack helpers shared between render commands and validators (`manifest/`, `packroot/`, `ide/`, `ai/`, `git/`). Manifest schema, `<pack>.local/` overrides, and collision policies (IDE / git: deepest extends wins; AI: shallowest) are documented in `docs/reference/render/index.md`. Each kind exposes `SelectServices`, `ResolveTemplatePack` (implicit-missing returns `found=false, err=nil`; explicit-missing or invalid-name errors), `LoadManifest`, `ValidateManifest`, `ExtendsRoot`. Manifest is **mandatory** — packs without `manifest.yml` return `ErrManifestMissing`. **`TemplateData.Service` vs `Resolved`**: `Service` is the canonical config identity (extends-chain root, used to key raw-config lookups); `Resolved` is the rendering identity (collision winner); `ServiceCfg` is the merged block of `Resolved` (so e.g. `.ServiceCfg.Container` reflects the extender's overlay).
- `internal/git/` — git update probe: `Probe`, `PullFFOnly`, `Decide` (safety matrix: dirty / no-upstream / fetch-failed → warn; behind + auto → pull; behind + prompt + TTY → prompt; behind + check → warn). `Runner` interface for tests.
- `internal/pathsafe/` — filesystem safety: `CheckNoSymlinks`, `ContainedRel` (rejects `..` / `.` escaping), `EnsureRealUnder` (callers must `filepath.EvalSymlinks` before passing). Used by template renderers to prevent escape attacks.

## User Commands

- `internal/usercommands/` — declarative command system facade (re-exports subpackages):
  - `model/` — pure types: `CommandDef`, `CommandFile`, `ParamDef`, `ContextDef`, `FileSpec`, `WorkflowStep` (with optional `Name` for pipeline-side `sub_step_overrides` targeting; `StepName()` returns `Name` when set else `Command`) + `WorkflowParallel`, enums. `CommandType` payload field is `Cmd` (legacy `Run` / `type: command` are strict-decode errors). **`type: daemon`**: declarative sugar for long-running named containers — one block declares `service` / `argv` / `params` plus a `daemon:` sub-block (`container_template`, `on_already_running` ∈ `{error, noop}`, `auto_remove`, `stop_timeout`, `controls`); the source command is consumed by the registry expander (Task 4: `registry/registry.go`) and **dropped** from `byID`, replaced by four virtual `CommandDef`s `<base>.start` / `.logs` / `.stop` / `.restart` (subject to `controls:` subset). `.start/.logs/.stop` are `type: builtin` targeting the daemon-runtime builtins above; `.restart` is `type: workflow` composing `.stop` + `.start`. Each synthetic carries `DerivedFromDaemon = <base>` plus `SourceDaemon *DaemonSpec` (yaml:"-", expansion-time metadata for inspect — never validated, never loaded from YAML). Sentinel errors `ErrDaemonServiceRequired` / `ErrDaemonServiceNotLiteral` / `ErrDaemonContainerTemplateRequired` / `ErrDaemonStopTimeoutInvalid` / `ErrDaemonControlsInvalid` are joined via `errors.Join` by model validation and matched per-field by `validate/commands/daemon.go` to suppress double-emission. Container naming + standard labels (`devbox.project` / `devbox.daemon.id` / `devbox.daemon.params`) live in the top-level `internal/daemon/` package (`ResolveContainerName`, `StandardLabels`, `FilterArgsByLabels`); the regex `^[a-zA-Z0-9_][a-zA-Z0-9_.-]*$` is the authoritative runtime gate on argv → `docker --name`. **`service:` is literal-only in v1** — no `${...}` / `{{...}}` substitution allowed (label stability).

Failure-output dumps print in BOTH modes.

## Notifications

- `internal/notify/` — desktop notifications. `New(cfg) *Notifier` (concrete struct, nil-safe `Notify`) dispatches via an unexported `backend` interface to `noopBackend` or `nativeBackend`. Factory short-circuits to noop on `cfg == nil`, master switch off, empty channels, CI / `DEVBOX_NONINTERACTIVE` / non-TTY (test seam: `isInteractiveForNotify`). `nativeBackend` wraps `osNotify` (test seam, signature `func(title, body string, icon any) error` — `any` mirrors beeep.Notify, lets the embedded `[]byte` icon flow through without temp-file conversion) in a goroutine + non-blocking semaphore + 2s timeout — slot release lives in the inner goroutine so a hung OS notifier can't leak more than one goroutine per process. **Platform split**: `native_other.go` (build `!darwin`) binds `osNotify = beeep.Notify` and sets `beeep.AppName = "Devbox"` in `init()`; `native_darwin.go` (build `darwin`) binds `osNotify = darwinNotify`, which dumps the embedded PNG to a temp file and execs `terminal-notifier -title T -message M -group Devbox -appIcon <png> -contentImage <png>`, falling back to `osascript` (no icon) on missing/failed `terminal-notifier`. Why not beeep on darwin: modern macOS silently ignores `-appIcon` for terminal-notifier, so beeep's bare `-appIcon <icns>` shows terminal-notifier's bundle icon; we add `-contentImage` so the Devbox logo at least renders as a thumbnail in the notification body. `assets/icon.png` is embedded via `//go:embed` (`notificationIcon []byte`) and passed to every notify call. Title format: `✓/✗ Devbox · <project>: <op> succeeded/failed` (project segment dropped when empty); body carries duration plus optional truncated error. `Op` (`OpDeploy` / `OpRun` / `OpCommand`) and `Outcome` (`OutcomeSuccess` / `OutcomeFailure`) enums with `*Unknown` at iota 0. `OutcomeFromErr(err)` is shared by all hookpoints. Errors always logged at debug, never returned. Consumers each declare a local `notifier` interface (one method) for testability — they never depend on a public interface.
- **Notifier hookpoints**: `internal/command/deploy.go` (deployRunCmd), `internal/lifecycle/RunRun`, and `internal/usercommands/runtime/RunCommand`. All three follow the same shape: `start := time.Now()`, `var projectName string`, `userconfig.Load` (parser error → `slog.Warn` + nil cfg, never blocks), `newNotifier(cfg)` (consumer-local seam), defer firing `Notify(context.Background(), ...)` from a named-return `err`. The defer is installed **before** the main config load so a malformed `devbox.yml` still triggers a failure notification. **`SkipNotify` invariants**: `lifecycle.RunContext.SkipNotify` is set by `RunRestart` so the inner `RunRun` does not fire (restart is not a notify event). `runtime.RunContext.SkipNotify` is set transitively at **every** internal invocation site (`runner_workflow.go` sequential + parallel paths, `pipeline/executor.go` action dispatch) — only the top-level `runCommandByID` orchestrator leaves it at zero-value false. The runtime gate is `rc.Cmd.Notify && !rc.SkipNotify`; the cheap-path check installs the defer before any I/O so pre-run failures still notify. Validator emits an info diagnostic for the static-detectable direct-parallel-sub-step case (`internal/validate/commands/notify.go`); the runtime guard handles transitive cases the validator cannot see. `notify: true` on `type: daemon` is a validator error.

## Snapshot

- `internal/snapshot/` — snapshot subsystem (paths, manifest, current pointer, name validation, artifact scan, archive pack/unpack, synthetic-command builder for workflow execution). Helper files split out from the create/restore flows: `devbox_files.go` (`captureDevboxFiles` / `restoreDevboxFiles` with `preserve_keys`-aware strip + merge over `*yaml.Node`, plus the 1 MiB `localYMLMaxBytes` cap on untrusted archive content) and `services_diff.go` (`DiffServices` + exported `FormatServicesDiff` shared by `snapshot inspect`, the restore prompt, and the `snapshot.<name>.services_diff` validator). User-visible schema: `docs/reference/config/snapshot.md`. Load-bearing invariants:
  - **Atomic IO contract** — `manifest.go` / `current.go` write a temp file **in the same directory** as the final file (cross-filesystem `rename` is not atomic), `chmod 0o644`, then `os.Rename`. Mirrors the `journal/state.go` pattern. The pre-restore backup at `.devbox/snapshots/.pre-restore-backup/` follows the same contract and overwrites the previous backup on each restore.
  - **No `schema_version` field** in `Manifest` — per project policy (CLAUDE.md). The manifest has no version gate, no migration path; rename / restructure freely as needed.
  - **Streaming sha256, int64 size, no symlinks** — `scan.go` walks the snapshot directory excluding `manifest.yml` and `devbox/`, computes per-file sha256 via `io.Copy(hasher, f)` (never `io.ReadAll`) so multi-GB dumps don't OOM; rejects any entry with `os.ModeSymlink` set with a clear error — workflows are not allowed to produce symlinks in the snapshot dir.
  - **Render-context propagation point** — snapshot vars (`${snapshot.name|path|description|variant|created_at}`) are threaded from `runtime.RunContext.Render.Snapshot` + `.SnapshotScope` into every sub-step `RenderContext` at `runner_workflow.go:202` and at the two leaf-context constructions in `build_context.go` (lines 32, 56). Without this propagation, snapshot vars in `with:` values of leaf user commands resolve empty. Scope visibility is gated by the `tpl.SnapshotScope` enum (`SnapshotScopeNone` → compile error; `SnapshotScopeCreate` → all keys except `created_at`; `SnapshotScopeRestoreOrRemove` → all keys). The scope check runs in `tpl.RenderCommand` via `validateSnapshotScope` **before** `CompileVarSyntax` so `CompileVarSyntax` stays pure-syntactic with no error path.
  - **Workflow executor reuse** — `exec.go` builds a synthetic `*model.CommandDef{Type: "workflow", Steps: workflow.Steps}` and dispatches via `usercommands.RunCommand`. Snapshot workflows are user-command workflows executed at runtime from a different source file; there is **no** parallel pipeline executor, no shadow scheduler. `BuildSnapshotRunContext` mirrors `BuildRunContext` but injects `Snapshot` + `SnapshotScope` into `Render`.
  - **Live-view observer wiring** — `ExecParams.StepObserverFactory func([]model.WorkflowStep) StepObserverCloser` is invoked **after** `SelectWorkflow` and **after** the pre-workflow confirmation prompt, immediately before dispatching to the runner; this defers any TUI footer until all `huh` prompts are done. `StepObserverCloser` is a local interface embedding `runtime.WorkflowStepObserver` plus `Close()` — the snapshot package owns the `defer obs.Close()`; the CLI never holds the observer past factory construction. The CLI implementation lives in `internal/command/snapshot_liveui.go` (`newSnapshotLiveObserver`); it returns `nil` for non-TTY or `--no-live` so the runner's nil-observer path produces plain output. A depth-counted pause/resume helper on the observer bridges `ui.SetHuhHooks` and `StepIOSuspender` against the same `liveui.LiveLine` so nested suspends from in-step `ConfirmCommand` prompts compose with the step-level suspend window — `live.Pause` / `live.Resume` each fire exactly once per command step.
  - **Archive-safety contract** (`archive.go`, `unpack`):
    1. Path validation runs pre-checks on the raw `tar.Header.Name` (`filepath.IsAbs`, empty / `.` / `..` rejection, `filepath.IsLocal` Go 1.20+), then joins against the staging root, then `pathsafe.ContainedRel` as belt-and-braces. **Never** rely on `filepath.Join` + `ContainedRel` alone — `Join` normalises `..` away before `ContainedRel` ever sees the original header.
    2. Type allowlist: `tar.TypeReg` and `tar.TypeDir`. Go 1.11+ normalises `TypeRegA` ('\x00') to `TypeReg` in `tar.Reader.Next()`, so the allowlist does not need a separate case for it. `TypeSymlink` / `TypeLink` / `TypeChar` / `TypeBlock` / `TypeFifo` / `TypeXGlobalHeader` (and any other typeflag) are rejected with an error naming the entry.
    3. Resource caps: package-level constants `maxUnpackBytes = 50 << 30` (50 GiB) and `maxUnpackFiles = 100_000`; enforced via `io.LimitReader` wrapping the decompressor. Constants, not config — promote to config later if needed.
    4. No follow on existing files: `O_CREATE|O_WRONLY|O_EXCL` refuses to overwrite anything inside the staging tree.
    5. Atomic install with backup rollback: extract into `./snapshots/.unpack-<random>/` (suffix from `mkdirRandom` via `crypto/rand` — blocks TOCTOU symlink pre-creation). If the final `<name>/` already exists, rename it aside as `.backup-<random>/`, rename staging into place, then remove the backup; on second-rename failure restore the backup so the final directory is never left half-installed. Any error during extraction triggers `os.RemoveAll` of the staging dir.
    6. Manifest-driven artifact verification (`VerifyExtractedArtifacts`) runs **after** extraction and **before** the rename-into-place step. Each `manifest.yml` artifact path is validated against the staging root with `filepath.IsLocal` + `pathsafe.ContainedRel` **before** `os.Open` — a maliciously crafted manifest cannot make the verifier read sibling-snapshot or system files; path-safety failure is a hard error, not a warn. Per-artifact sha256 is recomputed via `io.Copy(sha256.New(), f)` (never `io.ReadAll`). Three diagnostic groups (`Missing` / `HashMismatch` / `Extra`) are written to `cmd.ErrOrStderr()` (never `os.Stderr` directly); `Missing` and `HashMismatch` share a single grouped `continue? [y/N]` prompt — declined → cleanup + `UnpackVerifyDeclinedError`. `--no-verify` bypasses verification but always prints the bypass warning to stderr for CI visibility. The CLI summary line is driven by the typed `UnpackResult.Verification` (`VerificationSkipped` / `Clean` / `Warned`) — stderr is never parsed to reconstruct it. Pack writes only `<name>.tar.gz` — no `.sha256` sidecar.
  - **Lock acquisition** — every mutating subcommand (`create`, `restore`, `rollback`, `remove`, `pack`, `unpack`) wraps its `RunE` body with `lock.AcquireProjectLocks(baseDir)` + deferred release. **`pack` is included**: without the lock, packing a snapshot mid-`remove` produces a corrupt or truncated archive.
  - **Synthetic command ID** — internally constructed `CommandDef` uses `ID: "<internal>.snapshot.<scope>"`; suppressed from notifications via `SkipNotify: true` at sub-step level (`runner_workflow.go:229`). Snapshot subcommands emit their own notifications at the command boundary using `notify.OpCommand` with operation labels `"snapshot:create"` / `"snapshot:restore"` / `"snapshot:rollback"`.
- `internal/validate/snapshot/` — static validators for `devbox/snapshot.yml` and on-disk snapshot directories. `All(cfg, snapCfg, snapCfgErr, baseDir, reg, verifyChecksums) []validate.Validator` is the single assembly seam, registered from `internal/command/validate.go` (`buildRegistry`) alongside `env.All` and `checks.AllForStage`. Validators emit `snapshot.*` diagnostics: `config_loadable` (silent on `os.ErrNotExist`), `create_defined` / `restore_defined` (info), `variant_pairing` / `rollback_target_exists` (warn), `<name>.manifest_valid` / `<name>.artifacts_exist` (error), `<name>.checksums` (warn, runs only with `--verify`), `<name>.last_create_failed` (info), and `template_scope` (error — catches `${snapshot.created_at}` in `create:` blocks earlier than the runtime compile check). `devbox validate snapshot [<name>] [--verify]` is the dedicated subcommand (mirrors `validate env` / `validate checks`); `<name>` scoping filters via `MatchScope` to a single snapshot.

## Commands (Cobra)

- `internal/command/` — cobra commands with Fang integration and command groups (root summary, lifecycle, `status` group, mutating-only unified `services`, deploy / reset, docker / compose, docs, validate); thin adapters delegating to domain packages. **`deploy` group**: bare `devbox deploy` (no subcommand) in a TTY opens an interactive menu via huh's NewSelect with options Run / Run service… / Plan / Plan service… / Wizard / Exit. Wizard runs only on fresh projects (missing `local.yml` or empty) when setup questions are present OR port conflicts exist; see `internal/setup/` for wizard orchestration. Non-TTY `devbox deploy` prints help and exits 2. Subcommands `plan`, `run`, `state` are unchanged (non-interactive CLI). `deploy step` is removed entirely — no alias or shim. **`status` group** (`status.go`): default `RunE` renders health + apps + tools + infra + deploy + topology + git + daemons in order; each section also addressable via subcommand (`status apps` / `status tools` / `status infra` / `status deploy [svc]` / `status topology` / `status git` / `status daemons`); default-only `--no-apps` / `--no-tools` / `--no-infra` / `--no-deploy` / `--no-topology` / `--no-git` / `--no-daemons` flags suppress sections; a typed `section` enum + ordered list is the single source of truth for both the default orchestrator order and the `--no-*` flag set. The group does **not** use `PersistentPreRunE` (would replace the root project-resolution hook) — instead, `loadStatusContext(flags)` is called once from each subcommand's `RunE` and loads cfg/journal/tracked/topology on demand. `status deploy <svc>` uses `cobra.MaximumNArgs(1)` and `ValidArgsFunction` routed through `completionConfigPath`. All stdout via `cmd.OutOrStdout()`; warnings via `cmd.ErrOrStderr()`. **Mutating-only unified `services`**: bare `devbox services` opens a single multi-select toggle (TTY only) across every optional service of any type with mandatory items pre-checked/disabled and a `Type` column visible in the table; non-TTY → `ErrInteractiveRequired` sentinel (hint points at `devbox status`); all-mandatory short-circuit before opening the form; `services enable <name>` / `services disable <name>` look up the service by name across all types (no `--type` flag); `enable <mandatory>` warns and exits 0; `disable <mandatory>` errors and exits non-zero; completion via `completeDisabledOptional` / `completeEnabledOptional` filters span the union across all service types. **`devbox tools` is dropped** — no alias, no shim; cobra emits the standard "unknown command" error. `devbox commands [id]` (alias `cmd`) is the single command surface: no positional id → cmdbrowser selector; exact id → direct run; `-i/--inspect <id>` prints the resolved definition (mutually exclusive with `--set` / `--yes`); `--set k=v` (repeatable, `StringArrayVar`) prefills the param form. Orchestrator `runCommandByID(ctx, stdin/stdout/stderr, cfg, reg, projectRoot, id, runOpts)` owns the run pipeline: `reg.Get` → private guard → `resolve.ParamDefaults` (raw-string prefill, distinct from `resolve.Params` which still runs at `BuildRunContext`) → `ui.RunParamForm` → `BuildRunContext` → attach I/O channels → render confirmation title against `rctx.Render` → `ui.ConfirmRun` with `stringifyParams(rctx.Params)` summary → set `rctx.SkipConfirm` to prevent re-prompt → `usercommands.RunCommand`. Test seams: package-level vars `runParamForm` / `confirmRun` / `runUserCommand` / `notifyContext` (`signal.NotifyContext`) — subtests overriding any of these MUST NOT call `t.Parallel()`. The TUI `y` toggle is folded into `runOpts.Yes` at the call site as `yesFlag || skipFromTUI`. `service_plan.go` contains `buildTogglePlan(cfg, registry, svcDeploys, toggles) (TogglePlan, error)` (pure plan builder, no filesystem access), `executeTogglePlan(ctx, deps ExecuteDeps, plan TogglePlan, opts ExecuteOptions) error` (orchestrates before/apply/after steps via stubbed runtimes `RunDeploy`/`RunRestart`/`RunUserCmd`), `runDeployHelper(ctx, cmd, flags, opts DeployOpts) error` (extracted from `deployRunCmd` for reuse by the toggle executor; `DeployOpts.Services []string` supports nil=full-project, one=single-service, N=multi-service batch), `StopService(ctx, StopServiceDeps, name)` / `stopServiceLocked(ctx, StopServiceDeps, name)` (per-service docker-stop bypass for compose-disabled services; locked variant used by reset to avoid double-lock). `TogglePlan{BeforeSteps, ApplySteps []ApplyStep, AfterSteps, Notes}`. `ApplyStep{Kind PendingKind, Services []string}`. **Validate schema-bypass pattern**: `isValidateCommand(cmd)` in `PersistentPreRunE` switches from `project.Resolve` (schema-validating) to `project.Locate` (locate only) so schema errors surface as diagnostics rather than aborting before `RunE`. Apply this pattern to any future diagnostic-mode command. **Exit-code interface**: errors implementing `ExitCode() int` are translated to custom process exit codes in `cmd/devbox/main.go` via `errors.As`; the fang error handler suppresses the "Error:" line for them. `validationFailedError` in `validate.go` is the canonical example. `docs generate --scope cli` works without a project; `--scope all` / `--scope commands` requires a project.
- `internal/command/statusview/` — view-model types owned by the command layer and passed to `internal/ui` renderers (ui must never load YAML or compute hashes): `DeployStatusView`, `DeployStatusRow`, `DeploySummary`, `ConfigDelta` enum (`ok` / `changed` / `missing`), `GitWorkspaceRow`, `DaemonRow`.

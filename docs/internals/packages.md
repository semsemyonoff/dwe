# Internal Package Layout

Internal architecture reference for agents and contributors. This document captures per-package responsibilities, invariants, and cross-package contracts that are not derivable from the code alone (or that would be expensive to re-derive every time). User-facing schema / behavior docs live under [`docs/reference/`](../reference/) — this file is purely about *internal code structure*.

The executable entrypoint lives in `cmd/dwe`; most code is under `internal/`. Tests sit next to code as `*_test.go`; fixtures live in package-local `testdata/`.

## Layout

`internal/` is organized in three layers — see [Dependency Rules](#dependency-rules) for the intended contracts (depguard activation is pending):

```
internal/
  cli/                   cobra command tree, no domain logic
  core/                  domain logic, subclustered
    project/             "what is a DWE project" (config, services, stack)
    execution/           pipeline engine + collaborators
    workflow/            deploy, lifecycle, reset, snapshot, setup
    usercommands/        declarative user-command system
    validate/            static validation framework + subdomains
    docs/                embedded docs subsystem
    ui/                  domain-aware renderers (sink — imported only by cli/)
    notify/              desktop notifications
    bridge/              host bridge for dev containers (daemon, compose overlay, shim assets)
  shared/                leaf infrastructure (docker, git, lock, render, i18n, …)
```

## Dependency Rules

Three layering rules are intended contracts. Activation in `depguard` is deferred until the pre-existing cross-layer imports surfaced during the restructure are resolved (see Task 10 notes in `docs/plans/completed/2026-05-28-internal-restructure-layered.md`). Until then they are enforced by convention and code review only:

- **`shared-no-domain`** — `internal/shared/**` must not import `internal/core/**` or `internal/cli/**`. Shared is leaf infrastructure.
- **`core-no-cli`** — `internal/core/**` must not import `internal/cli/**`. Domain code is ignorant of cobra.
- **`ui-is-sink`** — `internal/core/ui/**` is a sink: no other `internal/core/**` package may import it. Only `internal/cli/**` may pull it in.

Soft (non-enforced) intra-`core/` ordering: `project ← execution ← workflow`. Anything depending on a named user operation lives in `workflow/`; anything that runs a pipeline lives in `execution/`; anything that defines "the project" lives in `project/`.

## CLI (`internal/cli/`)

The cli layer is a thin cobra composition root plus 18 per-domain subpackages. Each subpackage owns one command subtree and exports a single `NewCmd(groupID string, flags *cmdctx.RootFlags) *cobra.Command` entry point that the root composes via `root.AddCommand(<pkg>.NewCmd(group, flags))`; this replaces the old inline `newXxxCmd` declarations and the `addCmd` helper. Three pattern variants exist: (1) **standard** — single-export `NewCmd(groupID, flags)`; (2) **multi-export Go-domain grouping** — `lifecycle/` exposes `NewRunCmd` / `NewStopCmd` / `NewRestartCmd` / `NewResetCmd` because the four commands share a `preflightRun` test seam and the preflight+lock+journal pattern, even though they are independent top-level cobra commands; (3) **special** — `completion/` exposes `AttachInstallUninstall(parent *cobra.Command, flags *cmdctx.RootFlags)` because its subcommands attach to cobra's auto-generated `completion` command (`root.InitDefaultCompletionCmd()` cannot be replaced). `version.NewCmd(groupID string)` is the lone standard-variant that omits `flags` because it needs none.

**Cross-cutting CLI behaviors anchored on `cmdctx.RootFlags`** (details under each subpackage):

- **JSON output mode (`--output json` + `--pretty`)**: Read-only commands emit naked DTOs on stdout; errors go through `cmdctx.WriteError` as a `{"error":{code,message,hint,details}}` envelope on stderr. Use `cmdctx.WriteData[T](flags, cmd, data, textFn)` to dispatch text vs JSON. Construct typed errors with `cmdctx.Err(code, msg)` / `cmdctx.ErrWrap(code, err)` and chain `.WithHint(...)` / `.WithDetail(key, val)`. JSON mode side-effects (set in `PersistentPreRunE`): `NO_COLOR=1`, `SilenceErrors=true`, `SilenceUsage=true`. `runRoot` (no subcommand) routes to `runRootJSON` when JSON is on — never emits brand header or pending banner in that mode. DTO convention: snake_case fields, RFC3339 timestamps, durations in seconds and sizes in bytes as numbers; wrap top-level arrays in a keyed object (`{"apps":[...]}`); `omitempty` on optional inner fields but never on the wrapper key. Stderr in JSON mode is reserved for the error envelope — gate any `warning:` writes behind `flags.Output != "json"`. **Diagnostic commands (`validate` and subdomains) are the exception** to the envelope rule: they always emit diagnostics-as-data on stdout, even at severity=error; exit code conveys severity (0 ok/info, 1 error or warning+`--strict`), and `validationFailedError` carries `ExitCode()` so `main.go` short-circuits the envelope path. TUI-capable commands (`status`, future `cmdbrowser`) force TUI off when `flags.Output == "json"`. Exit codes via `cmdctx.ExitCodeFor(err)`: 0 success, 1 runtime, 2 usage (e.g. `invalid_output`, `--pretty` without `--output json`). Use `cli.NewRootCmdWithFlags()` (not `NewRootCmd()`) when you need the `*RootFlags` pointer; the no-flags constructor exists for the 14+ legacy test call sites only.
- **Display-string localization**: Every call site that renders user-command descriptions, parameter descriptions, group names, or doc-generator section headers to stdout must use the `i18n.Translator` interface (via `rflags.I18n`). Use typed helpers: `store.CommandDescription(locale, id, fallback)`, `store.ParamDescription(locale, id, paramName, fallback)`, `store.GroupTitle/Description(locale, id, fallback)`, `store.T(locale, uiKey, fallback)`. Never read `def.Description` directly in display code. Completion-path safety: `__complete` paths bypass `PersistentPreRunE`, so wrap via `i18n.TranslatorOrNop(rflags.I18n)`. Storage/hashing sites (journal, deploy steps, phase definitions) stay English — never introduce locale to `internal/core/workflow/deploy/journal/hash.go` or any persistence layer.

- **Container command policy (host bridge)**: when `DWE_INVOKED_FROM=container` (force-set by the bridge daemon — design D7; client-sent values are stripped, so not spoofable from a container), only an **allowlist, default-deny** subset of the CLI is reachable: the `commands` subtree, `status`, `info`, `logs`, `docs`, `prompt`, `version`, `help`, `vars`, bare `dwe`, cobra's `__complete`/`__completeNoDesc`, plus the nested exceptions `bridge status` and `render config` (the other `render` subcommands — env/ide/ai/git — stay host-only). `vars`'s read subcommands (`get`/`list`/`inspect`) are freely reachable; `vars set` is reachable but **deny-by-default RUNTIME-gated** by `bridge.vars_writable` inside `cli/vars/set.go` (the allowlist is prefix-wide and cannot see the var arg). `render config` rejects `--harvest` in a container (host-only state mutation). `validate` and the user-facing `completion` generator are deliberately host-only (the hidden `__complete` machinery stays allowed so a completion script baked into an image degrades silently instead of injecting a policy error into the shell). Everything else — including every NEW top-level command, until explicitly added to `bridgeAllowedTopLevel` in `internal/cli/bridgepolicy.go` — fails with typed `cmdctx.Err("bridge_command_blocked")` (run-on-host hint; stop/restart/reset additionally carry the suicide explanation). The gate runs inside the EXISTING root `PersistentPreRunE` (step 2b — after output-mode validation, before project resolution); `applyBridgeContainerVisibility` at the end of `NewRootCmdWithFlags` hides blocked commands from help and completion (a parent stays visible when any descendant is allowed — the `bridge` → `bridge status` shape). The policy is inherited by nested invocations (`type: dwe` user commands keep the env). Related fallback: bare `dwe commands`/`dwe cmd` (non-tty stdin) and bare `dwe docs` (non-tty stdout) OR truthy `DWE_NONINTERACTIVE` (the shared `cmdctx.NonInteractiveEnv()` `{"1","true"}` set) print their `list` output instead of the TUI browser. **Inside the allowlisted `commands` subtree there is a second, per-command gate**: user commands are container-reachable only when opted in via a `bridge:` block (`model.BridgeDef` — command-level or file `group:` header, field-wise merge, opt-in default), resolved into `CommandDef.BridgeHidden` by `registry.ApplyVisibility` and enforced by `registry.list` (all listing/completion variants — including the inspect escape hatch), the tree walker in `cli/command/list.go`, and `bridgeGuard` in `cli/command/bridgegate.go` (typed `command_not_bridged` on direct invocation AND inspect). The workflow runner and pipeline engine deliberately never consult `BridgeHidden` — a bridged workflow executes non-bridged sub-commands host-side. See § Core — User Commands. User-visible policy table: `docs/reference/concepts/bridge.md` § Command policy inside containers.

**Naming rationale**: `docker/` and `compose/` are kept as **separate packages** rather than collapsed into one `docker/` package exporting `NewDockerCmd`/`NewComposeCmd`; the latter would force the stuttering `docker.NewDockerCmd` (textbook Go anti-pattern of the `http.HTTPClient` shape). The file hosting `NewCmd` inside each subpackage is named after the package (`lifecycle/lifecycle.go`, `snapshot/snapshot.go`, `deploy/deploy.go`, `render/render.go`, …) to avoid overloading `root.go` — `internal/cli/root.go` is THE root. Where a subpackage name collides with an import (`internal/shared/version`, `internal/shared/prompt`, `internal/shared/docker`, `internal/core/workflow/snapshot`, `internal/core/workflow/lifecycle`, `internal/core/validate`, `internal/core/docs`), callers and the colliding import alias as `versioninfo` / `promptpkg` / `dockerpkg` / `snapshotpkg` / `lifecyclepkg` / aliased `cmdValidate` / `cmdDocs` etc.

**Cross-sibling import policy**: siblings communicate via `cli/cmdctx/` and never cross-import each other. Two pre-existing exceptions are documented and out of scope to fix here: `cli/service/` → `cli/deploy.RunHelper` (service-toggle drives deploys after enable/disable; resolved by lifting `RunHelper` into `core/workflow/deploy/` in a follow-up), and `cli/lifecycle/{run,restart}.go` → `cli/info.Run` (the `ShowInfo` lifecycle callback; the import became a sibling import once `lifecycle/` was extracted).

**Section preamble — cross-cutting behaviors anchored in `root.go`**: **Validate schema-bypass pattern** — `isValidateCommand(cmd)` in `PersistentPreRunE` switches from `project.Resolve` (schema-validating) to `project.Locate` (locate only) so schema errors surface as diagnostics rather than aborting before `RunE`; apply this pattern to any future diagnostic-mode command. **Exit-code interface** — errors implementing `ExitCode() int` are translated to custom process exit codes in `cmd/dwe/main.go` via `errors.As`; the fang error handler suppresses the "Error:" line for them. `validationFailedError` in `cli/validate/validate.go` is the canonical example.

- `internal/cli/` — composition root (`root.go`, ~334 LoC): `NewRootCmd`, `initRootCmd`, `PersistentPreRunE`, `runRoot`, `applyStyles`, `resolveLocalization`, `allowedWithoutProject`, `isValidateCommand`. No inline command builders; no `addCmd` helper. Companions: `root_test.go`, `root_resolver_test.go`, `fang_integration_test.go`.
- `internal/cli/cmdctx/` — typed `RootFlags` bundle threaded into every RunE callback (cfg path, language, accent overrides, project-root resolver, etc.) plus flag-helper utilities (e.g. `completionConfigPath` used by every `ValidArgsFunction` callback to safely resolve project state under cobra's hidden `__complete` path, which bypasses `PersistentPreRunE`). This is the single seam through which siblings exchange context. Shared cross-sibling helpers exported here: `WriteData[T]` / `WriteJSON[T]` (text-vs-JSON dispatch; `WriteJSON` is `WriteData` with an empty text renderer for JSON-only payloads), `WriteError` / `Err` / `ErrWrap` (typed-error envelope), `AcquireProjectLocksOrReport` (the project-lock acquire-and-report wrapper — see § snapshot Lock acquisition), and `WarnSilentLog` (the shared pipeline-`ErrSilent` "Full output saved to" log-tail hint used by `deploy run` / `reset run` — the one cmdctx helper that imports `core/execution/pipeline`).
- `internal/cli/info/` — `dwe info` renderer. `NewCmd(groupID, flags)` plus `Run(ctx, …)` (exported because `cli/lifecycle/{run,restart}.go` consume it for the `ShowInfo` lifecycle callback).
- `internal/cli/version/` — `dwe version`. `NewCmd(groupID string)` — the lone flagless variant.
- `internal/cli/prompt/` — `dwe prompt` cobra command for `--help` discoverability only. The fast path bypasses cobra entirely via `cmd/dwe/main.go`'s `isPromptInvocation` dispatch into `shared/prompt.Run` (lipgloss would auto-downgrade to no-color when stdout is piped). `NewCmd` `RunE` is unreachable in normal startup.
- `internal/cli/shell/` — `dwe shell` plus the misnamed-from-prior-refactor `exec.go` (was `service_cli.go`) carrying `resolveShellOptions`, `serviceContainerState`, `dockerExecCLI`, `composeRunCLI`, `runInteractive`, `errContainerNotFound`. Watch for the `os/user` import — package name `shell` does not collide. `NewCmd(groupID, flags)`. **Container detection is label-based, not name-guessed:** `serviceContainerState(projectName, service, processEnv, dockerBin)` delegates to the shared `docker.ServiceContainerName` (the one home for label-based container lookup; label-key consts `docker.ComposeProjectLabel` / `ComposeServiceLabel` / `ComposeOneoffLabel` are also reused by `stack.ServiceRunning` and `env` port-conflict). `service` is **svc.Container** — the value compose stamps into `com.docker.compose.service` and the service key dwe uses everywhere (topology, stop, logs); it defaults to the folder key but may be overridden in `service.yml`, so `resolveShellTarget` returns it and the probe/exec/run paths target it (NOT the user-facing service name). `serviceContainerState` runs two passes (running, then `--all`) to distinguish "stopped" from "absent"; each delegates to `docker.ServiceContainerName`, which probes `docker ps … --format '{{.Names}}'` (a single portable field — avoids `.State` and `--format json`, whose shapes differ between docker and podman) and **prefers a long-lived service container over an ephemeral one-off** by first filtering `com.docker.compose.oneoff=False`, falling back to the unfiltered query only when that finds nothing (so a one-off `compose run` container — e.g. a concurrent `dwe shell --mode run` session — is never exec'd into when a real service container exists, while compose backends that omit the one-off label still resolve via the fallback). Empty stdout from a zero-exit `docker ps` unambiguously means "no match" and a real Docker error exits non-zero and is surfaced, so a probe hiccup can never be mistaken for absence (which would start a duplicate). The state probe is the injectable `containerProbeFunc` seam (`func(service) (name, status, err)`); `errContainerNotFound` (no labelled container) drives auto-mode's fall-through to `docker compose run`. **One-shot mode** (`-c, --command "<cmd>"`): parallel dispatch path via `dispatchShell` (called from `RunE`) → branches on `shellCLIFlags.command`; non-empty routes to `runOneShotCommand` → `dockerExecOneShot` / `composeRunOneShot` (no info banner, no compose-run hardcoded `-it`); empty routes to existing interactive `runServicesCLI`. TTY auto-detect via package-level `ttyDetector` seam (defaults to `widgets.IsInteractiveFn`, swapped in tests); `dockerExecTTYFlags()` returns `["-i","-t"]` or `["-i"]`; `composeRunTTYFlags()` returns `["-i"]` or `["-i","-T"]` (compose run allocates TTY by default — `-T` disables). Child exit codes flow through cobra/fang via `*shellCommandExitError{code, underlying}` (extracts from `*exec.ExitError` in shared `wrapExitError`); `cmd/dwe/main.go:75-81` extracts `interface{ ExitCode() int }` and calls `os.Exit`, and `errHandler` at main.go:40-44 suppresses Fang's `Error:` banner for `ExitCode`-bearing errors so the user sees only the child's stdout/stderr. The global root `-c` shorthand was dropped (only `--config` long form remains) to free `-c` for `shell`.
- `internal/cli/logs/` — `dwe logs <service>` for streaming container logs by service name (canonical entry point — use it instead of `docker logs <container>` directly, since it handles container-name resolution via `daemon.ResolveContainerName`). Files: `logs.go` (`NewCmd` + `ResolveLogsTarget` exported helper + `runLogs` orchestrator), `parse.go` (NDJSON line parser for JSON mode). Flags: `--tail N` (default 50, 0 = all), `--since DUR|TS`, `-f/--follow`, plus the global `--output text|json` (NDJSON in JSON mode — one `{"ts","stream","msg"}` object per line). Read-only: no lock, no preflight. `ValidArgsFunction` uses `cmdctx.ServiceNameCompletion(flags)` so completion lists current project services. `NewCmd(groupID, flags)`.
- `internal/cli/status/` — `dwe status` group. `NewCmd(groupID, flags)` composes a default `RunE` rendering health + apps + tools + infra + deploy + topology + git + daemons in order; each section also addressable via subcommand (`status apps` / `tools` / `infra` / `deploy [svc]` / `topology` / `git` / `daemons`, one file per subcommand). Default-only `--no-apps` / `--no-tools` / `--no-infra` / `--no-deploy` / `--no-topology` / `--no-git` / `--no-daemons` flags suppress sections; a typed `section` enum + ordered list is the single source of truth for both the default orchestrator order and the `--no-*` flag set. The group does **not** use `PersistentPreRunE` (would replace the root project-resolution hook); instead `loadStatusContext(flags)` runs from each subcommand's `RunE` to load cfg/journal/tracked/topology on demand. `status deploy <svc>` uses `cobra.MaximumNArgs(1)` and `ValidArgsFunction` routed through `completionConfigPath` (`trackedServiceCompletion` lives in `deploy.go` since it is the sole caller). All stdout via `cmd.OutOrStdout()`; warnings via `cmd.ErrOrStderr()`. Test seams: `isTerminalFn`, `runStatusTUIFn`.
- `internal/cli/snapshot/` — `dwe snapshot` tree (`list`, `current`, `inspect`, `create`, `restore`, `remove`, `pack`, `unpack`), one file per subcommand. `NewCmd(groupID, flags)` plus shared helpers in `snapshot.go` and `liveui.go` (the `newSnapshotLiveObserver` factory wiring `liveui.LiveLine` into the workflow runner's `StepObserverFactory`). `internal/core/workflow/snapshot` is imported as `snapshotpkg` to avoid collision with the cli package name.
- `internal/cli/validate/` — `dwe validate`. Single-file subtree. `NewCmd(groupID, flags)` plus internal helpers `loadForValidate`, `errPartialLoad`, `validationFailedError` (the canonical `ExitCode()`-bearing error). `docs generate --scope cli` works without a project, but `validate` requires either `Resolve` or `Locate` depending on `isValidateCommand` routing.
- `internal/cli/command/` — `dwe commands [id]` (alias `cmd`), the single user-command surface. No positional id → cmdbrowser selector; exact id → direct run; `-i/--inspect <id>` prints the resolved definition (mutually exclusive with `--set` / `--yes`); `--set k=v` (repeatable, `StringArrayVar`) prefills the param form. Files: `command.go` (NewCmd), `runbyid.go` (orchestrator — see below), `list.go` (browser/tree rendering, `selectorTitle`), `inspect.go` (`printInspect`/`printInspectAt`/`inspectStepDescription`), `completion.go` (`registryIDCompletion`), `daemonset.go` (`daemonSetCompletion` for `command --set` flag completion). Orchestrator `runCommandByID(ctx, stdin/stdout/stderr, cfg, reg, projectRoot, id, runOpts)` owns the run pipeline: `reg.Get` → private guard → `resolve.ParamDefaults` (raw-string prefill, distinct from `resolve.Params` which still runs at `BuildRunContext`) → `resolve.Options` (membership validation for `--set` values) → `buildAskFields + ask.Run` (huh form for interactive prompting; skipped when all required params pre-satisfied or non-interactive) → `BuildRunContext` → attach I/O channels → render confirmation title against `rctx.Render` → `widgets.ConfirmRun` with `stringifyParams(rctx.Params)` summary → set `rctx.SkipConfirm` to prevent re-prompt → `usercommands.RunCommand`. Test seams: package-level vars `runAsk` / `confirmRun` / `runUserCommand` / `notifyContext` (`signal.NotifyContext`) — subtests overriding any of these MUST NOT call `t.Parallel()`. The TUI `y` toggle is folded into `runOpts.Yes` at the call site as `yesFlag || skipFromTUI`. `runbyid.go` (not `run.go`) disambiguates from `lifecycle/run.go`.
- `internal/cli/docs/` — `dwe docs` tree. Files: `docs.go` (NewCmd + TUI launch + `docsSelectorTitle`), `generate.go` (the huge `newDocsGenerateCmd` block: `runDocsGenerate`, `validateDocsFlags`, `resolveFormats`, `resolveScopes`, `genCLIDocs`, `genHiddenCLI*`, `walkAllCommands`, `genCLIIndex`, `writeCLIIndexEntries`, `genRegistryDocs`, `genRegistryMarkdown`, `writeCommandMarkdown`, `genCommandsIndex`, `genTopLevelIndex`, `mmdcAvailable`), `cache.go`, `export.go`, `list.go`, `search.go`, `show.go`, `llmstxt.go` (newDocsLlmsTxtCmd + runDocsLlmsTxt for `dwe docs llms-txt`), `llmstxt_collectors.go` (project-data collectors — `collectServiceSummaries`, `collectCommandSummaries`, `collectInfoSummary` — kept in cli layer so `internal/core/docs/llmstxt/` stays pure-function and config-import-free). `internal/core/docs` aliased as `coredocs` in files that need both names. `docs generate --scope cli` works without a project; `--scope all` / `--scope commands` requires a project. Docs subsystem is read-only — never calls `lock.AcquireProjectLocks` and never runs preflight; resolves locale **directly** via `i18n.ResolveLocale(flagLang, cfgLang, sysLang)` (NOT `rflags.Locale` — clamped to YAML store, wrong namespace for markdown).
- `internal/cli/completion/` — install/uninstall subcommands attached to cobra's auto-generated `completion` parent via `AttachInstallUninstall(parent, flags)`. Files: `completion.go` (Attach + shared `completionExitError`, `isSupportedShell`, `supportedShells`, `ErrUnsupportedShell`), `install.go` (`newInstallCompletionCmd` + path/profile/atomic-write helpers + seam vars `resolvePowerShellProfile`/`completionHomeDir`/`completionReadFile`), `uninstall.go` (`newUninstallCompletionCmd` + `runUninstall` + `emitZshFpathHint`). In `root.go` the wiring is `root.InitDefaultCompletionCmd()` → `root.Find(["completion"])` → set `GroupID = groupAdvanced` → `completion.AttachInstallUninstall(completionCmd, flags)`.
- `internal/cli/docker/` — `dwe docker` passthrough (351 LoC of subprocess + arg-policy plumbing). `NewCmd(groupID, flags)`. `internal/shared/docker` aliased as `dockerpkg` inside the file because the package itself is now named `docker`.
- `internal/cli/compose/` — `dwe compose` passthrough. `NewCmd(groupID, flags)`. Split from `docker/` to avoid the stuttering `docker.NewComposeCmd` (see Naming rationale).
- `internal/cli/deploy/` — `dwe deploy` tree. `NewCmd(groupID, flags)` exposed; `deploy.go` hosts the entry point (renamed from `root.go` for symmetry). Bare `dwe deploy` (no subcommand) in a TTY opens an interactive menu via huh's `NewSelect` with options Run / Run service… / Plan / Plan service… / Wizard / Exit. Wizard runs only on fresh projects (missing `local.yml` or empty) when setup questions are present OR port conflicts exist; orchestration in `internal/core/workflow/setup/`. Non-TTY `dwe deploy` prints help and exits 2. Subcommands `plan`, `run`, `state` are non-interactive CLI. `deploy step` is removed entirely — no alias or shim. `cli/deploy/menu.go` uses package-private `runDeployRunFn`/`runDeployPlanFn` rather than dispatching into `cli/lifecycle/`. `RunHelper` is consumed by `cli/service/` (documented pre-existing cross-import).
- `internal/cli/lifecycle/` — multi-export Go-domain grouping for `run`/`stop`/`restart`/`reset`. Files: `lifecycle.go` (package preamble + `var preflightRun = preflight.Run` test seam — **only `reset.go` uses the seam**; `stop.go` calls `preflight.Run` directly and `run.go`/`restart.go` route through `deploy.RunHelper`), `run.go` / `stop.go` / `restart.go` / `reset.go`. Exports: `NewRunCmd`, `NewStopCmd`, `NewRestartCmd`, `NewResetCmd` (each `(groupID, flags)`). `stop.go` also defines `StopService(ctx, StopServiceDeps, name)` / `stopServiceLocked(ctx, StopServiceDeps, name)` (per-service docker-stop bypass for `dwe stop <name>` — compose overlay is filtered out for disabled services, so direct `docker stop` is required; locked variant for callers that already hold project locks). Per-service reset does NOT use `stopServiceLocked` — it drives stop+rm through the synthetic-pipeline `docker_stop_remove_container` builtin instead. `restart.go` also defines `RestartService(ctx context.Context, baseDir string, cfg *config.DweConfig, name string, out io.Writer) error` (per-service docker-restart bypass for `dwe restart <name>` — no preflight, no project locks; `docker.ErrNoSuchContainer` maps to a user-actionable "run `dwe deploy run` first" error; `var restartContainerFn = docker.RestartContainer` seam for test injection). Lifecycle commands acquire project locks **after** preflight succeeds so `type: command` checks do not run under operation locks. `internal/core/workflow/lifecycle` aliased as `lifecyclepkg` in `run.go`/`restart.go`/`stop.go`. `info.Run` consumed via the sibling import documented above. **`reset --clear-generated`**: clears the `generatedstore` (scoped by `--service` via `ClearService` / all via `ClearAll` + `Save`) **only after the FULL reset succeeds — including the post-pipeline journal cleanup** (`journal.Remove` for full reset / `journal.ReplaceServiceWithPending` per-service), never merely after `RunWithOptions` returns; a pipeline OR journal-mutation failure leaves the store untouched (else a deployed-journal + empty-store mismatch would make the run gate trust a service with no secrets). Full reset has NO command-level confirm to hook (confirmation is a pipeline step), so the interactive "also clear N generated values?" prompt is decided at the command level up front (default No); per-service reuses the existing `resetConfirmFn` seam. Default behavior unchanged — store preserved.
- `internal/cli/render/` — `dwe render` tree (env / ide / ai / git / **config**). `NewCmd(groupID, flags)`; entry point in `render.go` (renamed from `root.go` for symmetry). `config.go` adds `dwe render config [service]` (optional positional → one service; none → all eligible **app** services via `DeployOrder(cfg, []string{"app"})` — config rendering is app-only, only apps declare `dir`/`render`/`generated`) driving `templates/config.RenderConfigs`; `--harvest` switches to a **harvest-only** pass (`HarvestGenerated`, NO render) for bootstrapping an already-committed value into the store. The default render path is read-only wrt locks (no preflight, no project locks); `--harvest` mutates the shared store, so it acquires project locks first (via `cmdctx.AcquireProjectLocksOrReport`, mirroring the deploy harvest builtin and `reset --clear-generated`) before loading the store. Resolves the store path from baseDir + `generatedstore.DefaultRelPath`; cli is the single stdout writer. Opt-in — no `dwe init` scaffold wiring (matches the user-authored copy mechanism it replaces). **Container reachability**: `render config` is a nested bridge exception (so a container can regenerate config after `vars set`); the other render subcommands (env/ide/ai/git) stay host-only. Because `--harvest` MUTATES host `.dwe/generated.yml` (a write path that bypasses `bridge.vars_writable`), `config.go` rejects `--harvest` with typed `render_harvest_host_only` when `bridgeclient.InContainer()` — only the read-only render is container-reachable.

- `internal/core/project/project/` — project discovery: `Locate(flag)` (upward walk from cwd; explicit mode when flag non-empty), `Resolve(flag)` (Locate + validates required project config fields); `ErrNotFound` sentinel; constant `ConfigFilename`.
- `internal/core/project/config/` — `DweConfig` and all YAML loaders (`LoadConfig`, `LoadServices`, `LoadServiceFolder`, `LoadDeployConfig`, `LoadDockerConfig`, `LoadLifecycleConfig`, `LoadInfoConfig`, `LoadStylesConfig`); merged-config types (services, render policy, parallel groups, actions, file gates, `DeployStep.SubStepOverrides` / `SubStepOverride`, `StatusColumn` for custom per-row columns). **Unified services schema.** All service-shaped entities (apps, tools, infra) live under `workspace/services/`, one folder per service. `service.yml` is the per-folder declaration file; folder name = map key (no `name:` field inside the file). Services are discriminated by `type:` (`app` | `tool` | `infra`). `ServiceType` is a named string type with typed constants `ServiceTypeApp` / `ServiceTypeTool` / `ServiceTypeInfra`, predicate methods `IsApp()` / `IsTool()` / `IsInfra()` on both `ServiceType` and `ServiceConfig`, sentinels `ErrServiceTypeMissing` / `ErrServiceTypeUnknown` / `ErrServiceFieldNotAllowed` / `ErrServiceExtendsCrossType` / `ErrServicePortsShape` / `ErrServiceHostsShape` / `ErrServicePortOutOfRange` / `ErrDependsOnTool`, and an unexported `allowedFieldsFor(t)` field allowlist consumed by both loader (strict-decode) and validators (updated to include `on_enable`, `on_disable`, `notes` for all toggleable service types). Each `ServiceConfig` owns `Ports map[string]ServicePortSpec` and `Hosts map[string]string` (always maps — no scalar shorthand). `ServicePortSpec{Port int, Scheme string}` accepts two YAML shapes via a custom `UnmarshalYAML`: bare-int shorthand (`http: 5173` → `{Port: 5173, Scheme: ""}`) or rich form (`http: {port: 5173, scheme: https}`). The mapping branch enforces its own strictness (unknown fields rejected, `port:` required at service.yml decode, null `port:` rejected) because `yaml.Node.Decode` does NOT inherit a parent decoder's `KnownFields(true)`. Helpers: `Port(name) int` returns `Ports[name].Port` (zero for missing); `PortScheme(name) string` returns the per-port override (empty when not set); `EffectiveScheme(portName, runtimeUseHTTPS) string` walks the precedence chain (per-port `Scheme` → `Info.Scheme` → runtime fallback → `"http"`/`"https"`) and is the canonical way to resolve a URL scheme for a service port; `PortNumbers() map[string]int` flattens to a scheme-less view for downstream consumers that don't carry scheme metadata (status rows, conflict probes). `ServiceInfoBlock.Scheme string` is the service-wide scheme override consulted by `EffectiveScheme`. For reverse-proxy URLs (`auto-urls` `port_via`), the **routed** service's `Info.Scheme` participates — it both wins the URL scheme and pins which proxy listener key (`http` vs `https`) gets looked up, via `resolveProxyTarget` in `internal/core/ui/render/info_auto_urls.go` / `resolveProxyTargetData` in `internal/cli/info/info_data.go`. The **proxy's own** `Info.Scheme` is deliberately ignored (it would otherwise leak the proxy's dashboard scheme onto every routed service); only a per-port override on the proxy's chosen listener plus `runtime.use_https` participate as fallbacks. `Host(name) string` returns the hostname for missing keys. `ServiceConfig` also has `OnEnable *ServiceToggleHooks`, `OnDisable *ServiceToggleHooks`, `Notes *ServiceNotes` fields. `ServiceToggleHooks{Requires ToggleRequires, Before []string, After []string}`; `ToggleRequires` is a string enum with zero-value `RequiresUnspecified`, values `RequiresNone`/`RequiresRestart`/`RequiresDeploy`. The dot-path namespace is `services.<name>.ports.<port-name>` (always a bare int, even when the typed `ServicePortSpec` carries a scheme override — preserves the contract for env-export rules like `from: services.main.ports.http`) and `services.<name>.hosts.<host-name>`. Per-port scheme overrides are surfaced as a sibling dot-path under `services.<name>.port_schemes.<port-name>` (string), emitted by `injectServicesIntoRaw` only for services that actually use the feature. **`LoadConfig` sequencing**: load services via `LoadServices(baseDir)` → `validateServicesOverlay` per layer (rejects any key other than `enabled:` / `ports:` / `hosts:` under `services.<name>` with per-layer source attribution; per-port value is either a bare int in 1..65535 or a rich-form mapping `{port?, scheme?}` — at the overlay layer, `port` is OPTIONAL so a developer can override scheme alone for an inherited port, but at least one of `port`/`scheme` must be present; hosts map → string) → merge 3-layer raw YAML (workspace.yml → defaults.yml → local.yml) → resolve `Enabled` and **deep-merge** per-developer port/host overrides into `cfg.Services[name].Ports` / `.Hosts` by entry name (`applyOverlayPorts` / `applyOverlayHosts` — declared entries the overlay does not mention are preserved; new entries are added) → `injectServicesIntoRaw` (mirrors every resolved field including post-overlay `ports` / `hosts` so `${services.X.ports.Y}` resolves through `Raw`). `LoadServiceFolder(baseDir, name)` reads `workspace/services/<name>/service.yml` with strict decode; `LoadServices(baseDir)` enumerates `workspace/services/*/`, calls `LoadServiceFolder` per folder, applies cross-service `extends:` toposort + inheritance merge, and collects all folder errors via `errors.Join`. Missing `workspace/services/` directory → empty map (no error). **Per-developer port/host overrides are a load-bearing DWE feature** — developers must be able to remap a clashing port or change a `*.local` hostname in `local.yml` without touching the shared service folders, and the resolved values must stay visible in `dwe status`. Do not narrow the overlay allowlist back to `enabled:` only, and do not remove the HOSTS / PORTS columns from `render.ServicesTable`. `RuntimeConfig` is now `{ UseHTTPS, SPX }`. `extends:` resolution uses `slices.Clone` / `maps.Clone` defensive copies so child mutation never corrupts parent. Per-type accessors `(c *DweConfig).AppServices()` / `ToolServices()` / `InfraServices()` (each filters by type); `ComposeFiles()` / `ComposeFilesAll()` emit `base → tools (sorted) → infra (sorted) → apps (sorted) → c.Compose.Extra` — order is part of the public surface, locked. Per-service `compose.extra` overlays from `workspace/local.yml` (`ServiceConfig.LocalComposeExtra`, `yaml:"-"`) are emitted **inside the same `all || svc.Enabled` gate** as `svc.Compose`, immediately after the service's own compose files; project-wide `compose.extra` (`ComposeConfig.Extra`, `yaml:"-"`) is appended **strictly last** to `composeFiles()` output and is unconditional. Both fields are populated by post-decode injection from the local.yml raw map only — never decoded directly from any YAML; injection runs BEFORE `ResolveServiceExtends`, which copies `LocalComposeExtra` parent→child when the child has none. Pre-merge validators `validateOverlayCompose` / `validateLocalCompose` / `validateNonLocalCompose` gate the schema to local.yml only (non-local layers see a hard error pointing at `workspace/local.yml`). Path safety after injection runs four ordered checks via `validateComposeExtraPathSafety` / `validateComposeExtraPath`: (1) reject `filepath.IsAbs(p)` — absolute paths bypass containment since `filepath.Join(baseDir, "/x")` returns `/"/x"`; (2) reject `filepath.Clean(p) != p` — unclean paths such as `link/../evil.yml` erase symlink components before `filepath.Join`, defeating the symlink check in step 4; (3) `pathsafe.ContainedRel(baseDir, abs)` — rejects `..`-escapes; (4) `pathsafe.CheckNoSymlinks(baseDir, abs, "compose overlay")` — rejects symlink components in the resolved path. Existence (`os.Stat`) is step 5 but is skipped for disabled-service overlays (`validateComposeExtraPathSafety` without Stat) because disabled services are excluded from `ComposeFiles()` while structural checks 1–4 still run since `ComposeFilesAll()` includes their paths. Paths are stored as-written (relative); Docker Compose resolves them via `cmd.Dir = BaseDir`. User-facing details: `docs/reference/config/workspace.md` § Compose overlays. **Always** access binaries via `config.DweBin`/`DockerBin`/`ShellBin`/`GitBin` (nil-safe), never `cfg.Binaries.*`. **Deploy config loaders** were split by context: `LoadProjectDeployConfig(path)` (project-wide `workspace/deploy.yml` — `after:` is not a field of `ProjectDeployConfig`, so strict `KnownFields(true)` decode rejects it); `LoadServiceDeployConfig(path)` (per-service deploy — permits `after:`); `LoadServiceDeployConfigs(baseDir, services)` (bulk loader for all services); `ParseDeployConfigForValidation(path)` (parse-only for validators, permits `after:` so validators can inspect and emit per-file diagnostics). `LoadResetConfig` (project-wide) rejects `after:`. Additional loaders: `LoadSnapshotConfig(baseDir)` (strict-decode, `KnownFields(true)`; returns `(nil, nil)` cleanly when `workspace/snapshot.yml` is absent — caller decides whether absence is fatal per subcommand); `LoadValidateConfig(baseDir)` (strict-decode; single parse point — callers thread the result into `validate.Context` rather than re-parsing); `LoadUIConfig(cfg)` / `UIConfig` (loaded leniently from the `ui:` block in `workspace.yml`; pointer fields distinguish absent from explicit zero). **Strict root + `vars:` sandbox.** The merged 3-layer root is strict: `LoadConfig` enforces a single source-of-truth allowlist `allowedRootKeys` (`{schema_version, project, runtime, state, exports, compose, ui, docs, services, vars, update}`) — any other top-level key is a **hard load-time error** with a `vars:`-hint message naming the offending layer file. The check iterates **per layer** (so the error attributes the source file) and runs **after** the dedicated `binaries:`/`tools:` legacy-key rejections (which keep their own migration messages) and **before** the `__configPath` / `injectServicesIntoRaw` injections. Arbitrary free-form project values have exactly one legal home: the `Vars map[string]any` (`yaml:"vars"`) block — strict at the root (it's an allowed key) but **unvalidated and arbitrarily nestable inside**; references resolve through `Raw` dot-paths unchanged (`${vars.db.password}`, `from: vars.db.user`). `schema_version` is tolerated-but-uninterpreted forward-compat metadata. **Formalized top-level `update:` block.** `Update *UpdateConfig{ Mode string }` (`yaml:"update"`) is the project self-update policy — 3-layer merged (scalar `mode` last-layer-wins), so the author sets policy in `workspace.yml` and a dev overrides in `local.yml`. Pointer so absent (nil → off) is distinct from present-empty (→ on). `UpdateConfig.EffectiveMode()`: nil → `"off"`; empty mode → `"on"`; else the value. `LoadConfig` value-validates `mode ∈ {on, off}` at load time (the allowlist only checks key *names*), mirrored as a `dwe validate` diagnostic. This **replaced** the old `lifecycle.yml` `run.update` flag (removed — enabling update no longer blanks the lifecycle `run` phases); the run consumer reads `cfg.Update.EffectiveMode()`. **Top-level `bridge:` block (`BridgeConfig{VarsWritable []string}`, `yaml:"bridge"`).** `"bridge"` is in `allowedRootKeys`; 3-layer merged; the deny-by-default container-write allowlist behind `dwe vars set`. Nil-safe accessor `BridgeVarsWritable(cfg) []string` (nil/empty → no container writes). The matcher `VarsWritableAllows(patterns, target) bool` uses **dot-boundary** semantics (NOT `strings.HasPrefix`): an exact pattern matches only the identical path; a `vars.x.*` wildcard matches only when `target` begins with `base + "."` — so `vars.db.*` allows `vars.db.host` but DENIES `vars.db`, `vars.dbx.host`, `vars.database.host`. **Distinct scope** from per-service `services.<name>.bridge:` in `service.yml` (`ServiceBridgeConfig`, enablement) — this top-level block is project-wide container-write POLICY. **Shared layer helper (`layers.go`)**: `LoadLayers(workspacePath) ([]Layer, error)` + `ResolveLayeredPath(workspacePath, path) (LayeredValue, error)` factor the 3-layer load/validation out of `LoadConfig` so `dwe vars inspect`'s per-layer (`default`/`local`/`current` + origin; `LayeredValue.Default`/`Local`/`Current`) resolution and `LoadConfig` share one source of truth for path selection, optional-layer handling, and strict-root/legacy attribution — they cannot drift. ## Core — Execution (`internal/core/execution/`)

Log files: `OpenPipelineLog` / `OpenSubStepLog`. **Executor step ordering**: `phase-when → step-when → files_gate probe → (journal-skip only when FilesGate == nil) → execute` (gated steps always re-probe). - `internal/core/execution/condition/` — deploy step `when:` evaluator. Two APIs coexist: legacy string-based (`Classify`, `IsRuntime(string)`, `EvalRuntime`, `Kind*` constants) for workflow string `when:`, and typed (`Condition` struct, `EvalRuntimeTyped`) for pipeline `when:`. Template conditions evaluate at plan time in `pipeline/resolve`, not here. Uses hardcoded `sh -c` (POSIX-portable, intentionally not `ShellBin`). **Known wart**: `type: builtin` in `when:` resolves the *predicate* registry here; `type: builtin` in a step body or `check:` resolves the *engine builtin* registry in `internal/core/execution/builtin/` — same keyword, two registries, disambiguated by YAML position. **`generated-missing <svc> <field>` predicate**: gates a service's generate step (true when the field is absent from `.dwe/generated.yml` or the store is missing). ⚠️ `EvalBuiltin` does `SplitN(predicate," ",2)`, so `parts[1]` is the WHOLE remaining string — the case re-splits it on whitespace into `<svc>`/`<field>` via the exported `ParseGeneratedMissing(args)` (the single two-arg parser, reused by the `config` validator's cross-check), NOT the single-path `path`/`rel` variable. User-facing semantics: `docs/reference/config/conditions.md`.
- `internal/core/execution/filesgate/` — deploy step file-existence gate (parser-types): `FilesGate`, `State` (`readable` / `missing`), `RequireSpec`, `StepRef` (minimal step-shaped value so validators avoid importing `config.DeployStep`). Subpackage `spec/` does plan-time validation (`Validate`, `ResolveRequireIDs` against command `files:` block). Root package stays import-light. User-facing semantics: `docs/reference/config/deploy/conditions.md` § `files_gate:`.
- `internal/core/execution/builtin/` — engine builtins usable as step bodies or `check:` actions. **Package layout**: a leaf `spec/` subpackage (cycle-breaker — `Builtin` interface, `Kind`, `CallerContext`, `ExecContext`, `Entry` struct, exported helpers `GetStringParam`/`GetBoolParam`/`GetStringSlice`/`GetStringMap`/`GetMapAny`/`GetDurationParam`/`SortedKeys`, plus shared env-file parsers `ParseEnvEntries`/`ParseEnvKeys`/`EnvLineKey` used by both `services/` and `env/`) + five domain subpackages each exposing `func Builtins() map[string]spec.Entry`: `containers/` (8 entries — `docker_daemon_start` / `docker_daemon_logs` / `docker_daemon_stop` / `daemons_reap` / `containers_running` / `docker_stop_remove_container` / `docker_wait_healthy` / `docker_remove_project_volumes`), `services/` (6 — legacy copy mechanism `service_configs_copy` / `service_configs_check` (deprecation-warned) + `service_dirs_ensure`, plus the render mechanism `service_configs_render` / `service_configs_render_check` / `service_generated_harvest`), `fs/` (2 — `file_exists` / `remove_paths`), `env/` (2 — `env_keys_present` / `executable_in_path`), `interaction/` (2 — `confirm` / `message`). Root `builtin/` holds the public API (`Get` / `Run` / `Validate` / `Describe` / `IsInteractive`), 3 cross-cutting predicates (`shell`, `tcp_reachable`, `config_keys_present`) that have no natural domain home, and the registry assembly: `buildRegistry()` merges the 5 subpackage `Builtins()` maps with the 3 root entries and panics on duplicate names (the panic is paired with `TestNoDuplicateRegistryNames` for compile-time-equivalent coverage). `config_keys_present` (`KindPredicate`, `with: {keys: [<dot-path>...]}`) asserts each dot-path resolves to a non-empty value in the merged `cfg.Raw` — the config-aware counterpart of `env_keys_present` (reads in-memory merged config, not an on-disk `.env`); addressing matches the setup wizard's `writes:` dot-paths, so it pairs naturally with the `post-setup` check stage. Root re-exports `spec.Builtin`/`spec.Kind`/`spec.CallerContext`/`spec.ExecContext` and the const groups via type/const aliases so external callers (`pipeline/`, `validate/checks/`, `workflow/lifecycle/`) continue using `builtin.Builtin` / `builtin.ExecContext` / `builtin.CtxUserYAML` unchanged. Behavior contracts (unchanged by the refactor): `Builtin` interface threads `ctx` for cancellation; `spec.ExecContext.DockerConfig` (loaded once per top-level invocation, normalised `os.ErrNotExist` → `&DockerConfig{}`) is the single source of docker policy — builtins never call `config.LoadDockerConfig` themselves; `IsInteractive(name)` is the centralised predicate (`confirm`, `docker_daemon_logs`) consumed by both pipeline plan-time (`pipeline/resolve.go` `checkInteractive`) and workflow runtime (`runners/builtin/builtin.go` parallel guard); `docker_stop_remove_container` backs the per-service reset synthetic `container` phase (stop+rm one named container, idempotent on missing, skips rm if stop fails); `containers_running` is the fast "is running" check (no polling, no timeout, no healthcheck — the right partner for `check:` on `docker up` steps); `daemons_reap` is auto-injected into `dwe stop` via `lifecycle.EnsureStopConfig` as the synthetic `_auto_reap_daemons` phase; the `containers/` daemon trio (`docker_daemon_start` / `docker_daemon_logs` / `docker_daemon_stop`) backs registry expansion of `type: daemon` user commands (see `internal/core/usercommands/`). **Config-render trio** (all `KindAction`, thin wrappers over `internal/core/execution/templates/config/`): `service_configs_render` (`with: {service, mode?}`, default `replace`) → `RenderConfigs`; `service_configs_render_check` exists to be paired as the render step's `check:` so its PRESENCE forces re-run every deploy via the `hasCheck → Run` lever in `journal/decision.go` (mirrors `service_configs_copy`+`service_configs_check`); `service_generated_harvest` (`with: {service}`) → `HarvestGenerated`. The copy pair (`service_configs_copy` / `service_configs_check`) is deprecated — `ConfigsCopy.Run` emits a single `ectx.Output.Warning` notice (NOT also from `ConfigsCheck.Run`, which would double-warn as the copy step's check).
- `internal/core/execution/templates/` — template pack helpers shared between render commands and validators (`manifest/`, `packroot/`, `ide/`, `ai/`, `git/`). Manifest schema, `<pack>.local/` overrides, and collision policies (IDE / git: deepest extends wins; AI: shallowest) are documented in `docs/reference/render/index.md`. Each kind exposes `SelectServices`, `ResolveTemplatePack` (implicit-missing returns `found=false, err=nil`; explicit-missing or invalid-name errors), `LoadManifest`, `ValidateManifest`, `DryRunRender`, `ExtendsRoot`. Manifest is **mandatory** — packs without `manifest.yml` return `ErrManifestMissing`. **`ResolveTemplatePack` implicit chain** (when `render.<kind>.template` is unset): service name → walk `extends:` chain ancestor-by-ancestor → `default`. First existing pack wins. Invalid pack names anywhere in the chain are skipped silently. **`DryRunRender`** parses + executes every render template in-memory against `TemplateData` without writing — used by the `templates` validator domain to surface missing-key / parse / execution errors at `dwe validate` time. **`AIRenderEnabledExplicit`** defaults to `s.IsApp()` (matches IDE/Git): only app services render AI docs by default; tools/infra opt in explicitly via `render.ai.enabled: true`. **`TemplateData.Service` vs `Resolved`**: `Service` is the canonical config identity (extends-chain root, used to key raw-config lookups); `Resolved` is the rendering identity (collision winner); `ServiceCfg` is the merged block of `Resolved` (so e.g. `.ServiceCfg.Container` reflects the extender's overlay).
- `internal/core/execution/templates/config/` — the **config** render kind: materializes service config files from template packs + a durable value store, replacing the legacy copy mechanism. **Deliberately does NOT use `packcommon`/`TemplateData`/raw-`{{ }}`** like ide/ai/git — config templates use the `${...}` shorthand substrate via `tpl.CompileVarSyntax`+`RenderContext` (user/devbox ergonomics, `${APP_*}`/`${DB_*}` parity). Two core functions: `RenderConfigs(projectRoot, cfg, serviceName, store)` resolves the pack (convention service-name → `extends` chain → `default`, plus `render.config.template` pin and `<pack>.local/` override via `packroot.Resolve`), loads + validates the manifest (`manifest.File`, `render: from→to`), builds the per-service `RenderContext` (merged config + `Generated = store.Service(serviceName)`), and renders each entry into `<svc.Dir>/<to>` (mode `replace`; pathsafe destination guard — authors write `to: src/...`, the `src/` join is convention not hardcoded). `RenderConfigs` is single-service; callers that process the whole project (the `dwe render config` no-arg path and `renderConfigsForRun`) iterate `config.DeployOrder(cfg, []string{"app"})` (deterministic golden output — never `range cfg.Services`). **Config rendering is app-only** — only app services may declare `dir` / `render` / `generated` (see `allowedFieldsFor`), so the auto-iteration loops pass just `"app"`; sweeping tool/infra would resolve the implicit `default` pack for a dir-less service and error. `HarvestGenerated(projectRoot, cfg, serviceName, store)` iterates the service's `generated:` fields, reads `<svc.Dir>/<file>` (pathsafe), applies `pattern` (regex, **capture group 1**), `SetIfAbsent` into the store, then `Save` — errors (missing file / no match / no capture group) surface, never silently skipped (**harvest, not mint**: the engine is hermetic, so the service mints the secret and DWE only reads a string back). `CheckRendered(projectRoot, cfg, serviceName)` centralizes pack/manifest resolution + target-existence for the `service_configs_render_check` builtin. Consumed by the three `services/` builtins, the `dwe render config` CLI command, and `renderConfigsForRun`.
- `internal/core/execution/templates/packcommon/` — shared leaf for the ai/ide/git template-pack infrastructure they have in common (the per-kind *validators* and collision resolvers deliberately stay separate — AI is shallowest-wins, IDE/git deepest-wins). Owns the extends-walk trio `ImplicitPackCandidates` / `ExtendsDepth` / `ExtendsRoot` plus the single `const maxDepth = 32` (previously duplicated 9×); the shared `TemplateData` struct with `AppServices` / `ToolServices` / `InfraServices` accessors; and `DryRunRender(kind, …)` / `executeTemplateInMemory(kind, …)` (the kind literal is the only per-pack difference). `ai`, `ide`, and `git` keep backward-compatible `type TemplateData = packcommon.TemplateData` aliases and `var` aliases for the walk funcs so external callers in `cli/render` and `validate/templates` compile unchanged. Cycle-free: `config` does not import `templates`.
- `internal/core/execution/preflight/` — assembler for the preflight hook invoked from lifecycle commands. `Run(ctx, cfg, cmdRegistry, baseDir, stage, skip, errOut) error`: when `skip == true` prints `"preflight skipped (--skip-preflight)"` to `errOut` and returns nil — NO validate.yml load, NO validator assembly, NO execution (the flag is a true bypass because `type: command` checks invoke arbitrary user scripts). Otherwise performs the single `LoadValidateConfig` parse, populates `validate.Context` with cfg + load result + warnings + load error, assembles `env.All(cfg)` + `checks.AllForStages(...)` + the single `config.validate` validator (so a malformed validate.yml surfaces inline as part of preflight, not silently), runs sequentially, renders diagnostics via `render.FormatDiagnostics` + `render.DiagnosticsTable` to `errOut` (always stderr at the command boundary), returns `*preflight.Error` (with `ExitCode() int = 1`) when any error-severity diagnostic surfaces. **Ordering contract**: every caller MUST invoke preflight BEFORE any side effect on Docker, git, or the filesystem — including `lock.Acquire` (deploy creates `.dwe/deploy/deploy.lock`), git probe/pull (run), and container stops (stop). cfg load and `loadCommandRegistry` are hoisted above preflight; registry-load failure is tolerated (nil registry yields unknown-command diagnostics). **Deploy two-gate / `post-setup`**: the check stage set comes from `stagesForPreflight(stage)` — for `"deploy"` it returns `{deploy, post-setup}`, every other stage maps to itself, and `""` → nil (match all). This is the ONLY place `post-setup` checks run: the interactive deploy menu's early pre-wizard gate (`cli/deploy/menu.go::runPreWizardPreflight`) queries only `"deploy"`, so `post-setup` checks are skipped there and execute at this final preflight after the setup wizard has populated `local.yml` (or, on `dwe deploy run`, immediately before the pipeline). User-visible schema: `docs/reference/config/validate.md` § Stages.

## Core — Workflow (`internal/core/workflow/`)

- `internal/core/workflow/deploy/` — deploy plan resolution: `ResolvePlan`, `ResolveServicePlan`, `ResolveServicesPlan`, `ResolveServicesPlanSubset(cfg, reg, deploys, names)` (subset deploy: validates every name has deploy.yml, topo-sorts by `after:`, strips duplicate ImplicitEnvStep, prepends one env step), `FindStep` (updated to read `workspace/services/<name>/deploy.yml`), `TrackedServices`, `LoadTrackedServices` (canonical tracked-service set from the resolved plan; nil registry tolerated — gate validation skipped). `TopoSortByAfter(deploys, services)` performs deploy-time ordering by the `after:` field (distinct from runtime `depends_on:` sort); returns names in dependency-first order with alphabetical tie-break; sentinel errors `ErrDeployCycle`, `ErrDeploySelfReference`, `ErrDeployUnknownAfterRef`. **Pipeline defaults**: `DefaultDeployConfig()` returns the built-in deploy pipeline (services → docker up --wait → post-deploy info+success); `EnsureDeployConfig(loaded *config.ProjectDeployConfig) (*config.ProjectDeployConfig, bool)` returns user config (false) or default (true). The CLI deploy entrypoint overwrites `cfg.Deploy` with the Ensure result so downstream resolvers always see a non-nil config. Subpackage `journal/` owns the state-file types and I/O (`ProjectState`, `ServiceState`, `PhaseState`, `StepState`, `Status`, `Load` / `Save` / `Remove` / `RemoveService`, hashing: `ActionHash` / `StepHash` / `ServiceConfigHash` / `ProjectConfigHash`, `Decide` for skip logic, `Recompute` for aggregates). `ProjectState` carries `Pending *PendingApply` (yaml omitempty). `PendingApply{Operations []PendingOp, ConfigHash string, CreatedAt time.Time}`; `PendingOp{Kind PendingKind, Services []string}`. `PendingKind` string enum: `PendingKindUnspecified` (zero), `PendingRestart`, `PendingDeploy`. Helper methods: `(*PendingApply).Find(kind)`, `(*PendingOp).ServiceNames()` (defensive copy). Package-level atomic helpers: `AddPendingOp`, `AddPendingOps` (atomic batch), `ClearPending`, `ClearPendingForKind`, `ClearPendingForServices`, `ClearPendingOps` (atomic batch clear), `ReplaceServiceWithPending` (atomic combine of RemoveService + AddPendingOp). State file: `.dwe/deploy/state.yml` (gitignored). User-facing journal semantics: `docs/reference/config/state/index.md`.
- `internal/core/workflow/lifecycle/` — lifecycle pipeline execution: `RunPhases`, `RunRun` (git update + phases + show-info), `RunRestart` (stop + run), `RunStop`; `RunContext.ShowInfo` is injected to avoid importing cobra renderers; `RunContext.SkipNotify` is set by `RunRestart` on its inner `RunRun` call so a restart fires at most one desktop notification (restart is not a user-invoked run — spec says zero notifications). **Pipeline defaults**: `DefaultRunConfig()` / `DefaultStopConfig()` return freshly-allocated built-in pipelines (callers may mutate safely). `EnsureRunConfig(loaded *LifecycleConfig) (*LifecycleRunConfig, bool)` and `EnsureStopConfig(cfg *LifecycleConfig) (*LifecycleStopConfig, bool)` each return the user config (false) or the default (true) — the bool signals whether the CLI should emit the info line. `EnsureStopConfig` always prepends `autoReapPhase()` regardless of defaulting; the auto-reap phase is the sole exception to full-replacement composition. `RunContext.OnDefaultUsed func(DefaultedPipeline)` and `StopContext.OnDefaultUsed func(DefaultedPipeline)` let CLI adapters emit the info line without importing cobra renderers. `DefaultedPipeline` is a typed string enum (`DefaultedRun`, `DefaultedStop`). `RunRestart` propagates `ctx.OnDefaultUsed` into `stopCtx` so restart fires the callback for both legs. Deploy gate is unconditional — no bypass flag (compose errors immediately on undeployed services). **Run-preamble config render**: `renderConfigsForRun` auto-renders service configs (replaying stored `${generated.*}` values) and is called **AFTER the deploy gate AND after the post-pull cfg reload, but BEFORE `RunPhases`** — NOT at the early `.env` render; `run` never runs generate/harvest. Ordering IS the safety argument: a `reset --clear-generated` + `dwe run` fails the gate before render is reached, so secrets are never blanked. `missingGeneratedKeys` makes run-render non-destructive: if any declared `generated:` key is absent from the store, that service's render is SKIPPED with a `dwe deploy run` hint (deploy render stays lenient — first deploy mints; this guard is run-only). `sharesExtendsParentHub` skips (silently) an `extends` child whose hub dir is inherited from its parent: such a child is a config-render **alias** (same resolved pack + hub → byte-identical output) whose `${generated.*}` values are minted under the PARENT's store key, because it has no own `deploy.yml`/harvest (e.g. a debug sidecar that bind-mounts the app's source). The parent renders the shared hub; rendering the alias again is redundant and would falsely trip `missingGeneratedKeys` (its keys are absent under the child's own name). This mirrors deploy, which never schedules a render for such a child. A child with its OWN `dir` is a genuine render target and is NOT skipped.
- `internal/core/workflow/reset/` — reset plan resolution (`ResolvePlan`, `FindStep`); mirrors deploy. `DefaultResetConfig()` returns the built-in reset pipeline (confirm → docker down → remove volumes + remove services/); `EnsureResetConfig(loaded *config.ProjectDeployConfig) (*config.ProjectDeployConfig, bool)` returns user config (false) or default (true).
- `internal/core/workflow/scaffold/` — pure domain behind `dwe init`. `Scaffold(Options) (Result, error)`: resolves the target dir, renders the embedded template plan, writes each file atomically (temp-file + `rename`), merges `.gitignore`, and links `CLAUDE.md` → `AGENTS.md`. **No cobra, no `io.Writer`** (honors "core returns data, cli writes"); the cli layer is `internal/cli/scaffold/`. `Options{TargetDir, Name, Prefix, Service, Branding{Title,Tagline,Accent}, Force}`; `Result{Target, Created, Skipped []string, SymlinkFallback, NestedWarning bool}`. **Idempotent at the file level** — fill-gaps, skip pre-existing files unless `Force`; a `Force` run reports everything `Created` (except the always-idempotent `.gitignore` append-merge). Two exported helpers let the cli layer pre-resolve the same path Scaffold writes to: `ResolveTarget(targetDir) (absPath, error)` (empty → cwd, then `Abs`) and `HasProjectConfig(absTarget) (bool, error)` (stats `workspace.yml` in the target *itself* — used for the cli existing-project consent gate, distinct from the ancestor-walking `detectNestedProject`/`NestedWarning`). Load-bearing details:
  - **Template storage** (`templates.go`): `//go:embed templates` mirrors the output tree. Walker rule — files ending `.tmpl` render through `text/template` with **custom `[[ ]]` delimiters** (`Delims("[[", "]]")`), then the suffix is stripped; every other file is copied **verbatim**. The `[[ ]]` choice is deliberate: the inert `info.yml`/`docker.yml` references contain literal `{{ .Project.Name }}` examples that must survive copy unrendered. Dotfiles are stored with a `dot-` path-segment prefix (`dot-editorconfig` → `.editorconfig`, `dot-dwe/config` → `.dwe/config`) because `go:embed` silently skips `.`/`_`-prefixed names — **not** `all:` (which would also pull in editor junk). `renderPlanFS(fs.FS, opts)` is FS-injectable for tests.
  - **Inert overrides** — `deploy.yml`/`lifecycle.yml`/`info.yml`/`docker.yml` ship **fully commented**. DWE pipeline composition is full-replacement (an active `deploy.yml` replaces the whole built-in pipeline, and a half-edit silently drops phases), so these stay inert and the built-in default stays active until the user uncomments. There is no divergence test — the only drift guard is the source pointer in each file's header (`Default*Config` constructor / `docs/reference/config/<x>.md`). A fully-commented YAML doc decodes to `io.EOF`, which the strict `KnownFields(true)` pipeline loaders in `project/config/workspace.go` now tolerate (empty doc == absent file → built-in default applies); see the Task 9 note in the plan.
  - **`styles.yml` shape** — branding renders the **nested** schema (`header.lines: [Title]`, `header.tagline: Tagline`, `colors.accent: Accent`); there is no top-level `title:` key, and `LoadStylesConfig` is lenient `yaml.Unmarshal` so a flat key would silently vanish. Empty branding falls back to commented placeholders via `[[- if ]]` guards.
  - **`.gitignore` is not a template** — the DWE block is the Go const `dweGitignoreBlock` in `gitignore.go` (single source of truth), applied via a separate `applyGitignore` append-merge path (create when absent; append only missing lines under a `# dwe` marker when present; idempotent). A template would make `renderPlan` double-emit `.gitignore`.
  - **`CLAUDE.md` symlink** — `linkClaudeMd(dir) (fallback bool, err error)` tries `os.Symlink("AGENTS.md", dir/CLAUDE.md)`; on error or pre-existing target it writes a verbatim copy and returns `fallback=true` (surfaced as `Result.SymlinkFallback`). The symlink call is a func var for testability.
  - **Starter service** — `applyServicePlan` rewrites the embedded `workspace/services/app/` segment to the chosen `Service` name, or drops the folder entirely when `Service == ""`. `service.yml` keeps `type`+`container` active (a fully-commented `service.yml` is invalid under strict decode), the rest commented.
  - **Nested-project detection** — `detectNestedProject` walks ancestors (not the target itself) for a `workspace.yml`; a hit sets `Result.NestedWarning` (the cli decides how to present it) and never blocks.
- `internal/core/workflow/snapshot/` — snapshot subsystem (synthetic-command builder for workflow execution, create/restore/remove/list/exec operations, workspace-files capture, services diff, observer). Organised as a three-tier strict layering: `meta/` (leaf: descriptor types + path coordinates + `ScanArtifacts` + `WriteFileAtomic`; no internal subpkg imports) → `archive/` (tar I/O: `Pack`, `Unpack`, `VerifyExtractedArtifacts`, `ReadManifestFromTar`; imports `meta/` only) → root (business workflows: imports both). The cycle-break that pinned `scan.go` into `meta/` is intentional — `archive.VerifyExtractedArtifacts` re-scans extracted artifacts via `meta.ScanArtifacts`, and if `scan.go` lived at the root the import would go archive→root while root already imports archive. Same reason `WriteFileAtomic` is exported in `meta/atomic.go` (was private `writeFileAtomic`) — both `workspace_files.go` and `restore.go` at the root call it. Helper files split out from the create/restore flows: `workspace_files.go` (`captureDWEFiles` / `restoreDWEFiles` with `preserve_keys`-aware strip + merge over `*yaml.Node`, plus the 1 MiB `localYMLMaxBytes` cap on untrusted archive content; returns/accepts `meta.DWEFiles`) and `services_diff.go` (`DiffServices` + exported `FormatServicesDiff` shared by `snapshot inspect`, the restore prompt, and the `snapshot.<name>.services_diff` validator). User-visible schema: `docs/reference/config/snapshot.md`. Load-bearing invariants:
  - **Atomic IO contract** — `meta/manifest.go` / `meta/current.go` write a temp file **in the same directory** as the final file (cross-filesystem `rename` is not atomic), `chmod 0o644`, then `os.Rename`. Mirrors the `journal/state.go` pattern. The shared helper is `meta.WriteFileAtomic` (`meta/atomic.go`). The pre-restore backup at `.dwe/snapshots/.pre-restore-backup/` follows the same contract and overwrites the previous backup on each restore.
  - **No `schema_version` field** in `Manifest` — per project policy (CLAUDE.md). The manifest has no version gate, no migration path; rename / restructure freely as needed.
  - **Streaming sha256, int64 size, no symlinks** — `meta/scan.go` walks the snapshot directory excluding `manifest.yml` and `workspace/`, computes per-file sha256 via `io.Copy(hasher, f)` (never `io.ReadAll`) so multi-GB dumps don't OOM; rejects any entry with `os.ModeSymlink` set with a clear error — workflows are not allowed to produce symlinks in the snapshot dir.
  - **Render-context propagation point** — snapshot vars (`${snapshot.name|path|description|variant|created_at}`) are threaded from `runtime.RunContext.Render.Snapshot` + `.SnapshotScope` into every sub-step `RenderContext` in `runners/workflow/step.go` (`renderCtx.Snapshot` / `renderCtx.SnapshotScope` assignment block) and at the two leaf-context constructions in `build_context.go` (the `BuildRunContext` and `BuildSnapshotRunContext` constructors). Without this propagation, snapshot vars in `with:` values of leaf user commands resolve empty. Scope visibility is gated by the `tpl.SnapshotScope` enum (`SnapshotScopeNone` → compile error; `SnapshotScopeCreate` → all keys except `created_at`; `SnapshotScopeRestoreOrRemove` → all keys). The scope check runs in `tpl.RenderCommand` via `validateSnapshotScope` **before** `CompileVarSyntax` so `CompileVarSyntax` stays pure-syntactic with no error path.
  - **Workflow executor reuse** — `exec.go` builds a synthetic `*model.CommandDef{Type: "workflow", Steps: workflow.Steps}` and dispatches via `usercommands.RunCommand`. Snapshot workflows are user-command workflows executed at runtime from a different source file; there is **no** parallel pipeline executor, no shadow scheduler. `BuildSnapshotRunContext` mirrors `BuildRunContext` but injects `Snapshot` + `SnapshotScope` into `Render`.
  - **Live-view observer wiring** — `ExecParams.StepObserverFactory func([]model.WorkflowStep) StepObserverCloser` is invoked **after** `SelectWorkflow` and **after** the pre-workflow confirmation prompt, immediately before dispatching to the runner; this defers any TUI footer until all `huh` prompts are done. `StepObserverCloser` is a local interface embedding `runtime.WorkflowStepObserver` plus `Close()` — the snapshot package owns the `defer obs.Close()`; the CLI never holds the observer past factory construction. The CLI implementation lives in `internal/cli/snapshot/liveui.go` (`newSnapshotLiveObserver`); it returns `nil` for non-TTY or `--no-live` so the runner's nil-observer path produces plain output. A depth-counted pause/resume helper on the observer bridges `widgets.SetHuhHooks` and `StepIOSuspender` against the same `liveui.LiveLine` so nested suspends from in-step `ConfirmCommand` prompts compose with the step-level suspend window — `live.Pause` / `live.Resume` each fire exactly once per command step.
  - **Archive-safety contract** (`archive/unpack.go`, with the rejection types + size caps in `archive/archive.go`):
    1. Path validation runs pre-checks on the raw `tar.Header.Name` (`filepath.IsAbs`, empty / `.` / `..` rejection, `filepath.IsLocal` Go 1.20+), then joins against the staging root, then `pathsafe.ContainedRel` as belt-and-braces. **Never** rely on `filepath.Join` + `ContainedRel` alone — `Join` normalises `..` away before `ContainedRel` ever sees the original header.
    2. Type allowlist: `tar.TypeReg` and `tar.TypeDir`. Go 1.11+ normalises `TypeRegA` ('\x00') to `TypeReg` in `tar.Reader.Next()`, so the allowlist does not need a separate case for it. `TypeSymlink` / `TypeLink` / `TypeChar` / `TypeBlock` / `TypeFifo` / `TypeXGlobalHeader` (and any other typeflag) are rejected with an error naming the entry.
    3. Resource caps: package-level constants `maxUnpackBytes = 50 << 30` (50 GiB) and `maxUnpackFiles = 100_000`; enforced via `io.LimitReader` wrapping the decompressor. Constants, not config — promote to config later if needed.
    4. No follow on existing files: `O_CREATE|O_WRONLY|O_EXCL` refuses to overwrite anything inside the staging tree.
    5. Atomic install with backup rollback: extract into `./snapshots/.unpack-<random>/` (suffix from `mkdirRandom` via `crypto/rand` — blocks TOCTOU symlink pre-creation). If the final `<name>/` already exists, rename it aside as `.backup-<random>/`, rename staging into place, then remove the backup; on second-rename failure restore the backup so the final directory is never left half-installed. Any error during extraction triggers `os.RemoveAll` of the staging dir.
    6. Manifest-driven artifact verification (`VerifyExtractedArtifacts`) runs **after** extraction and **before** the rename-into-place step. Each `manifest.yml` artifact path is validated against the staging root with `filepath.IsLocal` + `pathsafe.ContainedRel` **before** `os.Open` — a maliciously crafted manifest cannot make the verifier read sibling-snapshot or system files; path-safety failure is a hard error, not a warn. Per-artifact sha256 is recomputed via `io.Copy(sha256.New(), f)` (never `io.ReadAll`). Three diagnostic groups (`Missing` / `HashMismatch` / `Extra`) are written to `cmd.ErrOrStderr()` (never `os.Stderr` directly); `Missing` and `HashMismatch` share a single grouped `continue? [y/N]` prompt — declined → cleanup + `UnpackVerifyDeclinedError`. `--no-verify` bypasses verification but always prints the bypass warning to stderr for CI visibility. The CLI summary line is driven by the typed `UnpackResult.Verification` (`VerificationSkipped` / `Clean` / `Warned`) — stderr is never parsed to reconstruct it. Pack writes only `<name>.tar.gz` — no `.sha256` sidecar.
  - **Lock acquisition** — every mutating subcommand (`create`, `restore`, `rollback`, `remove`, `pack`, `unpack`) wraps its `RunE` body with the CLI lock helper `cmdctx.AcquireProjectLocksOrReport(baseDir, w)` + deferred release — **never** `lock.AcquireProjectLocks` directly. The helper wraps `lock.AcquireProjectLocks`, prints `*lock.ProjectLockHeldError` via the writer (exit code 2 preserved, error returned unchanged), and wraps any other error as `acquiring project locks: %w`. **`pack` is included**: without the lock, packing a snapshot mid-`remove` produces a corrupt or truncated archive.
  - **Synthetic command ID** — internally constructed `CommandDef` uses `ID: "<internal>.snapshot.<scope>"`; suppressed from notifications via `SkipNotify: true` at sub-step level (`runners/workflow/step.go`, in `runCommandStep`'s `subCtx` literal). Snapshot subcommands emit their own notifications at the command boundary using `notify.OpCommand` with operation labels `"snapshot:create"` / `"snapshot:restore"` / `"snapshot:rollback"`.
- `internal/core/workflow/setup/` — interactive setup wizard for fresh projects (`workspace/setup.yml` schema + executor). **Model**: `SetupConfig{Questions []Question}`, `Question{ID, Type, Title, Description string; Required bool; Writes string; Options []Option; Validate *ValidateSpec}`, `Option{Value, Label string}`, `ValidateSpec{Preset, Regex string}`. **Loader**: `LoadSetupYAML(path)` (strict-decode, missing file → `(nil, nil)`, parse errors wrapped); semantics-permissive (unknown `Type` / duplicate IDs / invalid `writes:` caught by validators, not loader). **Merge logic**: `BuildOverlay(questions, answers) map[string]any` (dot-path → nested map), `BuildPortOverlay(overrides) map[string]any` (port key → `services.<name>.ports.<port_name>`). The wizard now applies these overlays via the comment-preserving `local.ApplyOverlayToNode` + `local.WriteLocalYAMLNode` path (sequentially, last wins) — the old map-based `MergeIntoLocal` was removed; the node-aware mergeable guard in `local/local_node.go` reproduces `validateMergeable`'s map-over-scalar rejection AND the single legacy bare-int-port-leaf → `{port:N}` exception. **Validation**: `ValidateAndCoerce(q, raw) (any, error)` — processes `input`-type answers through preset validators (`port` → `int`; `hostname`, `path`, `non-empty` → `string`) or regex checks, returning typed values; other question types bypass coercion (huh already produces typed output). **Wizard executor**: `Run(ctx, WizardDeps)` orchestrates port-conflict prompts + setup questions (answers → overlay → merge → atomic write); huh-bound asker functions (`AskQuestions`, `AskPortOverrides`) are dependency-injected for testability. **Huh bindings**: `NewHuhAsker(out)` returns the production asker functions; `coerceInputAnswers`, `coercePortOverrides` are pure helpers extracted for unit testability. Sentinel error `ErrWizardCanceled` indicates user abort (returns without writing). Belt-and-suspenders type/semantic enforcement at wizard runtime: type assertions per question type, required-answer checks (zero-value rejection), re-validation of `input` presets against answer map values, `BuildPortOverlay` range check (1..65535).

## Core — User Commands (`internal/core/usercommands/`)

- `internal/core/usercommands/` — declarative command system facade (re-exports subpackages):

Built-in adapters (`shellcheck`, `hadolint`) plus a `type: generic` exec-and-wrap adapter; `Adapter` interface (`DefaultBin` / `DefaultPaths` / `DefaultExtensions` / `DefaultFilenames` / `ReservedFlags` / `BuildArgs` / `ParseOutput`); `walk.collectFiles(baseDir, paths, exts, filenames, pathsAreDefaults)` (recursive `filepath.WalkDir` rooted under `baseDir`; symlinks and `.git/` always skipped; `pathsafe.ContainedRel` containment with a short-circuit for `paths: ["."]` since `ContainedRel` rejects `.` by design; missing **default** paths are silently dropped, missing **user-configured** paths surface a Warning); `runtime.linterValidator` (per-linter `validate.Validator` — autodetect via `exec.LookPath`, default-bin-missing silent / explicit-bin-missing Warning, `exec.CommandContext` with `context.WithTimeout(parent, DefaultLinterTimeout)` where parent falls back to `context.Background()` when `ctx.Ctx` is nil, output bounded by `MaxLinterOutputBytes` via `boundedWriter`; two diagnostic buckets — `operationalDiags` never clamped, `findings` clamped from above by `entry.Severity` if set — so `severity: info` cannot silence a timeout Error or panic); `lintersGroup` implementing `GroupValidator` (`sync.WaitGroup` + buffered-channel semaphore — **NOT** `errgroup.WithContext` because one linter's failure must not cancel siblings; per-goroutine `recover()` converts panics to Error; concurrency capped at `MaxLinterConcurrency = runtime.NumCPU()`; pre-allocated `results[i]` slot per child — no shared slice, no mutex); `All(validateCfg, validateLoadErr, baseDir)` (corrupt-config short-circuit returns zero validators; `validateCfg == nil` falls through to per-adapter autodetect; reserved-flag rejection via `validateUserFlags(adapter, entry.Flags)` produces a synthetic error validator instead of registering the linter, so a bad config short-circuits before any subprocess runs). - `internal/core/validate/bridge/` — host-bridge domain (`bridge.*`): a single `servicesValidator` (ID `services`) over every service's `bridge:` block. Warnings (only when bridge is effectively enabled): no container target (unreachable on loaded configs — `container:` defaults to the folder name — kept for literal-built configs, mirroring the `BuildOverlaySpec` skip), and the reachable hazard: no `dir`/`dir_internal` workspace mapping → the overlay omits `DWE_HOST_WORKSPACE`/`DWE_CONTAINER_WORKSPACE`, shim cwd translation is unavailable, and the daemon containment check rejects every in-container invocation (type-aware hint: apps declare the pair; tool/infra cannot declare `dir` under strict decode → opt out or mount at an identical path). Registered in `internal/cli/validate/validate.go` via `valbridge.All()` alongside the other domain loops, with a `dwe validate bridge` scoped subcommand. Participates in `dwe validate` ONLY — never preflight (preflight consumes `valconfig.All()` exclusively; a bridge config mistake must not block unrelated lifecycle).

## Core — Notify (`internal/core/notify/`)

- `internal/core/notify/` — desktop notifications. `New(cfg) *Notifier` (concrete struct, nil-safe `Notify`) dispatches via an unexported `backend` interface to `noopBackend` or `nativeBackend`. Factory short-circuits to noop on `cfg == nil`, master switch off, empty channels, CI / `DWE_NONINTERACTIVE` / non-TTY (test seam: `isInteractiveForNotify`). `nativeBackend` wraps `osNotify` (test seam, signature `func(title, body string, icon any) error` — `any` mirrors beeep.Notify, lets the embedded `[]byte` icon flow through without temp-file conversion) in a goroutine + non-blocking semaphore + 2s timeout — slot release lives in the inner goroutine so a hung OS notifier can't leak more than one goroutine per process. **Platform split**: `native_other.go` (build `!darwin`) binds `osNotify = beeep.Notify` and sets `beeep.AppName = "DWE"` in `init()`; `native_darwin.go` (build `darwin`) binds `osNotify = darwinNotify`, which dumps the embedded PNG to a temp file and execs `terminal-notifier -title T -message M -group DWE -appIcon <png> -contentImage <png>`, falling back to `osascript` (no icon) on missing/failed `terminal-notifier`. Why not beeep on darwin: modern macOS silently ignores `-appIcon` for terminal-notifier, so beeep's bare `-appIcon <icns>` shows terminal-notifier's bundle icon; we add `-contentImage` so the DWE logo at least renders as a thumbnail in the notification body. `assets/icon.png` is embedded via `//go:embed` (`notificationIcon []byte`) and passed to every notify call. Title format: `✓/✗ DWE · <project>: <op> succeeded/failed` (project segment dropped when empty); body carries duration plus optional truncated error. `Op` (`OpDeploy` / `OpRun` / `OpCommand`) and `Outcome` (`OutcomeSuccess` / `OutcomeFailure`) enums with `*Unknown` at iota 0. `OutcomeFromErr(err)` is shared by all hookpoints. Errors always logged at debug, never returned. Consumers each declare a local `notifier` interface (one method) for testability — they never depend on a public interface.
- **Notifier hookpoints**: `internal/cli/deploy/deploy.go` (deployRunCmd), `internal/core/workflow/lifecycle/RunRun`, and `internal/core/usercommands/runtime/RunCommand`. All three follow the same shape: `start := time.Now()`, `var projectName string`, `userpkg.Load` (parser error → `slog.Warn` + nil cfg, never blocks), `newNotifier(cfg)` (consumer-local seam), defer firing `Notify(context.Background(), ...)` from a named-return `err`. The defer is installed **before** the main config load so a malformed `workspace.yml` still triggers a failure notification. **`SkipNotify` invariants**: `lifecycle.RunContext.SkipNotify` is set by `RunRestart` so the inner `RunRun` does not fire (restart is not a notify event). `runtime.RunContext.SkipNotify` is set transitively at **every** internal invocation site (`runners/workflow/step.go` sequential + `runners/workflow/parallel.go` parallel paths, `pipeline/executor.go` action dispatch) — only the top-level `runCommandByID` orchestrator leaves it at zero-value false. The runtime gate is `rc.Cmd.Notify && !rc.SkipNotify`; the cheap-path check installs the defer before any I/O so pre-run failures still notify. Validator emits an info diagnostic for the static-detectable direct-parallel-sub-step case (`internal/core/validate/commands/notify.go`); the runtime guard handles transitive cases the validator cannot see. `notify: true` on `type: daemon` is a validator error.

## Core — Bridge (`internal/core/bridge/`)

The host-side half of the dev-container bridge (the in-container half is `internal/shared/bridgeclient` + `cmd/dwe-shim`). User-visible behavior: `docs/reference/concepts/bridge.md`. Design references (D1–D12) live in the implementation plan; the load-bearing invariants are restated here.

- `internal/core/bridge/` — daemon + lifecycle + overlay generation. **The daemon is a stateless forwarder** (design D5): one connection = one command, fork `dwe <argv>` per connection, no in-memory cache, no project model — never add business logic here. Files: `daemon.go` (Config + env contract consts `EnvInvokedFrom` / `InvokedFromContainer` / `EnvNonInteractive` / `BindOverrideEnv`; `DefaultBridgeDir(projectRoot)` = `.dwe/bridge`), `listeners.go` (unix `host.sock` 0660 in dir 0700 + TCP `127.0.0.1:0` always; best-effort extra bind on the docker gateway IP via injectable resolver — bind failure on Mac is silent and expected; `port` written AFTER bind; `token` 0600 written once and kept across restarts — stable project identity; `DWE_BRIDGE_BIND` override is comma- or whitespace-separated; **never `0.0.0.0`**), `session.go` (per-accept: auth — constant-time token compare on TCP / peercred on unix — then HELLO validation: protocol version, realpath cwd containment inside `--project-root`, `tty:true` → `tty_unsupported`; 10 s HELLO deadline so half-open connections cannot pile up; SIGNAL allowlist = SIGINT/SIGTERM only; conn close → SIGTERM to the process group, 5 s grace, SIGKILL; `daemon_shutting_down` ERROR for accepts during Close), `exec.go` + `exec_unix.go` / `exec_windows.go` (the injectable `LaunchSpec`/`Process`/`LaunchFunc` seam; production `launchOS` resolves `os.Executable()` **lazily** so an injected launcher never touches it — calling it from a test re-executes the test binary, the documented recursion hazard; Setpgid + group signaling; signal deaths map to 128+sig; launch failure → STDERR + EXIT 127, protocol ERROR frames stay reserved for the D4 code set). **Env override contract (design D7)**: the daemon re-filters the client-sent env through `bridgeclient.StripEnv` (single strip-set source — `DWE_BRIDGE_DIR` / `DWE_BRIDGE_PROJECT` / `DWE_BRIDGE_UNREACHABLE`, `DWE_HOST_WORKSPACE`, `DWE_CONTAINER_WORKSPACE`, any `DWE_PROJECT_ROOT*`), then **also drops execution-hijacking variables** (`subprocessEnv` — `dangerousEnvNames` = `PATH`/`BASH_ENV`/`ENV`/`SHELLOPTS`/`BASHOPTS`/`IFS`, `dangerousEnvPrefixes` = the dynamic-loader families `LD_*` + `DYLD_*`), **replaces the host-identity set with the daemon's own values** (`hostIdentityEnvNames` = `HOME`/`USER`/`LOGNAME`/`TMPDIR`/`SSH_AUTH_SOCK`, `hostIdentityEnvPrefixes` = `DOCKER_*`/`COMPOSE_*`/`XDG_*`; `daemonEnviron` is the injectable seam — a container `HOME` silently sends the host docker CLI to `unix:///var/run/docker.sock`, absent on Docker Desktop / OrbStack macs, because contexts resolve via `$HOME/.docker/config.json`), and **force-sets** `PATH` to the daemon's own host PATH plus `DWE_INVOKED_FROM=container` + `DWE_NONINTERACTIVE=1`. The two `DWE_*` are host-controlled only; client-sent values are dropped, which is what makes the CLI container policy unspoofable. The PATH/loader strip is the security counterpart: the forked host `dwe` resolves `docker`/`git`/`sh` by bare name, so a container-controlled `PATH`/`LD_PRELOAD` would otherwise be host code execution — the command allowlist limits WHICH commands run, this hardening keeps allowlisted ones off attacker binaries. `DWE_INVOKED_FROM` must NOT affect `--output json` shape.
- Process lifecycle: `ensure.go` (`Ensure`/`Cycle`/`StopDaemon`/`ProbeDaemon` over a **bridge-private flock** on `.dwe/bridge/daemon.pid` via `shared/lock` — NEVER `lock.AcquireProjectLocks`, this is deliberately not a project lock; Ensure releases the probe flock before spawning — the daemon re-acquires at startup and a spawn-race loser exits cleanly; pidfile mtime is the uptime source, written exactly once by the daemon's own startup acquire), `spawn_unix.go`/`spawn_windows.go` (detached spawn: Setsid + released handle, child stdout/stderr → `daemon.log` so panics land there), `autostop.go` (`RunAutoStop` with injectable `Subscribe`/`CountRunning`: docker events filtered on `com.docker.compose.project=<resolved name>` — the label every other dwe probe matches, via `config.ResolveComposeProjectName`; 60 s `docker ps` poll fallback; 10 s startup grace; zero containers → graceful shutdown removes `host.sock`+`port`, **keeps `token`**; count errors are logged and retried, never fatal; deliberately NO connection-idle timeout — a dead daemon cannot be revived from inside a container).
- `composegen.go` + `prepare.go` — **overlay regeneration model (design D8)**: `.dwe/compose.bridge.yml` is dwe-owned machine state (same model as `.env` and rendered configs), regenerated atomically (same-dir temp + rename, write-if-changed) by the prepare hook on EVERY compose-up command and **DELETED when no enabled service has bridge enabled** — the overlay step ALWAYS runs even when bridge is fully off, so toggles can never leave a stale fragment in the `-f` chain. `RenderOverlay(OverlaySpec)` stays a pure renderer (golden tests); `BuildOverlaySpec` iterates via `config.DeployOrder` (never `range cfg.Services`). Two deliberate deviations from the original design sketch: mount sources are ABSOLUTE host paths (relative compose sources resolve against the FIRST `-f` file's dir, which shifts with `compose.base`), and `DWE_HOST_WORKSPACE`/`DWE_CONTAINER_WORKSPACE` are the per-service hub mapping (`<root>/<svc.dir>` ↔ `svc.dir_internal`) — both omitted when the pair is missing, and the daemon containment check then rejects untranslated cwds (the `validate/bridge` warning). Shim arch per service via `DockerArchResolver` (container inspect `{{.Image}}` → image inspect `{{.Architecture}}`, injectable `CommandOutput` seam; fallback = host arch with a warning — except the expected `No such container` case (first deploy / after reset), which falls back SILENTLY with only a `trace.Decision` `-v` line, since the host arch is correct for native images and re-resolves at the next start — never hardcoded amd64). **Container names for the arch probe are derived with `config.ResolveComposeProjectName(baseDir, cfg)`** — docker.yml's `project_name` when set, NOT `Project.FullName()` (the standing compose-bypass rule); `spec.Project` / `DWE_BRIDGE_PROJECT` stays `FullName()` — it is diagnostic identity, not a container prefix. The overlay also injects `DWE_BRIDGE_SERVICE: <OverlayService.Key>` per service — the workspace services map key (NOT `.Name`, the compose container name), because per-command `bridge.services` lists match workspace keys. Chain position: `composeFiles()` inserts `config.BridgeOverlayRelPath` after app overlays, BEFORE local.yml overlays (local keeps the last word); existence is stat'd at CALL time, not load time — the prepare hook regenerates/deletes the file after `LoadConfig` and before compose args are built. `Prepare(PrepareOptions)` = overlay regenerate-or-delete (always) + shim materialize + daemon Ensure-or-Cycle (`CycleDaemon: true` for `deploy run` and whole-stack restart — cycle REPLACES ensure, never runs in addition); call sites: `lifecycle.RunRun` (after the deploy gate AND post-pull reload, before phases) and `deploy.RunHelper` (after locks). `AnyBridgeEnabled(cfg)` gates daemon-touching steps and the best-effort ensure in top-level `dwe status`. **The bridge is strictly opt-in**: `BridgeEnabledExplicit` (in `project/config/`) defaults to OFF for every service type — it deliberately does NOT share the render toggles' app-default-on shape (`renderEnabledExplicit`), because the bridge mounts a host-controlled binary into the container and opens a container→host command channel.
- `internal/core/bridge/shimassets/` — embedded shim binaries + materialization. `//go:embed all:bin` with a COMMITTED `bin/.gitkeep` placeholder: the shims themselves are gitignored build artifacts (`make shims` cross-compiles `cmd/dwe-shim` for linux amd64/arm64; a prerequisite of `build` and all `test*` targets), and `//go:embed` against an empty dir is a hard compile error for the whole module. `Materialize(baseDir)` writes `.dwe/bridge/shim-linux-*` 0755 atomically (same-dir temp + rename — a half-written shim must never be observable at the bind-mount source of a running container), write-if-changed with chmod-only mode repair; `Status(baseDir)` reports current/stale/missing per shim; `FileName(arch)` is the single shim-name source (composegen references names, not bytes). The package is a leaf — no import of parent `core/bridge`.

## Shared — Leaf Infrastructure (`internal/shared/`)

- `internal/shared/version/` — `Version` / `Commit` / `Date` / `BuiltBy` vars + `Info()`; injected via `-ldflags -X`. Makefile LDFLAGS target `github.com/semsemyonoff/dwe/internal/shared/version.<Field>`.
- `internal/shared/prompt/` — shell-prompt segment renderer for starship / similar integrations. Public entry point: `Run(stdout io.Writer, args []string) int`; internal testable form: `runFromDir(stdout, args, cwd string, useColor bool) int` (explicit cwd so tests use `t.TempDir()` without touching process state). **Lipgloss is deliberately not imported**: lipgloss auto-downgrades to no-color when stdout is piped, which it always is when starship invokes `dwe prompt`. Local `findRoot(start)` stat-walks up to `workspace.yml` — intentionally duplicates `project.Locate` logic to avoid `filepath.EvalSymlinks` cost and the cwd-injection issue on the `Locate` path. Four stub structs (`workspaceStub` / `stylesStub` / `stateStub` / `promptCacheStub`) decode only the fields the prompt needs via lenient `yaml.Unmarshal`. Color is emitted as TrueColor ANSI (`\x1b[38;2;R;G;Bm…\x1b[39m`) using `strings.Builder` + `strconv.AppendUint` — never `fmt.Sprintf` to keep the render path allocation-free. `NO_COLOR` env: suppressed when the variable exists at all (`os.LookupEnv`, value irrelevant). Any error (yaml parse, IO, missing project) → silent exit 1. **Output shape**: `{▪} <project> [<service>] <deploy-icon> <stack-icon>` — each tail segment is independently optional; only the `{▪} <project>` prefix is a stability guarantee. **Service tag**: `detectService(cwd, root)` enumerates `workspace/services/*/`, reads each `service.yml`'s `dir:` and `extends:` fields via lenient `yaml.Unmarshal` into `serviceDirStub`, then a two-pass loop: first builds a `stubs` map, then per-service walks the `extends:` chain via `resolveDir` (cycle-safe via a per-walk `seen` map, no fixed depth cap) until a non-empty `dir:` is found. The resolved path is `filepath.Clean(filepath.Join(rootClean, dir))` for relative dirs, or `filepath.Clean(dir)` when `filepath.IsAbs(dir)`. Match: `cwdClean == resolved` or `strings.HasPrefix(cwdClean, resolved+sep)`. Resolved paths equal to root (`dir: .`) or escaping root (`dir: ..`, absolute paths outside root) are rejected via a `HasPrefix(resolved, rootPrefix)` containment check — otherwise they would tag every cwd in (or above) the project. The deepest match wins by `len(resolved)`. Per-file size cap of 64 KB on the hot path: `os.Stat` first, skip if oversized (defense against generated/anchor-bomb YAML on a per-keystroke render path). `cwd` is `filepath.Clean`-ed at the top to tolerate trailing separators or `./` segments from `$PWD`-honoring shells. Sanitized via `sanitizeName` at render time. Does NOT resolve symlinks (mirrors `findRoot`). Cost: one `os.ReadDir` plus N stat+read+parse per prompt invocation (sub-millisecond on typical projects). **Stack icon** (`●` running / `◐` partial / `○` stopped, colored from `palette.success` / `warning` / `muted` — `muted` default `#6B7280`, overridable via `styles.yml` `colors.muted`): backed by `.dwe/prompt-cache.yml` (TTL 2 min). `readStack(root, composeProject, now)` returns the cached state when fresh; on stale or missing cache it invokes `refreshStack` (shells out to `docker ps -q --filter label=com.docker.compose.project=<project>` via the test-injectable `dockerPsFunc(ctx, project, env)` with a 150 ms hard timeout). The probe env comes from `readDockerProcessEnv(root)`: `process_env` overrides from `workspace/docker.yml` + `workspace/docker.local.yml` (per-key, local wins — mirrors `LoadDockerConfig`'s deepMerge; lenient — bad YAML and non-string values silently skipped; values literal, never template-resolved, matching the strict loader) applied over the process env via `docker.MergeEnv`, so the probe targets the same daemon (`DOCKER_HOST` / `DOCKER_CONTEXT`) as lifecycle commands; nil (inherit) when no overrides. Read only on the refresh path — fresh-cache renders pay no extra file IO. **No-downgrade rule**: `writeCache` is invoked ONLY when `refreshStack` returns `ok=true` AND state is `stackRunning` (count > 0). On `stackStopped` (zero rows) the cache is NOT written — the stale cache value is returned while it is younger than `staleTrustCap` (5× TTL = 10 min); past the cap the confirmed zero-probe **renders** as `stackStopped` (still no write), so a stack stopped outside dwe converges to `○` instead of showing `●` indefinitely. An unconfirmed zero (`refreshStack` `ok=false`) never downgrades at any age, and with no cache at all the result is `stackNone` (icon omitted). Rationale: a zero-result from `docker ps` is indistinguishable between a genuinely stopped stack and a wrong label filter (templated `docker.yml.project_name` cannot be resolved by prompt); writing `stopped` could downgrade a correct `running` left by an authoritative writer. `stopped` writes are reserved exclusively for authoritative writers (lifecycle commands + `dwe status`). The compose project name in prompt comes from `readComposeProjectName`, mirroring `ResolveComposeProjectName` precedence with literal values only: `project_name` from `workspace/docker.local.yml` then `workspace/docker.yml` (local wins; template values fall back), else `prefix-name`, else `project.name`. Projects with templated `project_name` see prompt refresh as a persistent zero-result while lifecycle/status writes keep the cache accurate — past `staleTrustCap` that zero renders `○` until the next authoritative write. The `docker` binary name is hardcoded — `binaries.docker: podman` bypasses prompt-driven refresh (lifecycle writes still work); `process_env` IS honored (see above), only the binary name is fixed.
- `internal/shared/promptcache/` — leaf package: best-effort writer + invalidation API for `.dwe/prompt-cache.yml`. **Zero `internal/core/**` imports** (the leaf invariant — `core/project/stack.HealthState` does the `Health → state-string` mapping in `core/` so callers compose `promptcache.Write(root, stack.HealthState(h))`). Public surface: string constants `StateRunning` / `StatePartial` / `StateStopped`; `Write(root, state string) error` validates `state` is one of the three constants (returns error otherwise without writing), ensures `<root>/.dwe/` exists, encodes `{updated_at: time.Now().UTC().Format(time.RFC3339), state: <state>}` to YAML, atomic write via `os.CreateTemp(<root>/.dwe/, "prompt-cache-*.tmp")` + `os.Rename`; `Remove(root string) error` removes the cache file, idempotent on `os.ErrNotExist`. Callers (lifecycle / deploy / service / snapshot / status CLI packages) invoke directly — `_ = promptcache.Write(...)` or `_ = promptcache.Remove(...)`; errors are deliberately ignored at every call site (best-effort: the cache is observability, not correctness). **Writer matrix**: see `docs/guides/starship.md` § Writer map.
- `internal/shared/generatedstore/` — leaf store for service-minted "generated-once" secrets (Laravel `APP_KEY`, Magento `crypt.key`, …), mirroring `promptcache`'s leaf-IO shape. **Zero `internal/core/**` imports.** Backs `.dwe/generated.yml` (`const DefaultRelPath`, no `schema_version`); on-disk schema is `services: {<svc>: {<field>: <value>}}` (string values, block scalars for multi-line). `Load(path)` returns an empty store on a missing file but **surfaces** a corrupt file (NOT swallowed); `Save(path, s)` is atomic (temp + rename, mirrors `journal.Save`). Accessors: `Has(svc, field)`, `Get(svc, field)`, `Service(svc) map[string]string`, `SetIfAbsent(svc, field, val) bool` (write-if-absent — the harvest contract: a stored value is never overwritten), `ClearService(svc)`, `ClearAll()`, `IsEmpty()`. The store is intentionally separate from `.dwe/deploy/state.yml` so snapshot restore (which overwrites the journal) leaves harvested secrets untouched. `.dwe/` is fully gitignored, so secrets stay out of git. Consumed by `templates/config` (`RenderConfigs`/`HarvestGenerated`), the `generated-missing` predicate, `renderConfigsForRun`, and `reset --clear-generated`.
- `internal/shared/docker/` — `Compose` for building/executing `docker compose` with policy args; `NewCompose(cfg, dockerCfg, baseDir)` / `NewComposeAll(cfg, dockerCfg, baseDir)`; always read the binary via `Compose.BinName()` (nil/empty-safe). **`Compose.BaseDir` is the project root and is applied as `cmd.Dir` on every docker subprocess** (`Exec`, internal `output`, `RunningServices`) so that relative `-f compose.yaml` paths in `cfg.ComposeFiles()` resolve correctly even when dwe is invoked from a project subdirectory. Callers constructing raw `exec.Command` against `compose.BinName()` (e.g. `internal/core/project/stack/topology.go`, `stack/daemons.go`, `internal/core/usercommands/runtime/runners/service/exec.go`, `internal/cli/command/daemonset.go`, `internal/cli/compose/compose.go` raw passthrough) MUST also set `cmd.Dir = compose.BaseDir` (or the equivalent `baseDir` parameter for the stack helpers). Empty `BaseDir` is only safe inside tests that never exec. Health helpers: `WaitContainersHealthy`, `HealthStatus`, `ContainerIDsFor`. `StopContainer(ctx, dockerBin, name string, timeoutSec int) error` for direct container stop (no compose); idempotent on "No such container". `RemoveContainer(ctx, dockerBin, name string) error` is the symmetric `docker rm -f` helper, also idempotent on "No such container"; the pair backs both `dwe stop <name>` (stop only) and the per-service-reset synthetic `docker_stop_remove_container` builtin (stop+rm). `RestartContainer(ctx, dockerBin, name string, timeoutSec int) error` issues `docker restart -t <timeoutSec>`; unlike `StopContainer`, it is **NOT idempotent** — returns `ErrNoSuchContainer` when the container does not exist, so callers can differentiate "never deployed" from "stopped". `DefaultStopTimeoutSec` exported constant shared with `internal/core/execution/builtin/containers/daemon_stop.go`.
- `internal/shared/daemon/` — cross-cutting daemon domain utilities: `ResolveContainerName(projectFullName, renderedTemplate)` (prepends `<projectFullName>-`, validates against `^[a-zA-Z0-9_][a-zA-Z0-9_.-]*$` — the authoritative runtime gate on container names), `StandardLabels(projectFullName, daemonID, params)` (emits `--label key=value` argv pairs for the three standard labels), `FilterArgsByLabels(projectFullName, daemonID)` (`--filter label=…` argv for `docker ps`); sentinel errors `ErrContainerNameInvalid` / `ErrDaemonAlreadyRunning` / `ErrDaemonNotRunning`; label-key constants `LabelProject` / `LabelDaemonID` / `LabelDaemonParams`. Consumed by `internal/core/execution/builtin`, `internal/core/project/stack`, `internal/core/validate/commands`, and `internal/cli`.
- `internal/shared/bridgeproto/` — host-bridge wire protocol leaf (note: `shared/daemon/` above is TAKEN by user-command daemon utilities — hence the `bridge*` naming). Length-prefixed binary frames identical on both transports: `[4-byte BE uint32 payload length][1-byte type][payload]`, types 0x01–0x09 (HELLO / STDIN / STDOUT / STDERR / STDIN_CLOSE / SIGNAL / RESIZE-reserved / EXIT / ERROR), `MaxPayload` guard bounds memory. `ProtocolVersion` const + ERROR code constants (`auth_failed`, `version_mismatch`, `cwd_outside_project`, `tty_unsupported`, `daemon_shutting_down`). Deliberately NO channel-id in the header — one connection = one command; multiplexing would be a new `protocol_version`. `WriteFrame` emits header+payload in a **single `Write`** so concurrent frame writers on a `net.Conn` cannot interleave. Token helpers: generate (crypto/rand 32 bytes hex), read/write file 0600, constant-time compare — `TokenEqual` **rejects empty tokens on both sides** so a missing token file can never authenticate. Peercred: `PeerUID`/`PeerIsSameUser` behind build tags (`SO_PEERCRED` linux / `LOCAL_PEERCRED` darwin / fail-closed stub elsewhere, mirroring the `shared/lock` fallback shape).
- `internal/shared/bridgeclient/` — the in-container shim core; **leaf** (no `core/`/`cli/` imports), no cobra, no lipgloss (mirrors `shared/prompt` — `cmd/dwe-shim` is a thin main over it). Transport selection per design D2: stat + dial `$DWE_BRIDGE_DIR/host.sock` (300 ms timeout — a dead socket inode on Docker Desktop refuses instantly, by design; never platform-detect) → fall back to TCP `host.docker.internal:<port>` reading the `port`+`token` files (2×100 ms retry on missing — daemon-restart window). Token is sent only on TCP; unix authenticates via peercred. HELLO always carries `tty: false` (even on a real terminal — design D11). Color: `OptionsFromEnv` probes the shim's own stdout (`stdoutIsTerminal` seam) and on a real terminal appends `CLICOLOR_FORCE=1` plus `COLORTERM=truecolor` via `ForceColorEnv` (container `NO_COLOR` / explicit `CLICOLOR_FORCE` / explicit `COLORTERM` win unchanged) — the host-side dwe writes into a pipe and would otherwise downgrade to no-color and quantize the palette to the container's bare `TERM=xterm`. `SetStdinTTYEnv` force-owns `DWE_BRIDGE_STDIN_TTY` (spoofed values dropped, appended only when the shim's stdin IS a terminal) — the signal that lets host runners give user-command children a full PTY (see § runio). `StripEnv` is the **single strip-set source** (the daemon re-filters through it) — `DWE_BRIDGE_SERVICE` (`EnvBridgeService`) is deliberately NOT in it: the overlay injects it per service (value = the workspace service KEY, not the compose container name) and it must reach the host-side dwe, whose `registry.applyBridgeVisibility` consumes it via the `InContainer()` / `CallingService()` helpers here; container-reported, hence advisory (UX boundary, not security). The canonical `EnvInvokedFrom`/`InvokedFromContainer`/`EnvNonInteractive` constants also live here (leaf — importable from `core/` registry code); `core/bridge` keeps aliases for daemon-side call sites. `TranslateCwd` is path-boundary-aware prefix rewrite (`/workspace` does not match `/workspaces`), untranslatable cwds pass through as-is — the daemon (`resolveCwd` in `core/bridge/session.go`) FALLS BACK to its own project root for any cwd it cannot place inside the project (hooks routinely `cd` out of the container mount and send `/`), logging a note instead of rejecting; `ErrCodeCwdOutsideProject` is no longer emitted (kept for wire compat). Unreachable policy (design D10): default error + exit 1 (a hook must block the commit), `DWE_BRIDGE_UNREACHABLE=warn` → warning + exit 0; a connection dying before delivering ANY frame is mapped to unreachable too (Desktop's host proxy can accept the connect and only then discover nothing listens); `version_mismatch` renders the fixed "shim outdated, re-run `dwe deploy` to refresh shim binaries" remedy. Tests run the real client against in-process fake servers over loopback TCP + tmpdir unix sockets — no Docker.
- `internal/shared/lock/` — project-level file lock with stale-PID detection (Unix-only build tag): `Acquire(path)` uses `flock(LOCK_EX|LOCK_NB)`; on `EWOULDBLOCK` reads the holder PID and calls `Kill(pid, 0)` to reclaim stale locks. Lock files: `.dwe/deploy/deploy.lock` and `.dwe/snapshots/snapshot.lock`. Lock files are intentionally left on disk after `Release` with the last writer's PID; **never** delete a conflict lock file (inode-race invariant, `lock.go:120-125`). `project.go` exposes `AcquireProjectLocks(baseDir) (release func(), err error)` — the **single seam** for project-mutating commands: acquires `deploy.lock` first, `snapshot.lock` second (alphabetical), releases in reverse; on second-lock failure the first is released before returning the error; error message is `"<deploy|snapshot> operation in progress: pid N"` (wraps `lock.HeldError`). Every snapshot mutating subcommand (`create` / `restore` / `rollback` / `remove` / `pack` / `unpack`) and every deploy lifecycle command (`deploy run` / `run` / `stop` / `restart` / `reset`) calls this helper — never `lock.Acquire` directly on the deploy or snapshot lock path. Lifecycle commands acquire the project locks **after** `preflightRun` succeeds. Behavior detail: `docs/reference/config/state/index.md` § Lock file and `docs/reference/config/snapshot.md` § Lock interaction.
- `internal/shared/git/` — git update probe: `Probe`, `PullFFOnly`, `Decide`. **Mode is binary: `ModeOn` / `ModeOff`** (`UpdateMode` string type) — the former `prompt`/`auto`/`check` triad was collapsed (YAGNI) and the dead `ActionPullAuto` constant removed. Safety matrix: not-a-repo / `ModeOff` → skip; dirty / no-upstream / fetch-failed / diverged → warn; up-to-date → skip; behind + `ModeOn` → `ActionPullPrompt` on a TTY (ask, then `pull --ff-only`), `ActionWarn` ("behind … skipping in non-interactive") otherwise. The consumer (`workflow/lifecycle/run.go`) maps the resolved `on`/`off` string to `git.UpdateMode` before calling `Decide`. `Runner` interface for tests.
- `internal/shared/envfile/` — `.env` generation: `BuildContent(cfg)`, `Regenerate(configPath)`. No cobra / UI deps. Host-id resolution (`HostUID` / `HostGID`) delegates to `shared/hostid`.
- `internal/shared/hostid/` — leaf owner of the platform host-id logic shared by `envfile` and `tpl`: `Current() Info` does a single `user.Current()` read and returns `{UID, GID}` (`UID()` / `GID()` are convenience wrappers). `envfile.HostUID` / `HostGID` delegate here; `tpl.CurrentHostInfo` returns `HostInfo(hostid.Current())` (an identical-field struct conversion, so existing `HostInfo` literals in tests stay valid). Centralizes what was duplicated across `envfile/render.go` and `tpl/render_command.go`.
- `internal/shared/tpl/` — Go template engine: `Render`, `RenderCommand`, `EvalCondition`, `EvalCommandCondition` (render-first). `FuncMap()` returns a per-call shallow clone of a sprout-backed map (`std`, `strings`, `numeric`, `slices`, `maps`, `regexp`, `conversion`, `time`, `filesystem`, `semver`) plus domain helper `appURL`. Hermetic (no env, FS, network, crypto). `commandFuncMap` adds `resolve` / `resolveMap` / `resolveFile` (command scope only). **Snapshot template scope gate**: `${snapshot.*}` resolves only inside snapshot workflow blocks. The gate is enforced by `validateSnapshotScope(expr, scope)` in `render_command.go`, called from `RenderCommand` **before** `CompileVarSyntax`. `CompileVarSyntax` has no error path and must stay pure-syntactic — never add scope logic there. Three scope values: `SnapshotScopeNone` (zero value, default — compile error on any `${snapshot.*}`), `SnapshotScopeCreate` (all keys except `created_at`), `SnapshotScopeRestoreOrRemove` (all keys). Use `meta.BuildSnapshotVars(...)` (from `internal/core/workflow/snapshot/meta`) to build the map; inject via `RunContext.Render.Snapshot` + `.SnapshotScope`. **`generated` namespace** (config render): `RenderContext.Generated map[string]string` holds the current service's harvested values; `CompileVarSyntax` routes `case "generated"` → `{{ resolveGenerated .Generated "<name>" }}`. Like every other `${...}` resolver, `resolveGenerated` is **lenient** (absent key → `""`) — there is no strict-vs-lenient distinction. Config templates reference per-service config fields via `${services.<name>...}` (the curated `injectServicesIntoRaw` subset only) and top-level config via bare `${databases.x}`; a singular current-service `${service....}` binding does NOT exist. **`VarPattern`** is the exported `${...}` matcher (`= varPattern`, `\$\{([a-zA-Z_][a-zA-Z0-9_.]*)\}`) reused by `varsusage`'s static scanner so it keys off the renderer's OWN pattern semantics (no internal whitespace, no leading digit) rather than a divergent grep.
- `internal/shared/pathsafe/` — filesystem safety: `CheckNoSymlinks`, `ContainedRel` (rejects `..` / `.` escaping), `EnsureRealUnder` (callers must `filepath.EvalSymlinks` before passing). Used by template renderers to prevent escape attacks.
- `internal/shared/render/` — `Writer` with ANSI output methods (Success / Error / Warning / Info / Definition / TableHeader / ASCII art); plain passthrough for logs; `Writer.Confirm` is the non-TTY Y/n fallback. `Writer.ASCII(lines []string, font string) error` emits plain figlet text — callers wrap output in lipgloss style externally (typically via `accent`). No built-in color path; `validFigureColors` and `NewColorFigure` were dropped as part of the branding refactor.
- `internal/shared/liveui/` — shared live-output infrastructure: `LiveLine` + `LiveBlock` (sticky footer + multi-row block via `bubbles/v2/spinner` + private ticker) and output helpers (`LineTee`, `ANSIOnlyStripper`, `LogSanitizer`, `JoinWriters`). Consumed by `internal/core/execution/pipeline/plain.go` and by workflow parallel groups in `internal/core/usercommands/runtime/runners/workflow/parallel.go`. **Nine non-negotiable invariants** for the live view are documented in `liveline.go` — read them before touching anything here.
- `internal/shared/trace/` — leaf diagnostic sink for `-v`/`--debug` output. **Zero `internal/core/**` imports** (the leaf invariant); imported by `docker` / `git` / the execution engine / `preflight` for emit, but only `cli/` calls `Configure` + installs the slog handler. **All output is stderr-only** so stdout (incl. `--output json`) stays a clean machine-readable contract. Public surface: `Level` enum (`LevelOff` / `LevelVerbose` / `LevelDebug`, `int32`-backed via `atomic.Int32`), `Configure(w io.Writer, lvl Level)` (called once from root; `w` may be nil), `Enabled(l Level) bool`, `Command(ctx, name, args...)` (Verbose+; `$`-prefixed copy-pasteable line), `Decision(ctx, format, …)` (Verbose+; step run/skip + reason, `when:`/condition + preflight results), `Debugf(ctx, format, …)` (Debug-only; timings/exit codes/env/config internals), `LinePrinter` interface (`PrintLine(string)`, must be concurrency-safe), `SetPrinter(p) (restore func())`, `WithLinePrinter(ctx, p)`, `FormatCommand(args) string`, and `NewSlogHandler()` (`slog.go`). **Three-level emit precedence** (`emit`): (1) ctx-carried printer (`printerFrom` / `WithLinePrinter`) — set per parallel sub-step for correct attribution; beats (2) global active printer (top of the `SetPrinter` save/restore stack) — set by `PlainReporter.StartPipeline` to wrap `r.live.PrintlnDiag`, which frames the line above the footer via `termOut` but writes the line **text to the diagnostics writer = `os.Stderr`** (set via `LiveLine.SetDiagWriter` in `NewPlainReporter`), NOT `r.live.Println` (screen/stdout) — so in-pipeline `-v`/`--debug` echoes stay off stdout and `dwe run --debug 2>debug.log` captures them; beats (3) the `Configure` fallback writer (`os.Stderr`, used outside any pipeline + in JSON mode). `LevelOff` is a zero-alloc early return after one atomic load → no overhead when no flag is set. **Concurrency contract**: only sequential callers (nested pipelines) mutate the global printer stack under `mu`; `SetPrinter`'s restore is LIFO via an index guard + `sync.Once`, parallel sub-steps attribute via the ctx printer and never touch the global slot. **slog handler** (`slog.go`): installed via `slog.SetDefault` **only** at `LevelDebug` (`-v` never touches slog); `Enabled` is always true (gating happens at install time), records route through the same ctx→global→fallback precedence, and `WithAttrs`/`WithGroup` are supported. `installSlogHandler` captures Go's pristine default logger once and **restores it** when a later same-process `Execute` runs below Debug — so a prior `--debug` does not leak the always-emit handler into a subsequent non-debug run (matters for embedded/repeated `Execute`; the one-shot CLI never revisits). **Level precedence** (`levelFrom` / `debugEnvTruthy` in `cli/root.go`): `--debug` OR truthy `DWE_DEBUG` → Debug; else `--verbose` → Verbose; **flag beats env** (`DWE_DEBUG` in `{"","0","false","no","off"}`, case-insensitive + trimmed, is off). **`FormatCommand`/`quoteArg` is the single quoting source** — lifted byte-identically from the old `docker/compose.go` `formatCommand`/`quoteArg`, so compose error-wrap goldens must stay byte-identical to it. User-facing details: `docs/guides/troubleshooting.md` § Verbose & debug output.
- `internal/shared/i18n/` — localization system: embedded + project-layer translation file loading, locale resolution, and typed lookup. **Schema**: `Bundle{UI map[string]string, Commands map[string]CommandStrings, Groups map[string]GroupStrings}` (CommandStrings and GroupStrings carry description + params/title respectively). **File format**: YAML files under `internal/shared/i18n/translations/` (built-in) and `<projectRoot>/workspace/i18n/` (project overlay, optional); strict `KnownFields(true)` decode. **Loader**: `Load(projectRoot)` reads embedded files + project overrides (project-wins deep merge per locale); returns a `*Store` with methods `T(locale, uiKey, fallback)` (generic lookup for `ui.*` namespace), plus typed helpers `CommandDescription` / `CommandConfirmationText` / `ParamDescription` / `GroupTitle` / `GroupDescription`. `LoadProjectBundles(projectRoot)` returns per-file parse metadata for the validator (source path, locale, parse error if any); missing directory → `(nil, nil)`, OS error → sentinel `ProjectFile{Locale: "", ParseErr}`, parse error → non-fatal (skipped, file appears in result slice). **Resolver**: `ResolveLocale(flagLang, configLang, sysLang)` precedence chain: flag → config → system `$LANG` parse → `"en"` default. **Scope v1**: user-command `description`/`confirmation_text`/`param.description`, command-group `title`/`description`, and doc-generator `ui.*` strings. DWE's own Cobra strings stay English; `${snapshot.*}` variables stay English. **Coverage test**: `coverage_test.go` ensures every `ui.*` key in built-in `en.yml` exists in every other built-in locale. User-visible details: `docs/reference/config/i18n.md`.

## Entrypoint (`cmd/dwe/`)

- `cmd/dwe-shim/main.go` — the standalone in-container shim binary: a thin main over `internal/shared/bridgeclient` (signal.Notify for SIGINT/SIGTERM, `bridgeclient.OptionsFromEnv`, `os.Exit(bridgeclient.Run(...))`). No cobra, no lipgloss — the whole point is a ~3 MB static `CGO_ENABLED=0` linux build (`make shims` → `internal/core/bridge/shimassets/bin/`, embedded into the host dwe and materialized to `.dwe/bridge/` at prepare time).
- `cmd/dwe/main.go` — entry point (uses `fang.Execute` for styled help/errors). Four non-obvious startup behaviors: (1) **Prompt hot-path bypass** (`isPromptInvocation`): if `os.Args` is exactly `["…", "prompt"]` or `["…", "prompt", "--check"]`, `prompt.Run(os.Stdout, os.Args[2:])` is called and `os.Exit` fires immediately — before cobra, fang, pflag pre-parse, and `loadHelpColorScheme`. Any other `prompt` shape (e.g. `--help`, unknown flags, `--check=true`) falls through to cobra so help/errors render normally. (2) **Pre-Cobra pflag pre-parse** (`configPathFromArgs`): extracts `--config/-c` from `os.Args` using pflag with `UnknownFlags=true` *before* Cobra runs, so the project root can be located without triggering Cobra flag parsing. (3) **Early styles injection** (`loadHelpColorScheme`): calls `project.Locate` + `config.LoadStylesConfig` + `styles.ApplyStyles` before `fang.Execute`, then passes a `fang.WithColorSchemeFunc` so `--help` output uses the project's `accent`/`muted` tokens. Silent on all failures — Fang's default colors apply when styles cannot be loaded. The scheme func is ALWAYS installed (even without styles.yml) because it also pins the palette mode: fang's own `mustColorscheme` resolves isDark=false whenever stdout is not a terminal, which would render the LIGHT palette into a pipe — invisible dark-on-dark text over the host bridge. Both lipgloss v1 and v2 resolve DARK on pipes, so the wrapper forces `lipgloss.LightDark(true)` when `!term.IsTerminal(stdout)` and every dwe surface agrees. `styles.ApplyStyles` runs twice on a normal invocation (once here before Cobra, once from root `PersistentPreRunE`); the second call is a no-op when styles haven't changed. (4) **Custom error handler**: suppresses output for `ErrSilent` (command already printed its own error) and for `ExitCode`-bearing errors (diagnostics already printed via `fang.WithErrorHandler`); delegates all others to `fang.DefaultErrorHandler`. Exit-code errors also produce a non-zero `os.Exit(ec.ExitCode())` after `fang.Execute` returns.

## Назначение

`devbox/styles.yml` управляет визуальным видом CLI `devbox`: брендированным
header'ом, показываемым на старте, семью семантическими цветовыми токенами,
используемыми во всех UI-surface'ах (таблицы, status-секции, браузер команд,
help-вывод Fang), и символом-разделителем, используемым в definition-списках.

Грузится через `LoadStylesConfig()` и применяется на старте через
`styles.ApplyStyles()` (в `internal/core/ui/styles/`). Полное отсутствие файла
даёт идентичные встроенные дефолты.

## Структура

```yaml
header:
  lines:
    - "Welcome to"
    - "Devbox Laravel"
  font: doom
  tagline: "Local dev, container-orchestrated."

colors:
  accent:  "#2EC3EB"
  success: "#22C55E"
  warning: "#F59E0B"
  danger:  "#EF4444"
  muted:   "#9AA3BB"
  border:  "#334155"
  text:    ""

separator: "·"
```

## Справочник полей

### `header`

Контролирует брендированный header, отображаемый `devbox` (без аргументов) и
`devbox info`. Brand-идентичная строка (`{▪} Devbox · <project> · <version>`)
всегда рендерится; опциональный tagline и ASCII-арт накладываются поверх, когда
сконфигурированы.

| Поле | Тип | Дефолт | Описание |
|------|-----|--------|----------|
| `header.lines` | list of strings | _(нет)_ | Текстовые строки, рендерящиеся как ASCII-арт под brand-строкой |
| `header.font` | string | `doom` | Имя шрифта go-figure (doom, banner, big, block, slant, …) |
| `header.tagline` | string | _(нет)_ | Одна строка-tagline, рендерящаяся в muted-цвете ниже brand-строки |

ASCII-блок раскрашен токеном `accent`. Отдельного `header.color` нет — цвет
всегда выводится из семантической палитры.

### `colors`

Семь семантических цветовых токенов. Значения — сырые hex-строки (например,
`"#2EC3EB"`). Пустые / отсутствующие записи откатываются на встроенный light-
или dark-дефолт для данного токена (см. [Разрешение light / dark](#разрешение-light--dark)).

| Токен | Используется для |
|-------|------------------|
| `accent` | Брендированные surface'ы — brand-строка, ASCII-header, заголовки секций, focused-бордюры, заголовки таблиц, совпадения фильтра, активная пагинация, внутренний квадрат лого `{▪}` |
| `success` | Состояния OK / running / enabled; success-уведомления; индикатор `[--yes ON]` |
| `warning` | Warning-диагностики; partial / degraded состояния |
| `danger`  | Error-диагностики; failed-уведомления |
| `muted`   | Вторичный текст — счётчики, разделители, dimmed строки списков, tree-глифы, неактивная пагинация, описания команд/флагов |
| `border`  | Дефолтные (unfocused) бордюры панелей и таблиц |
| `text`    | Дефолтный body-текст. Пустое значение означает «пусть терминал сам выбирает foreground-цвет» — рекомендуется почти во всех случаях |

Эти же семь токенов драйвят рендер `--help` у Fang: title / command / flag /
program используют `accent`, description / argument используют `muted`.
Отдельного поддерева `colors.help` больше нет.

### `separator`

```yaml
separator: "·"
```

Символ, используемый между label и value в definition-элементах (например,
`Project · laravel`).

## Опуская файл

Если `devbox/styles.yml` не существует, `LoadStylesConfig()` возвращает
zero-value структуру, а `styles.ApplyStyles()` откатывается на встроенные
дефолты. CLI работает идентично — ошибка не выдаётся.

## Разрешение light / dark

У каждого токена есть встроенный light- и dark-hex-дефолт. На старте
`ApplyStyles` один раз зовёт `lipgloss.HasDarkBackground()` и резолвит каждый
токен в единственную hex-строку на весь остаток процесса. Разрешённое значение
выставлено через аксессоры `styles.Color*()` и мостит три styling-слоя: v1
lipgloss (`internal/core/ui/render/`, `internal/core/ui/widgets/`), v2 lipgloss
(`internal/core/ui/cmdbrowser/`) и `ColorScheme` Fang.

| Токен | Light-дефолт | Dark-дефолт |
|-------|--------------|-------------|
| `accent`  | `#0EA5E9` | `#2EC3EB` |
| `success` | `#16A34A` | `#22C55E` |
| `warning` | `#D97706` | `#F59E0B` |
| `danger`  | `#DC2626` | `#EF4444` |
| `muted`   | `#64748B` | `#9AA3BB` |
| `border`  | `#CBD5E1` | `#334155` |
| `text`    | _(пусто — дефолт терминала)_ | _(пусто — дефолт терминала)_ |

Непустое значение, заданное пользователем, переопределяет оба режима — override'ы
не per-mode. Повторный запуск `ApplyStyles` после смены профиля — поддерживаемый
способ ретеминга во время сессии.

## Кастомизация цветов

Переопределите любое подмножество токенов; не заданные токены сохраняют свои
light/dark-дефолты.

```yaml
colors:
  accent:  "#A78BFA"   # фиолетовый бренд
  success: "#10B981"   # зелёный с уклоном в teal
  muted:   "#94A3B8"
```

Для монохромного вида установите `accent` и `success` в одно семейство оттенков
и пусть `muted`/`border` обеспечивают контраст.

## Миграция со старой палитры

Более ранние версии выставляли 19 ключей палитры плюс вложенный блок
`colors.help`. Они сворачиваются в семь семантических токенов так:

| Старый ключ | Новый токен |
|-------------|-------------|
| `label`, `section_title`, `subheader`, `info`, `table_header`, `focus_border`, `filter_match`, `pagination_active`, `mandatory` | `accent` |
| `enabled` | `success` |
| `partial` | `warning` |
| `description`, `tree_count`, `tree_arrow`, `pagination_inactive`, `disabled` | `muted` |
| `table_border` | `border` |
| `warning`, `muted` | _(без изменений — те же имена ключей)_ |
| `colors.help.*` (весь блок) | _(удалён — выводится из `accent` + `muted`)_ |
| `header.color` | _(удалён — всегда `accent`)_ |

Запуск `devbox validate` подсвечивает rename-подсказку для каждого неизвестного
ключа, найденного в `styles.yml`. Обычные команды `devbox` грузят стили молча и
не предупреждают.

## Распространённые подводные камни

- **Использование кодов ANSI 256 вместо hex** — схема теперь ожидает hex-строки
  (`"#2EC3EB"`). Голые числовые коды невалидны.
- **Забыли кавычки на hex-значениях** — YAML обычно терпит `#2EC3EB` без
  кавычек (после ключа это не комментарий), но кавычки — более безопасная привычка.
- **Per-mode override'ы** — нет sub-ключа `light:` / `dark:`. User-override
  применяется в обоих режимах; выбирайте hex, который хорошо читается на обоих
  фонах, или полагайтесь на встроенные дефолты.
- **Старые ключи молча игнорируются в рантайме** — загрузчик lenient.
  Используйте `devbox validate`, чтобы поймать устаревшие ключи до того, как
  они станут невидимыми no-op'ами.

## Связанные команды

- `devbox` (без аргументов) — показывает brand-header + компактную сводку
- `devbox info` — показывает полный info-дашборд со стилизованным выводом
- `devbox validate` — подсвечивает rename-предупреждения для legacy-ключей палитры

# Конфигурация `ui`

Опциональный блок `ui:` в `devbox.yml` конфигурирует интерактивный браузер команд, используемый `devbox commands`, когда тот вызывается без точного command ID.

Блок грузится тем же lenient-загрузчиком, что и остальной `devbox.yml`: отсутствующий блок и неизвестные ключи молча игнорируются на этапе загрузки. Выделенный валидатор `ui` (запускаемый через `devbox validate`) подсвечивает неизвестные ключи как warning'и, а невалидные значения (например, отрицательную глубину) — как error'ы.

## Схема

```yaml
ui:
  commands:
    default_expanded_depth: 1        # int, дефолт 1
    auto_collapse_empty: true        # bool, дефолт true
    show_type_badges: true           # bool, дефолт true
```

### `ui.commands.default_expanded_depth`

Контролирует, сколько уровней дерева раскрыто по умолчанию при открытии браузера команд. Отрицательные значения зажимаются до `0` аксессором и отвергаются как ошибка валидатором.

Как и `auto_collapse_empty` и `show_type_badges`, это поле использует указатель `*int`, чтобы загрузчик мог отличить отсутствующий ключ (nil → использовать spec-дефолт `1`) от явного значения. Установка `default_expanded_depth: 0` означает all-collapsed (на входе ни одна группа не открыта); пропуск ключа восстанавливает дефолт `1` (раскрыты только top-level группы). Любое положительное целое раскрывает до этой глубины.

### `ui.commands.auto_collapse_empty`

Когда `true` (дефолт), сессии fuzzy-фильтра автоматически сворачивают и затемняют поддеревья с нулём совпадений; предыдущее состояние раскрытия восстанавливается на `Esc`.

### `ui.commands.show_type_badges`

Когда `true` (дефолт), правый список команд показывает цветной бэйдж типа (`shell`, `script`, `workflow`, `service_exec`, `service_run`, `builtin`, `devbox`) рядом с каждым command ID. Установите `false`, чтобы подавить бэйджи на узких или монохромных терминалах.

## Семантика указателей — omit vs explicit zero

Все три поля (`default_expanded_depth`, `auto_collapse_empty`, `show_type_badges`) используют указательные типы (`*int` / `*bool`), чтобы загрузчик мог отличить отсутствующий ключ (nil → использовать spec-дефолт) от явного значения. Простые `int`/`bool` смешали бы эти два состояния, потому что отсутствующий ключ и явный `0`/`false` оба десериализуются в zero-value.

Практические последствия:
- Установка `default_expanded_depth: 0` сворачивает все группы на входе; пропуск ключа даёт дефолт `1`.
- Установка `auto_collapse_empty: false` или `show_type_badges: false` — это намеренный opt-out; пропуск любого ключа восстанавливает его дефолт `true`.

## Пример

```yaml
# devbox.yml
schema_version: "2"

ui:
  commands:
    default_expanded_depth: 2
    auto_collapse_empty: true
    show_type_badges: false
```

Опустите блок целиком, чтобы принять все дефолты; существующие файлы `devbox.yml` без блока `ui:` продолжают вести себя идентично.

## Хоткеи

У браузера команд четыре режима фокуса. Видимые биндинги меняются с фокусом; динамический help-футер (`?`) перечисляет активное подмножество.

| Режим | Биндинг | Действие |
| --- | --- | --- |
| left (дерево) | `↑/↓`, `k/j` | перемещать курсор внутри дерева |
| left | `→`, `l` | раскрыть фокусированную группу |
| left | `←`, `h` | свернуть фокусированную группу или перейти к её родителю |
| left | `Space` | переключить раскрытие |
| left | `Home` / `End` | перейти к первой / последней видимой строке |
| left | `Enter` | войти в фокусированную группу (раскрыть при необходимости и переместить фокус направо) |
| left | `Tab` | переместить фокус в правый список |
| left | `/` | войти в режим фильтра |
| left | `?` | переключить long-help |
| left | `Esc`, `q`, `Ctrl+C` | выйти из браузера |
| right (список) | `↑/↓`, `k/j` | перемещать курсор внутри списка |
| right | `Enter` | подтвердить выбор (запустить или проинспектировать, в зависимости от точки входа) |
| right | `i` | открыть inspect-оверлей для подсвеченной команды |
| right | `y` | переключить skip-confirm (только в run-режиме); футер показывает `[--yes ON]` |
| right | `←`, `Tab` | вернуть фокус на дерево |
| right | `/` | войти в режим фильтра |
| right | `Esc`, `q` | выйти из браузера |
| filter | (печать) | уточнить fuzzy-запрос; счётчики `M/N` в дереве обновляются |
| filter | `↑/↓`, `Enter`, `i`, `y` | как в right-режиме, но против отфильтрованного результата |
| filter | `Esc` | выйти из фильтра и восстановить прежнее состояние раскрытия |
| inspect | `↑/↓`, `k/j`, `PgUp/PgDn` | скроллить inspect-вьюпорт |
| inspect | `Enter` | подтвердить (возвращает тот же `Result`, что и `Enter` из списка) |
| inspect | `Esc` | закрыть оверлей; фокус возвращается на правый список |

Биндинг skip-confirm `y` активен только в run-режиме (дефолт, когда `--inspect` / `-i` не задан); в inspect-режиме он удалён из keymap.

## Fallback-лестница

Браузер инспектирует терминал на старте и грациозно деградирует:

| Условие | Поведение |
| --- | --- |
| non-TTY | вызывающее место shortcut'ится с существующей ошибкой `no exact command ID given; pass a full command ID or run in an interactive terminal`; браузер никогда не достигается |
| TTY, `width < 60` или `height < 15` | делегирует на плоский список `huh.NewSelect` (сегодняшний pre-browser UX) |
| TTY, `width ∈ [60, 79]` | single-panel режим с псевдо-заголовками `── group ──`; без дерева, без бэйджей |
| TTY, `width ∈ [80, 99]` | two-panel режим без счётчиков групп `(N)` и без бэйджей типов |
| TTY, `width ≥ 100` | полный two-panel режим с бэйджами, счётчиками и breadcrumb |

`NO_COLOR=1` учитывается автоматически через lipgloss/bubbletea: бэйджи рендерятся как plain-текст, focus-маркер использует bold вместо цвета.

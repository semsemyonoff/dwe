# Переводы и поведение языка

Как Devbox разрешает активную локаль, где на диске лежат переведённые длинные документы и как проверка устаревания по контент-хешу удерживает переводы в актуальном состоянии.

## Разрешение локали

Devbox выбирает активную локаль по цепочке приоритетов:

1. **Флаг `--lang`** (на `docs show` / `docs export` / `docs list`; в рамках одного запуска)
2. **Переменная окружения `DWE_LANGUAGE`**
3. **Параметр `language` в пользовательской конфигурации** (`~/.config/devbox/config` или `.devbox/config`)
4. **Системная переменная `$LANG`** (разбирается до 2-буквенного кода)
5. **По умолчанию:** `en` (английский)

Пофайловый fallback: если markdown-файл не переведён на разрешённую локаль, Devbox автоматически использует английскую версию и показывает информационную плашку.

## Переводы длинной документации

Полные сведения о двух namespace-ах i18n и раскладке файлов переводов см. в [Локализация (i18n) — переводы длинной документации](../config/i18n.md).

## Раскладка файлов переводов

Переводы длинной документации живут в отдельном namespace от строк команд/UI:

```
docs/
  reference/               # английские встроенные доки
    config/
      devbox.md
    ...
  internals/
    architecture.md
    ...
  i18n/
    ru/                    # русские переводы
      reference/
        config/
          devbox.md        # переведённая версия
      internals/
        ...
    de/                    # немецкие переводы
      ...
```

Переводы **опциональны**; отсутствие перевода даёт fallback на английский с информационной плашкой.

## Проверка устаревания по контент-хешу

Каждый переведённый markdown-файл содержит строку-заголовок, фиксирующую SHA256-хеш английской версии на момент перевода:

```markdown
> Translated from: config/devbox @ a1b2c3d4e5f6

# Devbox Configuration
...
```

Когда вы открываете перевод, Devbox сравнивает этот хеш с встроенным манифестом (генерируемым на этапе сборки). Если хеши различаются, перевод помечается как **устаревший** и появляется предупреждение:

```
⚠ This translation is outdated (last synced at <hash>, current is <hash>). Press `e` to view the English version.
```

Переводчики могут обновить хеш в рамках своего pull request; Devbox перегенерирует манифест при следующем `make build`.
